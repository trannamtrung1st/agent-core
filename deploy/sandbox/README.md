# General Workbench build inputs and notices

[Operations](../../docs/17-observability-and-operations.md#trusted-local-opensandbox) owns launch/cleanup and Core environment overrides. The standalone infrastructure-only `docker-compose.sandbox.yml` is the preferred normal local deployment; `dev-real.sh start` prepares/reuses the pinned image, private key and authenticated server automatically without starting a Docker Agent Core app. The native app uses Real mode. nopCommerce is optional via `--with-store` or `--full`; packaged app integration uses an explicit separate `docker-compose.app-sandbox.yml` overlay. The dedicated runner remains a focused acceptance utility sharing server configuration. Ordinary Synthetic startup stays Docker-free.

`Dockerfile.workbench` pins Python/Node base digests, Debian’s snapshot, TypeScript and hash-locked Python dependencies. It declares the deployment runtime identity and handles existing numeric accounts/groups. The trusted-server `compatibility.py` adapter selects that same non-root identity at creation of exact managed generations, including third-party images with differing defaults, without replacing the selected image. It records original image ID/USER and attests inspected bind/security policy over the authenticated private API. Core proves filesystem/Git behavior before initialization/commands. There is no root workload stage, recursive host repair, broader mount or extra capability. Compatible images must supply shell/proc/Git/stat/Unix utilities; arbitrary images are not promised. Contract-5 verification is required for Space-owned home/private roots and per-root access modes. Operations owns rollout and recovery.

Python requirements are generated from `requirements.in` and enforced with `pip --require-hashes`. Compose preparation retains permanent input-addressed tags and exact image IDs, reusing them when inputs are unchanged. Image content IDs are also recorded by the acceptance runner; local IDs require explicit Core configuration. Input pinning is reproducible; image IDs can differ by architecture/build metadata and are not a bit-for-bit provenance claim. Keep the exact exported image ID associated with its installed inventory.

`inventory.py` exports SPDX 2.3 for installed Debian, Python, npm and Node components plus actual license-file hashes. The runner exports `workbench.spdx.json` and `workbench-licenses.tar.gz` beside `image.json` under gitignored local state. The 2026-10-14 macOS/arm64 export contains 498 package identities, 277 notice hashes and 547 retained notice files. Unknown/compound metadata remains NOASSERTION with its upstream declaration retained; this is inventory, not legal conclusion, vulnerability assessment or signed attestation. Debian/LibreOffice, Python, Node/npm and individual libraries retain their own notices; Node's release license is explicitly copied from the pinned image. OpenSandbox 1.1.1 is Apache-2.0; retain its upstream distribution notices. Agent Core source remains proprietary under the repository LICENSE.

Ordinary dotfiles, Git repositories, symlinks, within-root hardlinks and modes are supported. Core binds only exact owner directories at /working (RW/RO), permitted /home (RW/RO/absent) and the permitted owning /private root when distinct (RW/RO/absent); mounted roots share current bytes with workspace tools. Failed/cancelled execution can leave partial files. Root/ancestor swaps, escaping links and cross-root hardlinks fail closed. Limits are sampled directory budgets, not hard disk quotas; container-only writable storage and own-execd loopback remain disclosed trusted-local limits. Startup refuses incompatible old schemas/layouts; use only the explicit reviewed backup/reset procedure in Operations. No launcher resets or converts user data.

Focused Space bind regression (cached image, two disposable containers, no server changes):

```sh
python3 scripts/tests/space_workspace_mount_proof.py --image <installed-image-id-or-tag>
```

This proves real host bytes and RW/RO behavior across active Space, owning Private and Session working roots, with confirmed proof-container removal. It deliberately reports `sdkContractAttested=false`; it does not replace contract-5 Core/OpenSandbox verification. Never start a second OpenSandbox server on a daemon already serving another checkout.
