# Shared administration components

Canonical Account, System and organization pages are composed by `features/access/AccessApp.tsx`. `AdminShell` requires its explicit permission-filtered context: navigation destinations, active page, scope identity/action and header actions. It owns the shared desktop rail, narrow navigation Drawer, breadcrumbs, headings, draft indicators and keyboard/focus restoration. It has no unscoped Admin fallback. `appRoute.ts` accepts exact tenant Chat and access routes; root enters organization selection and retired `/admin/...` or `/c/...` routes resolve to Page not found.

The old `AdminApp`, `InstanceDetail`, `DefinitionDetail`, `DefinitionDraftWorkspace` and owner-host page tree are removed. Canonical tenant feature owners retain their own exact reads, revision witnesses, commands, uncertain-outcome recovery and draft guards. Shared administrative controls now require explicit tenant transports/metadata. Obsolete core Chat/realtime/file-preview transports and browser token code are separately tracked; this removal does not certify feature parity.

Reuse `AgentConfigurationPanel`, `AgentConfigurationLayout`, `AdminPageHeading`, `AdminOwnerHeading`, `AdminCollectionToolbar`, `useAdminCollectionSearch`, `useAdminDetailLayout`, `SkillDrawer`, `InstanceResourceFields`, `InstanceResourceInspector` and `FilePreview` for their product compositions. Pure candidate, timing, import, preview and presentation helpers remain independently testable. The settings controller retains sparse drafts and per-field inheritance/reset behavior; canonical callers inject their tenant transport.

Presentation stays on Ant Design v6 with existing layout classes and tokens. Parent shells own outer insets and sibling gaps; controls retain native inner padding. Collection action groups remain non-wrapping with adequate column widths and local horizontal overflow. Drawer/modal actions retain responsive wrapping. `adminFormFeedback`, `showAdminFailure` and `appMessageConfig` own validation and safe feedback; do not create a second notification or layout system.

[Frontend contract](../../../../docs/13-frontend-implementation-spec.md#authenticated-browser-entry-cutover) owns current behavior. [Browser entry evidence](../../../../docs/reports/browser-entry-cutover-verification-2026-10-21.md) records this cutover. Dated earlier Admin reports remain historical evidence.

The administrative SDK modules now contain shared types and pure helpers only. Use `ContainerRegistryFields`, `DriveAccountFields`, `CustomEmailAccountFields` and `DefinitionCandidateForm`; their old dialog/request wrappers are removed. Instance settings require an injected transport, Event filters require an evaluator callback, monitoring requires the exact tenant, and Definition budget controls require scoped limits metadata. See [transport cutover evidence](../../../../docs/reports/admin-client-transport-cutover-verification-2026-10-21.md). Confirmed Credential deletion releases its own busy guard before collection navigation; uncertain completion does not.

The dynamic model cutover reuses `TenantCredentialEditor` and `CredentialFields` for protected model-inference API keys. Purpose and API-key kind are explicit; origins belong to provider connections. These credentials are excluded from the Agent tool-binding picker. Definition authoring retains the model-default selector and speech aliases, with the retired LLM alias field removed. System Model catalog and organization AI models now reuse the same shell, collection toolbar and detail layout. Their native editors retain drafts, explicit current-read witnesses, source-qualified labels and current/saved authentication references. Current selector evidence and final cutover review are recorded in the [delivery ledger](../../../../docs/reports/dynamic-model-management-delivery-2026-10-25.md).

Model-management reference inspection and reference-affecting confirmation reuse `ModelReferences` and `ModelImpactConfirmation` across connection/offering/default editors. Counts are current readable-resource projections, not execution permission or a global usage registry. The existing viewport-bounded Modal CSS composition also owns the model-impact dialog; header/footer stay visible, the body scrolls, and narrow controls retain native forty-pixel hit targets. Model-management row actions may wrap within their owning Actions column. Confirmation cancellation retains drafts, and stale/failed previews require explicit current readback before another save.

Model catalog tables share the product-specific `ModelCatalogFilters` native Select composition. Provider/connection/state/capability filters combine with the existing collection search and reset paging; explicit All options support keyboard reset. Expanded metadata separates declaration provenance/time from observation. System stored-registration counts include retained disabled/retired offerings, not executions, and never appear in tenant preset projections. The connection picker displays audit-derived last key replacement metadata without reading a secret. New Chat uses the existing identity-width composition for current authorized setup guidance.

Self-management fields are shared by tenant Instance controls and Definition authoring/inspection. Stored automatic/procedure choices stay visible across modes; effective offering still requires live authority. Instance status separates saved mode from Frozen and from the unsaved draft. Field-owned mobile hit targets and existing panel/token spacing serve both consumers. See [completion evidence](../../../../docs/reports/agent-self-management-delivery-2026-10-26.md).
