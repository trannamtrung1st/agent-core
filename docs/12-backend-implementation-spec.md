# Backend Implementation Specification

Canonical tenant text execution reuses `AgentRunHostedService`, `AgentRunCoordinator` and `SessionRuntime`. `TenantSessionRuntimeHost` reserves shared capacity, verifies current authority, loads an owned claim-bound snapshot and supervises the Runtime to settlement/disposal. Its registry and private output sink cannot be reached by legacy Hub connections. The factory supplies only tenant storage/Run adapters, current Run authority and the restricted tool executor; legacy Profile, credential, workspace, memory, Experience, browser and attachment services are absent. Trusted execution references reach initial and rebuilt `AgentContext` and tool admission. Only IAM inspection tools are offered; compaction, proactive admissions and unsupported continuations remain fenced pending their tenant paths. ## Tenant operation eligibility and shared tool boundary

Approved local persona execution uses `TenantApprovedOperationService`, `TenantPersonaEffectRules` and the specialized exact-effect store port. The service loads saved request/decision/grant and current actual Run/Instance; callers cannot submit replacement persona fields, select the human grantor or change the target. Current IAM/policy and pinned/live Settings management eligibility remain independent gates. Both stores atomically update the actual persona and revisions, save a completed receipt, consume the exact exceptional grant when present, record the Run side effect and advance tenant security/audit. Denial writes a stable receipt and revokes the available exact grant without changing the persona or failing unrelated Run work. The transaction checks current lease, expiry, target and global human Account status after service preparation; tenant/Run/target CAS fences other changes. SQLite explicitly tracks the actual Instance row before changing it. Exact receipts suppress replay after restart and simultaneous calls. A completed local effect is never reauthorized from a missing receipt or uncertain side-effect state. Read/list projections expose decision attribution and safe operation result separately from approval status, with fresh human authorization after metadata I/O. Production tenant execution/tool wiring and external-effect reconciliation remain pending. See [approved persona effect verification](reports/tenant-approved-persona-effect-verification-2026-10-17.md).

The typed durable successor uses `TenantApprovalService`, `TenantApprovalRules` and `ITenantApprovalStore` for Instance persona operations. Core canonicalization fixes operation name, permission, actual executing Instance, persona fields and Instance/persona revisions before computing SHA-256; the stable operation ID is separate from the same-root dedupe fingerprint. Both stores commit actual Run wait plus request and security/audit atomically. Running admissions require the live generation and unexpired claim; queued pre-execution preparation holds no fabricated worker lease. Canonical Runs reference first-class requests and reject embedded legacy approvals. Human approval/rejection/cancellation writes a terminal request, immutable human decision, exact exceptional grant only for approved ExceptionalGrant, safe audit and processed signal in one transaction. CAS, current human session, current authority, material witnesses and commit-time expiry fence delayed decisions. Cancellation can release a stale wait with its own exact request permission. Core expiry produces a durable terminal signal without inventing a human decision. The existing `AgentRunHostedService` drains expiry/signals before its normal coordinator pass; signal acknowledgement and requeue commit together. Tenant Runs remain excluded from legacy execution. Full tenant effect dispatch, remaining grant/continuation integration, external reconciliation and other operation families are still pending; the local persona successor above completes one transactional effect path. See [durable approval verification](reports/tenant-durable-approval-verification-2026-10-17.md).

Current operation eligibility derives identity from persisted tenant Run context and owning Session, rechecks active executor/Instance and original requester Session-read/chat, then uses the single IAM evaluator for exact target permission. Human-only and nondelegatable missing authority deny. Agent action authority plus the requester/policy selects ordinary review; missing delegatable agent authority selects exceptional eligibility only when a qualifying active human has underlying action, approve and grant-exception authority. Review requires underlying action plus approve. Independent review excludes the original requester; requester rights never replace executor rights. Results perform no effect or approval creation.

Core minimum policy is None for read permissions, WhenRequesterLacksPermission for other ordinary mutations, and Always for delete/send/execute and non-read Credential/Browser/Sandbox permissions. These permission-level minimums do not replace ToolPolicy or action-specific safety gates. Human-only remains a hard deny. Tenant governance can strengthen mode/independence or return to the Core minimum under current human/security/policy witnesses; no model input changes this policy. Current policies are loaded with tenant security on every check.

`SessionToolExecutor` checks `TenantToolAuthorization` before legacy isolation, management or provider service calls in both async policy evaluation and actual execution. Owning roots remain discoverable after logical deletion so a missing frame cannot trigger a global fallback. Narrow IAM inspection uses the saved Run and only safe decision/key/ref projections, with bounded strict arguments and output. Effective-permission results include only currently granted actions, with ordinary review where applicable. Other tenant effects remain unavailable until typed target/witness/approval enforcement is integrated. Registry offers are conditional on trusted matching tenant execution context; tenant Runtime dispatch/context wiring remains pending. [Executed evidence](reports/tenant-operation-authorization-verification-2026-10-17.md).

Legacy approval preparation is a protected boundary before execution: the common dispatcher and direct Email, Drive, Instance management and identity-maintenance preparation methods fence tenant Sessions before reading previews or provider data. Automation preparation applies the same ownership fence before registration reads or semantic verification. Actual retained Session ownership applies even without an admission frame; an explicit tenant frame also denies when no tenant service is configured. Generic legacy previews do not create tenant approval requests. Pure argument normalization and hashing remain data transformations, never authority.

The accepted replacement uses `IdentityService` for bootstrap/login/session validation/password rotation and invitation-bound Account registration. Tenant roles inherit to owned resources; resource assignments match exact type/id. Owners are explicit tenant-wide builtin assignments. Store transactions reject changes that leave no active human Owner, including the race between global Account suspension and tenant membership changes. Password rotation changes the security stamp and invalidates all previous sessions.

Resource-scoped checks and assignments require a real target in the same tenant: member, role or registered agent identity in security state, or a definition/current Instance child in its actual owning/source store. Permission catalog resource types prevent an ordinary operation grant from authorizing another resource family; scoped access inspection/assignment and approval qualification govern the target itself. Unknown, nonexistent and foreign targets deny with `resource_unavailable`; a known target with an incompatible operation permission denies with `resource_type_mismatch`. Direct service/store writes obey the same ownership rule. One Agent Instance ID cannot acquire registered identities in two tenants. Other store families, tool admission and Hub resource access are still pending; this slice does not claim their cutover.

Both security and Instance revisions must match. The store rechecks active actor/global Account status at commit, so a suspended creator cannot complete a prepared write. Existing identity backing/tenant ownership cannot change or disappear through security updates.

The canonical lifecycle service uses existing Instance lifecycle exclusion, then existing Automation policy reconciliation and Sandbox enforcement after commit. Old unscoped Instance lifecycle writes reject owned roots, and backing deletion is restricted. ## Agent Workspace v2 tools and policy

Every Session belongs to a real active Agent Instance at creation. Each Agent Instance owns durable `/home`; each Session owns temporary `/working`. Unsupported historical built-ins remain in Git history, outside the runtime catalog. `environment.workspace` may name a template only. General Assistant v20 retains the workspace tools, including `workspace.cwd`, alongside native Browser capabilities and explicitly authorized `background.start`. The canonical registry supplies identical workspace descriptions for discovery, projection and execution.

Move/delete/batch affecting cwd or an ancestor fails Conflict.

Batches validate their complete syntax/scope before effects, then report ordered partial execution. No file revision, hash or tree token is accepted.

## Agent Definition

JSON only, UTF-8, files loaded through IAgentDefinitionStore from a configured agents directory. A file contains one definition; shipped names include `agents/examiner.json`, `agents/customer-support.json`, `agents/compliance.json`, versioned `general-assistant` files, and `agents/secretary-v1.json`. Approved knowledge bodies live beside them under `agents/knowledge/{identity}.md` and are not copied into session workspaces. Store published older versions in version subdirectories if needed; recursively index by (id, version), fail startup on duplicate keys. Versions are immutable positive integers. schemaVersion=2 identifies the current format; version identifies that agent's revision. Optional `skills` remain omitted when null, with an empty effective Skill set. Retained schema-1 files/snapshots require the explicit one-way context conversion. Reject unknown schema versions and unknown fields to catch spelling mistakes. A session pins and persists the validated definition so editing files cannot alter an existing identity. `FileAgentDefinitionStore` validates field rules and that `ProviderPreferences` aliases resolve (`primary-llm`, and when Voice.Enabled `primary-stt` / `primary-tts` in Synthetic). Missing versions return null from `GetAsync`.

## Agent Runtime and prompt/context builder

Voice generation receives the resolved effective speech locale in `AgentContext`. Its mode section instructs the model to write spoken wording in that locale, since selecting a TTS voice does not translate text. The conversation-language policy continues to govern display text; a different speech language uses a separate spoken projection. Text-mode prompts omit this speech-language instruction. Locale changes apply to the next generation, including clearing the override back to Agent default.

Implement a concrete PromptContextBuilder invoked by the default IAgentBrain. Keep named, independently testable sections in Application, not scattered concatenation inside endpoints or adapters. Order:

1. Core sections: the platform-owned operating contract and only applicable built-in, voice-output and attachment-reading procedures. Only Core projects to `system`; authored content cannot construct Core clauses.
2. Runtime sections: effective persona/goals, `agentInstructions`, policies, Session mode/locale, current tool facts, enabled/loaded Skills and authorized persisted task intent. Runtime projects to `developer` with frozen Definition/Instance field provenance. Mode and locale remain trusted facts; fixed voice/delivery/security and Office-reading rules belong to Core. Unavailable attachment reread never injects its tool-specific procedure.
3. Evidence sections: remembered summary/profile/memory, Experience/Continuity, resources, attachments and trigger payloads, framed as data. Selected chronological history and the current user batch retain native user/assistant roles; tool continuations retain assistant/tool roles and call IDs.

`ContextAssembler` orders and validates this single representation for conversations, initiative, completion, compaction, schedule classification and Synthetic draft evaluation. Core and Runtime have separate hard budgets; optional Evidence is omitted deterministically with manifest coverage. Existing SummaryBoundary, delivered/heard-prefix, history and Office/attachment selectors remain the content owners. The current task is never duplicated or silently truncated.

Agent-execution context requires effective Runtime identity and instructions. Platform-only auxiliaries explicitly select their purpose. The tool loop applies Skill, environment and recovery section updates before materializing its request, then prepares the selected semantic protocol. Repeated semantic preparation reuses an unchanged prepared request. Immutable image bytes and their cached content hashes are shared across section updates/projections; fingerprinting includes multipart content without serializing image bodies. Newly generated tool batches are validated before persistence/effects, rejecting every reused call ID while preserving existing pending-call recovery.

History includes the just-committed user turn exactly once. Do not send partial transcripts as completed turns. Do not grant environment/profile/summary text system instruction authority: wrap as quoted data with a fixed application instruction explaining its status. Adapters receive fully formed ModelRequest and only translate it. No adapter constructs identity prompts.

For authored Automation occurrences (Schedule, Event, Core Event and manual, with conversation or background output), selected conversation turns are serialized as one User-role historical-evidence JSON block rather than replayed as native user/assistant instructions. The same summary boundary, newest-20 selection and delivered/heard prefixes apply. Serialization and its label fit within the existing 24,000-character history budget by dropping older complete entries. A selected Core clause keeps those turns contextual: intervening requests cannot replace or suppress the admitted task. The persisted Automation instructions are pinned Runtime task intent; trigger JSON and historical content remain Evidence. Historical chat cannot edit or cancel an Automation; legitimate owner changes use the existing authorized commands and affect future admissions. Current tool permissions and approvals remain independent. Conversation-output occurrences match the persisted task scope, format and length; they do not answer earlier Chat requests or append unsolicited administration or past-action commentary. Current execution blockers must still be reported honestly. Ordinary UserTurn and native initiative histories retain their conversation roles.

Context budget baseline: retain newest 20 entries, maximum 24,000 UTF-16 characters of history, summary <=2,000 characters and profile <=2,000 characters. Drop oldest complete entries first and retain the current user turn; reject an over-budget current turn rather than silently changing meaning. Definition `agentInstructions` retains its existing 8,000-character validation. The assembler separately rejects Core above 65,536 and Runtime above 131,072 characters; it omits optional Evidence sections above a combined 65,536-character budget with coverage metadata, while the selected native transcript retains its existing bounds. These conservative character limits are not universal model token counts: the configured model must support at least a 16k-token context, and provider contract tests must validate the chosen model/limits. A provider with a smaller limit requires lower configured context budgets, not truncation inside the adapter.

A persisted session summary is remembered data, not a system instruction. It excludes ordinary raw history only when `SummarizedThroughEntrySequence` is a valid boundary: summary text is non-empty, the sequence is positive and no greater than the durable last entry sequence, and it does not reach into the current trailing user batch. Raw entries at or below that sequence are omitted before the newest-20 / 24,000-character history budget. The current trailing user batch still appears exactly once. An invalid or overlapping boundary fails open to raw history, records the content-free `summary_boundary_rejected` diagnostic, and does not rewrite persistence during prompt construction. Initiative and completion evaluation requests use that same boundary: recent turns stay strictly after it, and the persisted summary is included in those payloads as labeled remembered data. An invalid boundary leaves those requests on raw history. Assistant history uses the received prefix for text and the heard prefix for voice. The runtime does not refresh a rolling excerpt summary when a user turn is admitted. `ConversationCompactor` proposes a format-1 summary from the previous summary plus a bounded durable prefix strictly after the committed boundary. It reads at most 41 history rows, keeps at least 20 raw entries, sends no tools or response envelope, and returns a candidate without writing the store. Empty, oversized, malformed, unsafe, or failed model output leaves the prior summary unchanged. Legacy summaries stay format 0 until a candidate replaces them. After a durable completed assistant turn, the session runtime may run that service outside the mailbox when at least 40 eligible rows remain, no approval is pending, and no response or queued user batch is active. The candidate returns through the mailbox. The mailbox commits it only when the operation generation, base summary, and source boundary still match, then persists the summary without rewriting raw rows. Detach and reattach reuse one in-flight operation. Finalization cancels it, and a late result cannot replace a newer summary. A history read that throws, or a result the mailbox cannot accept, releases that operation without changing the summary so a later completed turn can compact. A reopened snapshot loads the newest restore window, so an early raw row can be absent from that window while the committed summary still carries its content. Content-free diagnostics are `compaction_rejected`, `compaction_cancelled`, and `compaction_stale`. No embeddings or vector database. When `MemoryPolicy.SessionMemory` is set, active session memories are added as a separate learned-data Evidence section labeled remembered data, not instructions. When `MemoryPolicy.IdentityUserRetrieval` is set and the session has an agent instance plus a trusted profile, active IdentityUser memories for that instance and profile join the same block. The block states that identity and trusted profile values outrank learned memory on a conflict, and each subject and content stay on one line. Voice unheard suffixes come from speech text, the same string assistant history uses. The block stays apart from the trusted profile and persona lines. It omits another session, instance, or profile. It stays empty when neither gate is enabled, and a missing instance id does not retrieve IdentityUser items. When `MemoryPolicy.UserRetrieval` is set, active User memories for that trusted profile join the same block. A definition that leaves `UserRetrieval` off does not receive them. `UserPromotion` is a separate gate and does not by itself inject the items.

IAgentBrain checks initiative eligibility and contextual usefulness. UserTurn returns Speak without initiative evaluation. For LongSilence, EnvironmentUpdate, and UnfinishedInteraction, `DefaultAgentBrain` first applies hard gates (caps, completed assistant turn for idle, allowlisted environment, pending topic). Ineligible gates return `StaySilent` with `CountsTowardSilentCap=false` so proactive caps do not advance silent-evaluation pause. When eligible and `ILanguageModel` is configured, a compact JSON initiative evaluation (`speak|staySilent|deactivate`) decides whether generation is worthwhile; only `speak` builds the normal ModelRequest. Optional `nextWaitMs` applies to `staySilent` and proactive `speak` only: the runtime clamps it (text sessions use higher minimum silence/cooldown floors than voice) and treats null/unusable values as the existing deterministic StaySilent backoff or the normal post-Speak silence threshold. `deactivate`/`RequestDeactivate` pauses without arming a next wait. Reaching proactive caps denies further LongSilence evaluation without pausing the session; silent-evaluation and inactivity bounds still pause via `ApplyDeactivate` with durable `pauseReason`. UserTurn normally returns Speak. The controller rechecks eligibility after asynchronous decisions return and enforces hard runtime caps even when the brain returns Speak.

## OpenAI-compatible HTTP adapter

Decision: Infrastructure/OpenAICompatibleLanguageModel implements ILanguageModel using IHttpClientFactory, System.Text.Json and direct HTTP, no vendor SDK. The preferred hosted configuration targets OpenRouter, while direct OpenAI or local compatible inference use the same adapter. Named configuration supplies BaseUrl, ApiKey, DefaultModel, optional ReasoningEffort (OpenAI-compatible `reasoning_effort` on chat completions), AdditionalHeaders, Timeouts and capabilities. For the initial hosted **adapter smoke** configuration only, DefaultModel may be `openrouter/free`. The Real/demo **default** must be a **fixed** operator-selected OpenRouter model ID; do not use the random free-model router as `DefaultKey`. The shipped Real catalog offers fixed `openai/gpt-6-luna`, `anthropic/claude-haiku-5.5` and `openai/gpt-6.1-sol` choices. The variable `openrouter/free` route is ineligible for three-layer execution. Bind ApiKey from `OPENROUTER_API_KEY` or equivalent backend configuration; never from the browser. BaseUrl is the API root ending in `/v1/`; append `chat/completions` without resetting an existing path prefix. Reject non-http(s) URLs and embedded userinfo; allow local HTTP only for explicitly configured demo/self-hosted endpoints. Values come from trusted backend operator configuration, never browser requests.

Map normalized System/User/Assistant messages to endpoint roles, MaxOutputTokens to `max_tokens`, optional Temperature to `temperature`, and the adapter configuration's DefaultModel to `model`. A tool-offered conversational turn sends `max_tokens` 8192. `finish_reason=length` with a partial tool-call draft fails as `toolCallTruncated` and does not emit a tool call. `LengthLimit` before a parseable semantic envelope fails as `outputLimit` rather than `missingDisplayText`. Session-scoped reasoning effort on `ModelRequest` overrides configured `LanguageModelProviderOptions.ReasoningEffort` for that request; do not mutate the singleton options object. When `ReasoningObjectWire` is enabled (OpenRouter Real profile), map effort to a `reasoning` object. Exclude visible reasoning when no tools are offered; request reasoning details for tool rounds so adapter-owned continuation can be replayed without exposing it in display text. Stream `delta.reasoning` / `reasoning_details` into `ModelReasoningDelta` only; never concatenate them into `ModelTextDelta` or assistant display. Require `stream=true`. Send Authorization Bearer only when ApiKey is nonempty; forbid AdditionalHeaders overriding Authorization, Host or content framing headers. Tool schemas, tool choice and semantic response schemas follow the current catalog capabilities and response contract; catalog-selected Responses uses the equivalent Responses wire fields.

Use ResponseHeadersRead. Parse UTF-8 SSE incrementally across arbitrary network/line/JSON boundaries, tolerate CRLF and comments, combine multiline data fields, bound each SSE event to 1 MiB, process `[DONE]`. Normalize only text from the first supported choice; multiple choices are an InvalidRequest/UnsupportedCapability, never multiple application responses. Ignore known role-only/usage-only chunks; preserve whitespace text exactly. Map finish_reason stop→Completed, length→LengthLimit, content_filter→ContentFiltered; tool/function calls→UnsupportedCapability. Delay ModelCompleted until stream terminator so trailing usage can be included. EOF after a valid finish marker is accepted; EOF without finish marker or `[DONE]` is Unavailable. `[DONE]` without finish marker means Completed if at least a valid choice was observed; otherwise malformed stream. Malformed JSON is normalized failure, not silently skipped.

## Timeouts and retry policy

Initial background Runs reserve up to 30 seconds (at most one quarter of the pinned duration), one final tool step and 4,096 output tokens for completion. Normal prose completion checkpoints `completionRequired` and offers only `work.complete` with no semantic response envelope or substantive tools. The model must summarize existing verified receipts in 1–2,000 characters and use NeedsAttention for incomplete work. Invalid completion arguments receive field-specific feedback and at most one corrected envelope within remaining time, tool-step, output and checkpoint bounds. The typed `CompletionCorrectionAttempted` checkpoint flag prevents the allowance from resetting after provider retry or restart. A second invalid envelope, or prose after that correction, fails as `completion-invalid`; an absent completion still fails as `completion-required`; a substantive tool during finalization fails closed. Timer/step/capacity cutoffs keep this completion tool available within the original hard deadline. Genuine provider failures retain the normal bounded same-Run retry policy below; a deadline remains `run-deadline`, and ordinary prose cannot manufacture success. A resumed completion phase restores its marker and receipts without reopening work.

Scheduling clarification serializes `scheduleDraft.instructions` and the original argument object as untrusted evidence for the immediately following eligible user turn. The agent interprets that evidence and supplies a complete new structured proposal. Core never merges draft arguments, recognizes confirmation words, corrects intervals from user text or bypasses verification for particular wording. Schedule completeness is checked independently before verification: a weekly request missing weekday/time returns a structural schedule error, not an authorization failure.

`TriggerScheduleCommands.PrepareAsync` loads the owned current target, checks its expected revision, resolves structured schedule fields and configured timezone, and produces the exact action fingerprint. `ITriggerCommandAuthorizer` receives `AutomationAuthorizationRequest`: current user text, typed operation, tool, full proposed action/fingerprint and optional referent/draft and prior-conversation evidence. The runtime supplies at most eight prior nonstreaming turns within 12,000 serialized characters, excluding the current source turn; assistant text uses delivered/heard prefixes. Those turns may explain a current timezone clarification but never independently grant authority. The independent verifier checks alignment of every mutation field, including target, schedule, task, execution destination, delivery and enabled state. No language-specific production recognizer remains. Occurrence, initiative, environment, historical and missing provenance cannot authorize mutations. List/inspect reads never grant write authority.

Real verification resolves the operator catalog default through `ILanguageModelResolver` with purpose `TriggerAuthorization`, preserving declared transport/developer-role support and selecting its least supported recognized reasoning effort (otherwise its validated default). Synthetic uses an explicit typed decision fixture independent of text. The verifier starts with 512 output tokens and retries once at 1024 only on confirmed LengthLimit, within one shared 30-second deadline and caller cancellation. It discards all partial output and accepts only a completed stream with exactly one JSON decision. Deny, Ambiguous, malformed/oversized output, tools, filtering, incomplete streams and unrelated provider failures do not retry.

Allow applies to the exact prepared action within the current user execution. Deny/Ambiguous return clarification without effects. Unavailable/invalid verification retains that action in the existing durable AgentRun approval workflow and offers exact owner UI approval, without asking the user to rephrase or repeatedly calling classification. Approval binds the full fingerprint and current response; preparation reloads owner/revision/policy before dispatch. Changed actions, target revisions, Session/response scope or provenance invalidate approval. Reject, expiry, cancellation and supersession produce no mutation. Reconnection restores the same preview. Neither semantic Allow nor creation grants future memory modifications or other execution effects.

Interactive browser Runs reserve 60 seconds for requested cleanup before the final 30-second reply reserve. At 210 seconds of the unchanged 300-second active budget, Core cancels the substantive model call and checkpoints a cleanup phase. Only already-authorized semantic find/snapshot, dialog, click, tab and close operations are projected/admitted; new substantive calls in a pending batch receive `finish_required/cleanup_reserve` without execution. Dialog decisions remain model-guided and must be justified by the user’s requested action. Core does not infer authentication from filling, clicking or closure. Cleanup recovery retains the same Run, response, durable receipts and generation fences.

Interactive browser Runs reserve the final 30 seconds of their admission-pinned active execution budget (300 seconds by default) for a tool-free reply (maximum 2,048 output tokens). Core stops admitting another tool batch or another tool in a batch when the remaining budget cannot cover both its 30-second per-tool bound and the reply reserve. A work-phase model call is cancelled at the reserve boundary; the hard deadline and caller cancellation remain independent. Approval waiting pauses work, cleanup and hard-deadline clocks. Already committed receipts remain durable; unexecuted pending calls receive `finish_required` before the phase checkpoint, so crash recovery cannot replay them. A Core-only System checkpoint marker preserves the finalization phase and remaining budget. Standard and unattended admission budgets remain unchanged; initial background completion uses the reserves described above.

After successful recorded browser work, a provider timeout may start one bounded finalization phase within that remaining budget, with no browser/application tools, new effects or visible-prefix stitching. User stop/steer/disconnect never starts this recovery. Existing protocol repair stays bounded inside finalization; a requested tool fails closed as `finalizationToolCall`. Hard Run expiry is `Timeout/runDeadline`; provider deadlines retain setup/idle/total reasons; an unexpected provider cancellation is `providerCancelled`, and a per-tool timeout is `toolTimeout`. An explicit terminal `DeadlineExceeded` command may settle an expired but still-current claim only with exact revision/generation fencing; it cannot renew, retry, admit output/effects or settle a reclaimed/cancelled generation. Failed finalization preserves successful action receipts and the safe diagnostic. Closing a browser never establishes sign-out, and filling/clicking never establishes authenticated state.

Trusted prior-Run facts include only allowlisted failure code/reason, diagnostic identity, finalization reason, interruption and bounded registered tool outcomes. They omit failure-summary prose, arguments, page content, private URLs and protected values. Current and prior facts remain separate. The Chat reply outcome and recorded browser actions are presented independently, including when the reply fails.

SessionRuntime and its factory require the canonical `IAgentRunStore`. An admitted user Run paused before its first assistant entry resumes under the same Run and response while its claim remains valid; a superseding user turn cancels that unstarted Run. A durable terminal conversation save settles its Run even when its continuation callback is suppressed by pause or epoch changes.

Infrastructure disables automatic HTTP retries/hedging for generation POSTs. Session Runtime schedules a durable retry on the same AgentRun for Unavailable, RateLimited, or a Timeout classified as `setupTimeout` or `streamIdle`, only before visible output, without an uncertain in-flight effect, while attempts remain and cancellation has not been requested. The claim is released into WaitingToRetry; the coordinator claims the next attempt with the same Activation, Run and response identities and retained checkpoint/effect receipts. Safe RetryAfter determines a 1–300 second delay, defaulting to two seconds. Completed tool effects are not replayed. Authentication, invalid requests, caller cancellation and unsupported capabilities remain terminal. Total/unclassified provider timeouts and provider cancellation remain terminal except for the bounded tool-free interactive-browser finalization phase described above. A setup/idle timeout cannot prove that upstream billable work was not accepted; the bounded retry trades that possibility for recovery from transient stalls. Never stitch a retry onto visible partial text.

Separate default budgets: headers/connect 10 seconds, stream idle 60 seconds reset on any transport read (including SSE comment/heartbeat lines), total response 120 seconds per provider call. The native Real `http-openrouter` profile and Real Compose overlay override setup to 30 seconds, retaining idle 60 and total 120. HttpClient.Timeout is infinite so explicit linked deadlines own cancellation. FailureReason distinguishes `setupTimeout` (no response headers received), `streamIdle`, and `totalTimeout`; the total deadline wins when it expires during setup. Caller cancellation remains Cancelled. Setup failure messages include the configured seconds without provider bodies or host paths. Existing logs, realtime errors, persisted failure references and UI diagnostic copy carry the bounded reason. Circuit breaker defaults: 50% transport/5xx failures, minimum 5 requests over 30 seconds, break 15 seconds. It rejects quickly as Unavailable; it does not replay requests. API keys and provider bodies are excluded from logs.

Map 401/403 Authentication, 429 RateLimited (safe RetryAfter), 400/422 InvalidRequest, 5xx/network disconnect Unavailable, local deadline Timeout, caller token Cancelled, requested unsupported feature UnsupportedCapability, others Unknown. Malformed or unusable assistant output after the request was accepted is `InvalidResponse`, not `InvalidRequest`. An Infrastructure `SemanticResponseLanguageModel` decorator around resolved language models normalizes the assistant response into `ModelSemanticResponseReady` and never logs raw JSON, function arguments, or marker payloads. When display and action are otherwise valid, omitted speech normalizes to `same` and malformed speech normalizes to `none` so the Chat answer is still delivered; `llm.speech.normalized` records `speechOmitted` or `speechMalformed` without the envelope. The strict schema and `agent_core_respond` require `disposition` and `action` (`chat.respond` or null) for general activations. Direct `UserTurn` requests carry `ModelResponseContract.RequireChatResponse`, tightening structured output and `agent_core_respond` to `Continue` or `Complete` with required `chat.respond` and non-empty `displayText`; runtime admission (`InvalidAgentStep`) remains the fail-closed guard if a provider ignores that schema. Text turns (`SpeechWillBeUsed` false) canonicalize a missing or unusable speech object to `same` with null text and keep a well-formed `none` or `custom` projection. Voice turns ignore text on `same` and `none`. Omitted speech normalizes to `same`, and an unknown mode or empty `custom` text normalizes to `none` without failing the answer. The parser does not log response arguments. Application `AgentStepNormalizer` maps that provider-neutral envelope to one Agent Step. Omitted disposition and action, including the plain-text compatibility channel, become `Complete` and one `chat.respond`. An explicit null action stays empty. Memory proposals stay beside the action. `AgentStepController` decides the effect without mutating Session, AgentRun, approval, trigger, or memory. `Complete` or `Continue` with one Chat action delivers that action once. `Continue` does not start another generation. `Wait`, and `Complete` or `Continue` with no Chat action, return control without a Chat effect, memory admission, or successful assistant completion. Session Runtime removes the streaming assistant placeholder for those paths instead of marking it `Interrupted`, and live `ResponseCompletedOutput` does not set `interruptReason`. User-turn execution still commits as cancelled after persistence reconciles the removed row. Direct user-turn no-chat steps (`Wait`, `Complete`, or `Continue` without `chat.respond`) fail as `InvalidAgentStep` rather than returned control. Terminal assistant `Failed` rows always persist a `FailureReference` and publish a matching live `error` event with the same diagnostic id. `app.message.send` is not offered on the initial model generation of a direct user turn; it becomes available only after substantive non-message work (for example workspace, web, email, sandbox, or HTTP tools) in the same execution completes and only on a later generation within that turn. Tool calls from one generation share a pinned intermediate-messaging admission snapshot; unlocking does not apply mid-batch. `PumpModelAsync` treats the brain `Speak` request tool list as an upper bound and may narrow it or append only `app.message.send` after admission; it does not widen other brain-selected tools. `skills.load` alone does not unlock it. `ApplicationMessagePolicy` (defaults: twelve admitted messages per execution, 2000 characters per message, 8000 aggregate admitted characters) is enforced authoritatively in Session Runtime admission; recovered durable `ApplicationMessage` rows for the same `responseId` reduce the remaining budget. When `app.message.send` is offered, its tool description states the remaining message and aggregate character budget and the offered JSON schema `text.maxLength` is `min(2000, remainingCharacters)` for that generation; successful or duplicate tool results return `remainingMessages` and `remainingCharacters`. An exhausted budget omits the tool on the next generation and returns `over_budget` for hallucinated calls without failing the user turn. `Blocked` uses the existing diagnostic failure path. A following model completion for that response is ignored. Invalid disposition, action, payload, or a model-supplied session, destination, profile, tenant, or recipient is `InvalidResponse` with a low-cardinality failure reason and no effect. The native parser rejects those destination fields and an unknown `action` or `disposition` instead of stripping them. Hidden reasoning is not part of the step. Chat delivery maps the admitted `ChatRespondAction` through `SemanticResponseMapper`. `ChatActionAdmission` allows ordinary same-session Chat without a new approval and denies detached Session Chat. A later semantic result refreshes the same assistant entry. A terminal response ignores a duplicate observation. Native `response_format` / `json_schema` is used only when `ModelRequest.ResponseContract` is present and trusted `ModelCapabilities.StructuredOutput` is true. When structured output is absent and `ModelCapabilities.Tools` is true, the same decorator adds the adapter-only function `agent_core_respond` and reads that call as the structured response. That function is not a session tool and does not write memory. `[[memory:...]]` remains a best-effort parser for models with neither channel. `OpenAICompatibleLanguageModel` does not log native structured response bodies. A midstream failure yields ModelFailed, cancels downstream TTS and leaves the partial response failed. A future user retry creates a new response ID. [Tests](16-testing-strategy.md) specifies chunk-boundary and partial-failure tests.

`AssistantResponseSchema` separates response-function and marker-compatibility instructions. Function-capable models without native structured output receive terminal `agent_core_respond` guidance with typed blocks and structured speech/memory, forbidding compatibility controls in display text. Marker-only models retain their marker grammar and artifact provenance guidance. `SemanticResponseLanguageModel` resolves these provider protocols before the UI; the parsers and UI rendering stay unchanged.

When conversational protocol repair exhausts on an unusable or incomplete plain-text result, its terminal failure retains the original bounded reason and response channel. Output-limit failures retain their specific safe cutoff message alongside the failed repair outcome.

Speech adapters independently advertise **effective** capabilities and formats. It is speech-to-text only; it is not native speech-to-speech reasoning and must not be treated as an INativeRealtimeProvider. ## OpenAI realtime transcription adapter

The shipped `OpenAiSpeechRecognizer` live session is a no-op `DeferredSession`; `SpeechFactory` does not select Recognition Adapter=`OpenAI`. The remainder of this section is the **deferred/unshipped** streaming contract, not current runtime behavior. Selectable hosted STT today is `OpenAICompatibleBatch`.

When implemented, `OpenAiSpeechRecognizer` opens an OpenAI Realtime **transcription** session (`session.type = transcription`). Recommended configuration:

```text
OpenAiSpeechRecognizer
    → OpenAI realtime transcription session
    → configurable realtime transcription model
    default recommendation: gpt-live-transcribe
```

Model IDs stay in Infrastructure options (`DefaultModel`); Application never embeds them. The adapter opens a **backend** WebSocket to the current OpenAI Realtime transcription endpoint using the configured API key; the browser never receives that key. Optional vendor fields such as `audio.input.transcription.delay` are **adapter-local**: send them only when the selected API/model version documents support for that field; contract-test both omit and include paths. Do not treat `delay=low` (or any delay value) as a required or default Agent Core setting. Canonical audio is PCM16 mono 24 kHz (`audio/pcm` rate 24000), matching the session format. Continuously forward admitted PCM (`input_audio_buffer.append`). Map `conversation.item.input_audio_transcription.delta` to `SpeechPartial` and `conversation.item.input_audio_transcription.completed` to `SpeechFinal` for the `utteranceId` bound to that provider `item_id`. Map transport/auth/rate-limit/session errors to `RecognitionFailed`/`ProviderFailure`. Cancel and dispose the provider session on voice stream end, mode exit to text, detach, disconnect or recognition cancel. Provider reconnect creates a **new** transcription session and application streamId; do not splice PCM or reuse item bindings.

Prefer `turn_detection: null` and commit with `input_audio_buffer.commit` from `ObserveBoundaryAsync(Ended)` so Agent Core owns turns. If a concrete API revision requires provider turn detection, treat its speech-started/stopped events as evidence only: they may refine activity timing but must not authorize `Speak`, allocate a response, or split/merge browser `utteranceId`s. Browser VAD and the Interaction Controller remain authoritative.

Utterance mapping and races are specified on [ISpeechRecognizer](04-backend-interfaces.md#independent-speech-ports). Advertise effective `StreamingAudio=true`, `PartialTranscripts=true`, `SpeechBoundaryEvents` according to whether provider VAD events are consumed as evidence, and `Cancellation=true` for local session disposal. Do not claim timing/confidence fields `gpt-live-transcribe` does not return.

## Compatible batch STT (degraded)

`OpenAICompatibleBatch` is a **separate** adapter. Do not configure `OpenAiSpeechRecognizer` as batch and pretend it streams. It appends `audio/transcriptions` to its own BaseUrl and posts multipart form data: model=DefaultModel, language=RecognitionOptions.Language, response_format=json, and file=a WAV-wrapped canonical utterance. Require a JSON text string, normalize it to one SpeechFinal for the captured utteranceId, then release the buffered WAV. Effective capabilities: StreamingAudio=false, PartialTranscripts=false, SpeechBoundaryEvents=false. Barge-in policy is `speechAndFinal` (default) or configured `speechActivity`. The 20-second final-transcript application deadline cancels an outstanding batch request even when the general provider total timeout is longer. No automatic POST retries.

## Compatible speech HTTP mappings (TTS)

The speech HTTP implementation (OpenAiSpeechSynthesizer for the initial OpenAI configuration; OpenAICompatibleSpeech for another compatible endpoint) appends `audio/speech` to its own BaseUrl and posts JSON model=DefaultModel, input=segment text, voice=resolved alias, speed=SpeakingRate, response_format=pcm. Its initial supported provider response is raw PCM16 little endian mono 24 kHz; reframe into canonical frames while reading. Require configured support for that response format before enabling voice. If another endpoint returns only compressed media or a different rate, a separately tested adapter conversion is required; do not silently interpret compressed bytes as PCM. The initial HTTP speech adapter has StreamingAudio=true for streamed response bytes, TimingMarks=false, Cancellation=true for local stream cancellation; discovery must lower streaming capability if the endpoint buffers the whole response. Normalize HTTP failures using the LLM error taxonomy. Synthetic implementations implement the same ports without HTTP.

## Session ready projection

Application builds `SessionReadyProjection` / `ReadyOutput` ([Event Model](07-event-model.md)). It contains only data the API may map to `session.ready`: public agent descriptor, mode, pendingMode, status, streamId, audioFormat, **effective** capabilities, public history, pagination metadata (`hasOlderHistory`, `historyBeforeSequence`), and lastEntrySequence. The ready transcript window is the newest durable history page (`ReadHistoryPageAsync`, limit 50), overlaid with current runtime rows by entry identity so live streaming rows keep the published display prefix; it is not derived from the bounded `HistoryRestoreWindow` runtime snapshot used for prompt context. HTTP history and non-live rows use the ordinary received-clamped projection. During reattach, the one active Streaming assistant row may include the already-published display prefix through the runtime's last emitted `textStart + text.length`; this makes its text length contiguous with the next `agent.text.delta` without changing durable `receivedTextEndExclusive` or exposing a generated-but-never-published tail. It must not include session summary, agent instructions, provider configuration, credentials, unpublished generated assistant tails, mailbox/queue/timer/provider handles or other internal runtime state. Persistence `SessionSnapshot` stays on IMemoryStore and is never sent to Contracts. The rolling session summary remains server-only prompt/context data.

Environment trigger Text contains a serialized, validated data-only representation of the allowlisted payload, including orderReference/status or pending topic. AgentContext supplies Mode, PendingTopic and HelpOfferedDuringSilence explicitly; the brain never reads mutable Session Runtime fields. The runtime sets PendingTopic from an unfinished_interaction fixture via `IEnvironmentEventIngress` and clears it after a delivered intervention or an explicit fixture clear (empty topic); it does not infer a workflow or autonomous task from arbitrary user text.

## P6 durable work (observed)

`AgentRunToolCallCheckpoint` and SessionRuntime bound the complete serialized model/tool checkpoint to 256 KiB independently of the shared 8 MiB tool-output ceiling. Before dispatch it includes the next tool-message envelope in remaining checkpoint headroom and supplies adapters a conservative text budget accounting for JSON escaping. Result admission verifies the exact serialized document; oversized results become explicitly truncated, bounded prefixes. Every checkpoint is size-checked before construction. An oversized initial prompt, tool batch or exhausted result capacity returns terminal `checkpoint-capacity`, not an exception/retry loop. New checkpoints reserve space for the blocked-action hash needed by browser recovery. A legacy full checkpoint that cannot hold its recovery flag/hash fails closed without replaying the uncertain effect. Succeeded dispatch fences clear only after a tool-result checkpoint commits; capacity failure or restart cannot reexecute a completed write.

Ordinary batches/results additionally preserve one maximum valid `work.complete` and its serialized envelope, derived from the trigger's actual completion contract, plus browser recovery metadata and one bounded Core capacity notice. Valid terminal arguments use compact UTF-16 base64 storage so every permitted summary character has a fixed bound; the resumed arguments undergo normal completion/authority validation. Ordinary tool arguments and completed-effect identity remain unchanged. Before approval or external dispatch, insufficient result space returns `finish_required` and asks the model to finish from collected evidence. One bounded refusal can be checkpointed and followed by completion; further ordinary calls may fail `checkpoint-capacity`. The tested system ceiling is 256 KiB; it is not an Agent setting. Superseded read-only observations are re-compacted before result and checkpoint admission. Requested cleanup preserves 8 KiB of result/checkpoint headroom plus existing completion and recovery envelopes. Budget exhaustion with durable evidence enters finalization with `stepLimit`, `runDeadline`, `checkpointCapacity`, or `outputLimit`: conversational replies are tool-free; initial background Runs offer only `work.complete`.

After routing, `BackgroundOccurrenceIntakeHostedService` atomically admits child Session graphs. `AgentRunHostedService` reconciles pending Experience/input intent and dispatches runnable claims through `AgentRunCoordinator`. Scheduling/routing remains separate from shared Session execution; waiting and terminal Runs hold no claim. Lifecycle counters carry bounded outcomes only.

A headless Running claim retains runtime ownership while its brain decision is pending, including a retry whose preceding response is already terminal. Cleanup consults mailbox-owned work state under the SessionHost admission gate; WaitingToRetry may release the runtime after its durable transition.


Observed execution-model pin: `ExecutionModelPolicy` runs before live-versus-durable routing. Precedence is the registration's `ModelOverrideCatalogKey`, then the Agent Instance `UnattendedModelCatalogKey`, then `SessionModelBinder.PinDefault`. The pin (catalog key, provider alias, model id, reasoning effort, and source) is immutable on the occurrence after it is stored. Later default edits apply only to occurrences admitted afterward. Live occurrence turns resolve that pin with `ModelPurpose.Conversation`. A catalog mismatch retries as `model-unavailable` on a durable item until attempts are exhausted, still naming the original pin. ## OpenSandbox command and recovery behavior

Lazy provisioning persists generation intent before the provider create. Trusted Instance/Session/Run authority resolves exact owner mounts and effective HomeAccess. ## Bounded semantic response recovery

`SessionRuntime` omits `ModelResponseContract` throughout initial `BackgroundOutcome` Work and Cleanup. The semantic decorator forwards such requests unchanged, without `agent_core_respond` or a native response schema. Cleanup retains authorized `work.complete`; existing completion validation, one validation correction and finalization reserves remain in force. Ordinary background prose enters completion-only finalization and cannot complete the Run itself.

`ProtocolFailures` classifies only presentation/format defects as repairable: `missingDisplayText`, `invalidBlocks`, `invalidJson`, `responseFunctionArgumentsInvalid`, `invalidMarkerEnvelope`, and `outputLimit`. New format reasons require an identified semantic channel; the two historical presentation reasons remain compatible with legacy channel-less normalized failures. Complete JSON code fences normalize deterministically before ordinary full-object validation. No partial JSON/action is salvaged. Policy stops retain `contentFiltered` and cannot become output-format repairs.

Before any corrective generation, save the allowance and original failure. After a semantic corrective generation, invalid completion is terminal; validation cannot obtain another generation.
