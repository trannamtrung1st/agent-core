# Backend Implementation Specification

Recovered conversation dispatch now admits into the same SessionHost runtime registry used by foreground attachment. Creation checks disposal, termination, ownership and runtime capacity under the existing admission gates. Dispatch itself goes through the SessionRuntime mailbox and acknowledges ownership before model completion. Attaching shares that running response; detached finalization holds the same admission gate while marking transport detached, so it cannot detach a newly attached owner. Production uses the canonical AgentRun record. Cleanup rechecks accepted work through the Session mailbox while holding admission exclusion, so an earlier settled attempt cannot revoke a newly dispatched retry.

## Capability authorization, projection and discovery

New-mode environment stores `capabilities: {mode,resolvedCapabilities,authorizationFingerprint}` and `projection: {alwaysCapabilities}`. The legacy `toolAllowlist` cannot simultaneously carry grants. Domain validates exact syntax/duplicates and projection subset; Application validates registration and context-only projection restrictions with structured findings. All draft/publication resolution is trusted, deterministic and snapshot-based. New-mode configuration absence is eligibility, not invalid authority. Persisted candidate documents are bounded to 1 MiB; this document-size guard does not impose a capability count limit.

`ToolCatalog.For` delegates projection to `ToolProjectionService` using the existing ToolPolicy-checked eligibility catalog. Legacy definitions keep their broad historical offers; capability-aware definitions project bootstrap + always + trusted context + active Skill required + execution-loaded tools, deduped by exact name. Browser start guidance and response-specific narrowing still apply. Unlike the legacy immutable initial request tool upper bound, new-mode continuations rebuild from pinned authority and current trusted context after a load or Skill activation.

`capabilities.load` ranks exact registered names even when embedded in a longer query (case-insensitive, ignoring surrounding sentence periods), then category/tag/name/summary matches with deterministic ordinal ties. It searches only authorized, discoverable, currently eligible names.

`capabilities.load` returns compact metadata and updates fenced execution state before real schemas appear on the next generation. It never executes a matched capability, changes authority, bypasses approval or reveals unauthorized/unconfigured tools. Loaded interfaces reset each AgentRun and survive retry/reclaim of that same execution. Both user and background turns persist explicit loaded IDs/count in their AgentRun checkpoint payload. Ordinary execution still rechecks registry, authority, configuration, scope, owner, lifecycle, occurrence/trust, approval and replay policy even for an unprojected or previously loaded name.

Initialize empty response/epoch-owned load state for each accepted live occurrence. Recheck the current connection before admitting its load, preserve IDs/count through continuation, and never read a completed user turn's load state for another response. Accepted live receipts remain non-replayable; see [Persistence and Configuration](15-persistence-and-configuration.md).


## Agent Workspace v2 tools and policy

Every Session belongs to a real active Agent Instance at creation. Each Agent Instance owns durable `/home`; each Session owns temporary `/working`. New Sessions and reconstructed runtimes start with cwd `/home`. Definition identity is configuration, never an alternative Session owner. Unsupported historical built-ins remain in Git history, outside the runtime catalog. `environment.workspace` may name a template only. General Assistant v20 retains the workspace tools, including `workspace.cwd`, alongside native Browser capabilities and explicitly authorized `background.start`. The canonical registry supplies identical workspace descriptions for discovery, projection and execution.

`workspace.cwd({operation:"get"})` returns `{cwd:"/home"}` initially. Set accepts `{operation:"set",path:"/home/projects/a"}` or an existing `/working` directory. A target must exist, be a directory and remain authorized. Relative read/list/search/write/patch/structure/artifact paths resolve from the current cwd. Omitted list/search path means cwd. `/workspace/working` is rejected in new mode rather than becoming a public alias. Paths cannot escape a root, select another Session/owner or expose host/blob paths. Move/delete/batch affecting cwd or an ancestor fails Conflict.

Ordinary write creates home files, accepting optional expectedRevision/expectedSha256 for replacement. Patch requires current expectedSha256 and exact-once UTF-8 edits. Read/list/search retain bounded content/tree behavior. Same-scope home mkdir/copy/move/delete/batch requires expectedTreeSha256 from a current whole-home listing. Individual `workspace.copy` between `/home` and `/working` supports exact binary bytes, complete trees, empty directories and parents, with destination quota/conflict checks. Existing home file replacement requires CAS; directory destinations never merge. Cross-scope move is Forbidden; copy then separately delete if intended. Batch stays structural, at most 16 operations/16 KiB and single-scope, with full ordered preflight and honest partial execution.

Publish user downloads with `artifacts.create_from_workspace` from either root. Normal model guidance describes durable work directly in home and explicit scratch processing/copy for sandbox. Tool policy and execution both check the pinned policy and actual managed eligibility; background work does not receive Session cwd.

Canonical legacy allowlist validation distinguishes `duplicate_tool` and `invalid_tool_name`; candidate validation retains unregistered_tool and unconfigured_tool. Findings name `environment.toolAllowlist`; authoring Problem Details retains `code:ValidationError` and adds `field`/`validationCode` plus useful detail. The former 32 limit has been removed by the capability enhancement above.


[Interfaces](04-backend-interfaces.md) owns ports, [Architecture](03-system-architecture.md) owns concurrency, and [Controller](05-interaction-controller.md) owns turn-taking. This document owns Agent Definition, text-first context construction and the initial HTTP model adapter. The canonical MVP composes STT → Interaction Controller → text Agent Runtime / LLM → Speech Segmenter → TTS; it requires no multimodal audio-reasoning model.

## Agent Definition

JSON only, UTF-8, files loaded through IAgentDefinitionStore from a configured agents directory. A file contains one definition; shipped names include `agents/examiner.json`, `agents/customer-support.json`, `agents/compliance.json`, versioned `general-assistant` files, and `agents/secretary-v1.json`. Approved knowledge bodies live beside them under `agents/knowledge/{identity}.md` and are not copied into session workspaces. Store published older versions in version subdirectories if needed; recursively index by (id, version), fail startup on duplicate keys. Versions are immutable positive integers. schemaVersion=1 identifies the format; version identifies that agent's revision. Optional `skills` stay on schemaVersion 1 and are omitted when null, so existing files and snapshots remain valid with an empty Skill set. Reject unknown schema versions and unknown fields to catch spelling mistakes. A session pins and persists the validated definition so editing files cannot alter an existing identity. `FileAgentDefinitionStore` validates field rules and that `ProviderPreferences` aliases resolve (`primary-llm`, and when Voice.Enabled `primary-stt` / `primary-tts` in Synthetic). Missing versions return null from `GetAsync`.

Optional `environment` (default empty harness/knowledge/tools, empty workspace template, `allowUnreadUnsupportedTypes=false`) is omitted from historical MVP examples below; shipped fixtures include it. `process`/`shell` remain denied even if listed. Physical template application copies `agents/templates/{templateId}` into `/working` only (no harness/knowledge corpora). Shipped initiative pins: examiner `maxConsecutiveProactiveTurns=1`, customer-support `2` (`maxPerSilencePeriod=2`, 60s silence / 120s cooldown in JSON; text runtime floors still apply), compliance `0`.

All fields above required except speech provider aliases, the three optional initiative bounds, and `environment`. id: lowercase `[a-z0-9-]`, 1..64; version positive; identity strings 1..256 except description up to 1,024; goals 1..10 nonempty strings <=500; systemInstructions <=8,000. InterruptionStyle=`acknowledgeThenContinue|answerNewTurn`; ResponseLength=`concise|balanced`; `conversationPolicy.language` is `auto` (match the user's conversational language unless they request otherwise) or a fixed BCP-47-like tag for specialized agents; maxOutputTokens 1..4,096; silenceThresholdMs 1,000..120,000; cooldownMs 5,000..600,000; maxPerSilencePeriod 1..8 (shipped examiner/compliance 1, customer-support 2). When omitted, `MaxConsecutiveProactiveTurns` defaults to 1, `MaxSilentEvaluations` to 8, `MaxInactivityMs` to 900000. Triggers are unique values `longSilence|environmentUpdate|unfinishedInteraction`. speakingRate=0.5..2.0. `LanguageModel` is always required and must resolve. When `Voice.Enabled`, `SpeechRecognizer` and `SpeechSynthesizer` are required and must resolve to configured adapters. When `Voice.Enabled` is false, those aliases must be null/omitted; a text-only process must start without STT/TTS. `InterruptionClassifier` defaults to `heuristic` if omitted. Metadata <=16 string pairs, values <=256, never secrets. Every other nullable or optional policy alternative has been removed from this initial schema; startup validation surfaces missing required values.

## Agent Runtime and prompt/context builder

Implement a concrete PromptContextBuilder invoked by the default IAgentBrain. Keep named, independently testable sections in Application, not scattered concatenation inside endpoints or adapters. Order:

1. System message: product interaction guardrails, identity, goals, systemInstructions, behavior and conversation policies.
2. System message: application-owned current mode/state and interrupted-response note. For assistant history, use the entry's deliveryMode: `received` prefix for text-delivered responses, `heard` prefix for voice-delivered responses. Include only that validated prefix; say that the rest of that response was not delivered. Unseen/unheard tails never enter this or later turns, including after a mode switch.
3. System message: labeled session summary and minimal user preferences, treated as remembered data rather than instructions. Active Skill procedures come from the frozen effective catalog in a separate system section. Enabled Always procedures initialize every execution; tool-capable prompts include compact enabled catalog metadata for OnDemand discovery. No keyword routing or live procedure reread occurs during retries. Required capabilities do not grant tools, credentials, or approval. Store reviews distinguish requested subsets from whole-grid results. A filter action is not evidence that the filter succeeded; aggregates must be supported by the observed result set, otherwise the review reports uncertainty. `skills.load` and `app.message.send` are mailbox effects on that user-turn pump. An application message is not a prompt turn.
4. System message: approved harness/knowledge identities and tool allowlist. Permission is runtime-enforced and is not granted by model text.
5. Chronological user/assistant messages from retained history; omit unseen assistant tails and non-turn backchannels. Avoid duplicating the current user entry.
6. User message containing the current environment event, when applicable, clearly delimited as observed data. For proactive triggers, generation runs only after a separate compact initiative evaluation (`initiative-decision-v2`) returns `speak` with `intent` and `objective` plan fields. That evaluation prompt includes a compact agent context (identity, goals, clipped system instructions, conversation and initiative policy) plus session state (trigger, recent turns, silence duration, proactive counters). When the summary boundary is valid, recent turns start after it and the persisted summary is included as labeled remembered data. An invalid boundary keeps raw recent turns. The full turn prompt is built only after `speak`, applying trusted `intent` (server allowlist / `InitiativeIntent`) as fixed framework instructions and passing `objective` only as untrusted planner context (`initiative_planner_observation` JSON) subordinate to identity/system prompts. `InitiativePlan` enforces intent and note bounds at the Ports boundary. Planner JSON is appended as a final User-role model message (internal context, not a human turn).

History includes the just-committed user turn exactly once. Do not send partial transcripts as completed turns. Do not grant environment/profile/summary text system instruction authority: wrap as quoted data with a fixed application instruction explaining its status. Adapters receive fully formed ModelRequest and only translate it. No adapter constructs identity prompts.

Context budget baseline: retain newest 20 entries, maximum 24,000 UTF-16 characters of history, summary <=2,000 characters and profile <=2,000 characters. Drop oldest complete entries first and retain the current user turn; reject an over-budget current turn rather than silently changing meaning. Fixed system/definition budget is <=12,000 characters; validate it when loading definitions. These conservative character limits are not universal model token counts: the configured model must support at least a 16k-token context, and provider contract tests must validate the chosen model/limits. A provider with a smaller limit requires lower configured context budgets, not truncation inside the adapter.

A persisted session summary is remembered data, not a system instruction. It excludes ordinary raw history only when `SummarizedThroughEntrySequence` is a valid boundary: summary text is non-empty, the sequence is positive and no greater than the durable last entry sequence, and it does not reach into the current trailing user batch. Raw entries at or below that sequence are omitted before the newest-20 / 24,000-character history budget. The current trailing user batch still appears exactly once. An invalid or overlapping boundary fails open to raw history, records the content-free `summary_boundary_rejected` diagnostic, and does not rewrite persistence during prompt construction. Initiative and completion evaluation requests use that same boundary: recent turns stay strictly after it, and the persisted summary is included in those payloads as labeled remembered data. An invalid boundary leaves those requests on raw history. Assistant history uses the received prefix for text and the heard prefix for voice. The runtime does not refresh a rolling excerpt summary when a user turn is admitted. `ConversationCompactor` proposes a format-1 summary from the previous summary plus a bounded durable prefix strictly after the committed boundary. It reads at most 41 history rows, keeps at least 20 raw entries, sends no tools or response envelope, and returns a candidate without writing the store. Empty, oversized, malformed, unsafe, or failed model output leaves the prior summary unchanged. Legacy summaries stay format 0 until a candidate replaces them. After a durable completed assistant turn, the session runtime may run that service outside the mailbox when at least 40 eligible rows remain, no approval is pending, and no response or queued user batch is active. The candidate returns through the mailbox. The mailbox commits it only when the operation generation, base summary, and source boundary still match, then persists the summary without rewriting raw rows. Detach and reattach reuse one in-flight operation. Finalization cancels it, and a late result cannot replace a newer summary. A history read that throws, or a result the mailbox cannot accept, releases that operation without changing the summary so a later completed turn can compact. A reopened snapshot loads the newest restore window, so an early raw row can be absent from that window while the committed summary still carries its content. Content-free diagnostics are `compaction_rejected`, `compaction_cancelled`, and `compaction_stale`. No embeddings or vector database. When `MemoryPolicy.SessionMemory` is set, active session memories are added as a separate learned-data system block labeled remembered data, not instructions. When `MemoryPolicy.IdentityUserRetrieval` is set and the session has an agent instance plus a trusted profile, active IdentityUser memories for that instance and profile join the same block. The block states that identity and trusted profile values outrank learned memory on a conflict, and each subject and content stay on one line. Voice unheard suffixes come from speech text, the same string assistant history uses. The block stays apart from the trusted profile and persona lines. It omits another session, instance, or profile. It stays empty when neither gate is enabled, and a missing instance id does not retrieve IdentityUser items. When `MemoryPolicy.UserRetrieval` is set, active User memories for that trusted profile join the same block. A definition that leaves `UserRetrieval` off does not receive them. `UserPromotion` is a separate gate and does not by itself inject the items.

IAgentBrain checks initiative eligibility and contextual usefulness. UserTurn returns Speak without initiative evaluation. For LongSilence, EnvironmentUpdate, and UnfinishedInteraction, `DefaultAgentBrain` first applies hard gates (caps, completed assistant turn for idle, allowlisted environment, pending topic). Ineligible gates return `StaySilent` with `CountsTowardSilentCap=false` so proactive caps do not advance silent-evaluation pause. When eligible and `ILanguageModel` is configured, a compact JSON initiative evaluation (`speak|staySilent|deactivate`) decides whether generation is worthwhile; only `speak` builds the normal ModelRequest. Optional `nextWaitMs` applies to `staySilent` and proactive `speak` only: the runtime clamps it (text sessions use higher minimum silence/cooldown floors than voice) and treats null/unusable values as the existing deterministic StaySilent backoff or the normal post-Speak silence threshold. `deactivate`/`RequestDeactivate` pauses without arming a next wait. Reaching proactive caps denies further LongSilence evaluation without pausing the session; silent-evaluation and inactivity bounds still pause via `ApplyDeactivate` with durable `pauseReason`. UserTurn normally returns Speak. The controller rechecks eligibility after asynchronous decisions return and enforces hard runtime caps even when the brain returns Speak.

## OpenAI-compatible HTTP adapter

Decision: Infrastructure/OpenAICompatibleLanguageModel implements ILanguageModel using IHttpClientFactory, System.Text.Json and direct HTTP, no vendor SDK. The preferred hosted configuration targets OpenRouter, while direct OpenAI or local compatible inference use the same adapter. Named configuration supplies BaseUrl, ApiKey, DefaultModel, optional ReasoningEffort (OpenAI-compatible `reasoning_effort` on chat completions), AdditionalHeaders, Timeouts and capabilities. For the initial hosted **adapter smoke** configuration only, DefaultModel may be `openrouter/free`. The Real/demo **default** must be a **fixed** operator-selected OpenRouter model ID; do not use the random free-model router as `DefaultKey`. The shipped Real catalog still offers `openai/gpt-6-luna`, `anthropic/claude-haiku-5.5`, `openai/gpt-6.1-sol`, and experimental `openrouter/free` as explicit session choices. Bind ApiKey from `OPENROUTER_API_KEY` or equivalent backend configuration; never from the browser. BaseUrl is the API root ending in `/v1/`; append `chat/completions` without resetting an existing path prefix. Reject non-http(s) URLs and embedded userinfo; allow local HTTP only for explicitly configured demo/self-hosted endpoints. Values come from trusted backend operator configuration, never browser requests.

Map normalized System/User/Assistant messages to endpoint roles, MaxOutputTokens to `max_tokens`, optional Temperature to `temperature`, and the adapter configuration's DefaultModel to `model`. A tool-offered conversational turn sends `max_tokens` 8192. `finish_reason=length` with a partial tool-call draft fails as `toolCallTruncated` and does not emit a tool call. `LengthLimit` before a parseable semantic envelope fails as `outputLimit` rather than `missingDisplayText`. Session-scoped reasoning effort on `ModelRequest` overrides configured `LanguageModelProviderOptions.ReasoningEffort` for that request; do not mutate the singleton options object. When `ReasoningObjectWire` is enabled (OpenRouter Real profile), map effort to a `reasoning` object. Exclude visible reasoning when no tools are offered; request reasoning details for tool rounds so adapter-owned continuation can be replayed without exposing it in display text. Stream `delta.reasoning` / `reasoning_details` into `ModelReasoningDelta` only; never concatenate them into `ModelTextDelta` or assistant display. Require `stream=true`. Send Authorization Bearer only when ApiKey is nonempty; forbid AdditionalHeaders overriding Authorization, Host or content framing headers. Tool schemas, tool choice and semantic response schemas follow the current catalog capabilities and response contract; catalog-selected Responses uses the equivalent Responses wire fields.

Use ResponseHeadersRead. Parse UTF-8 SSE incrementally across arbitrary network/line/JSON boundaries, tolerate CRLF and comments, combine multiline data fields, bound each SSE event to 1 MiB, process `[DONE]`. Normalize only text from the first supported choice; multiple choices are an InvalidRequest/UnsupportedCapability, never multiple application responses. Ignore known role-only/usage-only chunks; preserve whitespace text exactly. Map finish_reason stop→Completed, length→LengthLimit, content_filter→ContentFiltered; tool/function calls→UnsupportedCapability. Delay ModelCompleted until stream terminator so trailing usage can be included. EOF after a valid finish marker is accepted; EOF without finish marker or `[DONE]` is Unavailable. `[DONE]` without finish marker means Completed if at least a valid choice was observed; otherwise malformed stream. Malformed JSON is normalized failure, not silently skipped.

## Timeouts and retry policy

Interactive browser Runs reserve 60 seconds for requested cleanup before the final 30-second reply reserve. At 210 seconds of the unchanged 300-second active budget, Core cancels the substantive model call and checkpoints a cleanup phase. Only already-authorized semantic find/snapshot, dialog, click, tab and close operations are projected/admitted; new substantive calls in a pending batch receive `finish_required/cleanup_reserve` without execution. Dialog decisions remain model-guided and must be justified by the user’s requested action. Core does not infer authentication from filling, clicking or closure. Cleanup recovery retains the same Run, response, durable receipts and generation fences.

Interactive browser Runs reserve the final 30 seconds of their admission-pinned active execution budget (300 seconds by default) for a tool-free reply (maximum 2,048 output tokens). Core stops admitting another tool batch or another tool in a batch when the remaining budget cannot cover both its 30-second per-tool bound and the reply reserve. A work-phase model call is cancelled at the reserve boundary; the hard deadline and caller cancellation remain independent. Approval waiting pauses work, cleanup and hard-deadline clocks. Already committed receipts remain durable; unexecuted pending calls receive `finish_required` before the phase checkpoint, so crash recovery cannot replay them. A Core-only System checkpoint marker preserves the finalization phase and remaining budget. Standard and unattended work retain their existing budgets and completion policy.

After successful recorded browser work, a provider timeout or provider cancellation may start one bounded finalization phase within that remaining budget, with no browser/application tools, new effects or visible-prefix stitching. User stop/steer/disconnect never starts this recovery. Existing protocol repair stays bounded inside finalization; a requested tool fails closed as `finalizationToolCall`. Hard Run expiry is `Timeout/runDeadline`; provider deadlines retain setup/idle/total reasons; an unexpected provider cancellation is `providerCancelled`, and a per-tool timeout is `toolTimeout`. An explicit terminal `DeadlineExceeded` command may settle an expired but still-current claim only with exact revision/generation fencing; it cannot renew, retry, admit output/effects or settle a reclaimed/cancelled generation. Failed finalization preserves successful action receipts and the safe diagnostic. Closing a browser never establishes sign-out, and filling/clicking never establishes authenticated state.

Trusted prior-Run facts include only allowlisted failure code/reason, diagnostic identity, finalization reason, interruption and bounded registered tool outcomes. They omit failure-summary prose, arguments, page content, private URLs and protected values. Current and prior facts remain separate. The Chat reply outcome and recorded browser actions are presented independently, including when the reply fails.

SessionRuntime and its factory require the canonical `IAgentRunStore`. An admitted user Run paused before its first assistant entry resumes under the same Run and response while its claim remains valid; a superseding user turn cancels that unstarted Run. A durable terminal conversation save settles its Run even when its continuation callback is suppressed by pause or epoch changes.

Infrastructure disables automatic HTTP retries/hedging for generation POSTs. Session Runtime schedules a durable retry on the same AgentRun for Unavailable, RateLimited, or a Timeout classified as `setupTimeout` or `streamIdle`, only before visible output, without an uncertain in-flight effect, while attempts remain and cancellation has not been requested. The claim is released into WaitingToRetry; the coordinator claims the next attempt with the same Activation, Run and response identities and retained checkpoint/effect receipts. Safe RetryAfter determines a 1–300 second delay, defaulting to two seconds. Completed tool effects are not replayed. Authentication, invalid requests, caller cancellation and unsupported capabilities remain terminal. Total/unclassified provider timeouts and provider cancellation remain terminal except for the bounded tool-free interactive-browser finalization phase described above. A setup/idle timeout cannot prove that upstream billable work was not accepted; the bounded retry trades that possibility for recovery from transient stalls. Never stitch a retry onto visible partial text.

Separate default budgets: headers/connect 10 seconds, stream idle 60 seconds reset on any transport read (including SSE comment/heartbeat lines), total response 120 seconds per provider call. The native Real `http-openrouter` profile and Real Compose overlay override setup to 30 seconds, retaining idle 60 and total 120. HttpClient.Timeout is infinite so explicit linked deadlines own cancellation. FailureReason distinguishes `setupTimeout` (no response headers received), `streamIdle`, and `totalTimeout`; the total deadline wins when it expires during setup. Caller cancellation remains Cancelled. Setup failure messages include the configured seconds without provider bodies or host paths. Existing logs, realtime errors, persisted failure references and UI diagnostic copy carry the bounded reason. Circuit breaker defaults: 50% transport/5xx failures, minimum 5 requests over 30 seconds, break 15 seconds. It rejects quickly as Unavailable; it does not replay requests. API keys and provider bodies are excluded from logs.

Map 401/403 Authentication, 429 RateLimited (safe RetryAfter), 400/422 InvalidRequest, 5xx/network disconnect Unavailable, local deadline Timeout, caller token Cancelled, requested unsupported feature UnsupportedCapability, others Unknown. Malformed or unusable assistant output after the request was accepted is `InvalidResponse`, not `InvalidRequest`. An Infrastructure `SemanticResponseLanguageModel` decorator around resolved language models normalizes the assistant response into `ModelSemanticResponseReady` and never logs raw JSON, function arguments, or marker payloads. When display and action are otherwise valid, omitted speech normalizes to `same` and malformed speech normalizes to `none` so the Chat answer is still delivered; `llm.speech.normalized` records `speechOmitted` or `speechMalformed` without the envelope. The strict schema and `agent_core_respond` require `disposition` and `action` (`chat.respond` or null) for general activations. Direct `UserTurn` requests carry `ModelResponseContract.RequireChatResponse`, tightening structured output and `agent_core_respond` to `Continue` or `Complete` with required `chat.respond` and non-empty `displayText`; runtime admission (`InvalidAgentStep`) remains the fail-closed guard if a provider ignores that schema. Text turns (`SpeechWillBeUsed` false) canonicalize a missing or unusable speech object to `same` with null text and keep a well-formed `none` or `custom` projection. Voice turns ignore text on `same` and `none`. Omitted speech normalizes to `same`, and an unknown mode or empty `custom` text normalizes to `none` without failing the answer. The parser does not log response arguments. Application `AgentStepNormalizer` maps that provider-neutral envelope to one Agent Step. Omitted disposition and action, including the plain-text compatibility channel, become `Complete` and one `chat.respond`. An explicit null action stays empty. Memory proposals stay beside the action. `AgentStepController` decides the effect without mutating Session, AgentRun, approval, trigger, or memory. `Complete` or `Continue` with one Chat action delivers that action once. `Continue` does not start another generation. `Wait`, and `Complete` or `Continue` with no Chat action, return control without a Chat effect, memory admission, or successful assistant completion. Session Runtime removes the streaming assistant placeholder for those paths instead of marking it `Interrupted`, and live `ResponseCompletedOutput` does not set `interruptReason`. User-turn execution still commits as cancelled after persistence reconciles the removed row. Direct user-turn no-chat steps (`Wait`, `Complete`, or `Continue` without `chat.respond`) fail as `InvalidAgentStep` rather than returned control. Terminal assistant `Failed` rows always persist a `FailureReference` and publish a matching live `error` event with the same diagnostic id. `app.message.send` is not offered on the initial model generation of a direct user turn; it becomes available only after substantive non-message work (for example workspace, web, email, sandbox, or HTTP tools) in the same execution completes and only on a later generation within that turn. Tool calls from one generation share a pinned intermediate-messaging admission snapshot; unlocking does not apply mid-batch. `PumpModelAsync` treats the brain `Speak` request tool list as an upper bound and may narrow it or append only `app.message.send` after admission; it does not widen other brain-selected tools. `skills.load` alone does not unlock it. `ApplicationMessagePolicy` (defaults: twelve admitted messages per execution, 2000 characters per message, 8000 aggregate admitted characters) is enforced authoritatively in Session Runtime admission; recovered durable `ApplicationMessage` rows for the same `responseId` reduce the remaining budget. When `app.message.send` is offered, its tool description states the remaining message and aggregate character budget and the offered JSON schema `text.maxLength` is `min(2000, remainingCharacters)` for that generation; successful or duplicate tool results return `remainingMessages` and `remainingCharacters`. An exhausted budget omits the tool on the next generation and returns `over_budget` for hallucinated calls without failing the user turn. `Blocked` uses the existing diagnostic failure path. A following model completion for that response is ignored. Invalid disposition, action, payload, or a model-supplied session, destination, profile, tenant, or recipient is `InvalidResponse` with a low-cardinality failure reason and no effect. The native parser rejects those destination fields and an unknown `action` or `disposition` instead of stripping them. Hidden reasoning is not part of the step. Chat delivery maps the admitted `ChatRespondAction` through `SemanticResponseMapper`. `ChatActionAdmission` allows ordinary same-session Chat without a new approval and denies detached Session Chat. A later semantic result refreshes the same assistant entry. A terminal response ignores a duplicate observation. Native `response_format` / `json_schema` is used only when `ModelRequest.ResponseContract` is present and trusted `ModelCapabilities.StructuredOutput` is true. When structured output is absent and `ModelCapabilities.Tools` is true, the same decorator adds the adapter-only function `agent_core_respond` and reads that call as the structured response. That function is not a session tool and does not write memory. `[[memory:...]]` remains a best-effort parser for models with neither channel. `OpenAICompatibleLanguageModel` does not log native structured response bodies. A midstream failure yields ModelFailed, cancels downstream TTS and leaves the partial response failed. A future user retry creates a new response ID. [Tests](16-testing-strategy.md) specifies chunk-boundary and partial-failure tests.

`AssistantResponseSchema` separates response-function and marker-compatibility instructions. Function-capable models without native structured output receive terminal `agent_core_respond` guidance with typed blocks and structured speech/memory, forbidding compatibility controls in display text. Marker-only models retain their marker grammar and artifact provenance guidance. `SemanticResponseLanguageModel` resolves these provider protocols before the UI; the parsers and UI rendering stay unchanged.

Speech adapters independently advertise **effective** capabilities and formats. Observed selectable hosted speech is `OpenAiSpeechSynthesizer` and `OpenAICompatibleBatchSpeechRecognizer`, selected independently of the OpenRouter text configuration. `OpenAiSpeechRecognizer` remains a registered realtime transcription adapter class but is not a selectable runtime path while its live session is a no-op. It is speech-to-text only; it is not native speech-to-speech reasoning and must not be treated as an INativeRealtimeProvider. Bind hosted speech secrets from `OPENAI_API_KEY` or equivalent backend configuration when the operator supplies it. Implement the adapters on the existing milestone schedule; default tests and Synthetic DI must not resolve or call hosted speech adapters, and missing OpenAI credentials must not fail normal build/test. Selecting Recognition Adapter=`OpenAICompatibleBatch` with a backend API key registers `OpenAICompatibleBatchSpeechRecognizer` without an outbound call until utterance-end transcription. ## OpenAI realtime transcription adapter

The shipped `OpenAiSpeechRecognizer` live session is a no-op `DeferredSession`; `SpeechFactory` does not select Recognition Adapter=`OpenAI`. The remainder of this section is the **deferred/unshipped** streaming contract, not current runtime behavior. Selectable hosted STT today is `OpenAICompatibleBatch`.

When implemented, `OpenAiSpeechRecognizer` opens an OpenAI Realtime **transcription** session (`session.type = transcription`). Recommended configuration:

```text
OpenAiSpeechRecognizer
    → OpenAI realtime transcription session
    → configurable realtime transcription model
    default recommendation: gpt-live-transcribe
```

Model IDs stay in Infrastructure options (`DefaultModel`); Application never embeds them. The adapter opens a **backend** WebSocket to the current OpenAI Realtime transcription endpoint using the configured API key; the browser never receives that key. Optional vendor fields such as `audio.input.transcription.delay` are **adapter-local**: send them only when the selected API/model version documents support for that field; contract-test both omit and include paths. Do not treat `delay=low` (or any delay value) as a required or default Agent Core setting. Canonical audio is PCM16 mono 24 kHz (`audio/pcm` rate 24000), matching the session format. Continuously forward admitted PCM (`input_audio_buffer.append`). Map `conversation.item.input_audio_transcription.delta` to `SpeechPartial` and `conversation.item.input_audio_transcription.completed` to `SpeechFinal` for the `utteranceId` bound to that provider `item_id`. Map transport/auth/rate-limit/session errors to `RecognitionFailed`/`ProviderFailure`. Cancel and dispose the provider session on voice stream end, mode exit to text, detach, disconnect or recognition cancel. Provider reconnect creates a **new** transcription session and application streamId; do not splice PCM or reuse item bindings.

Prefer `turn_detection: null` and commit with `input_audio_buffer.commit` from `ObserveBoundaryAsync(Ended)` so Agent Core owns turns. If a concrete API revision requires provider turn detection, treat its speech-started/stopped events as evidence only: they may refine activity timing but must not authorize `Speak`, allocate a response, or split/merge browser `utteranceId`s. Browser VAD and the Interaction Controller remain authoritative.

Utterance mapping and races are specified on [ISpeechRecognizer](04-backend-interfaces.md#independent-speech-ports). Advertise effective `StreamingAudio=true`, `PartialTranscripts=true`, `SpeechBoundaryEvents` according to whether provider VAD events are consumed as evidence, and `Cancellation=true` for local session disposal. Do not claim timing/confidence fields `gpt-live-transcribe` does not return.

## Compatible batch STT (degraded)

`OpenAICompatibleBatch` is a **separate** adapter. Do not configure `OpenAiSpeechRecognizer` as batch and pretend it streams. It appends `audio/transcriptions` to its own BaseUrl and posts multipart form data: model=DefaultModel, language=RecognitionOptions.Language, response_format=json, and file=a WAV-wrapped canonical utterance. Require a JSON text string, normalize it to one SpeechFinal for the captured utteranceId, then release the buffered WAV. Effective capabilities: StreamingAudio=false, PartialTranscripts=false, SpeechBoundaryEvents=false. Barge-in policy is `speechAndFinal` (default) or configured `speechActivity`. The 20-second final-transcript application deadline cancels an outstanding batch request even when the general provider total timeout is longer. No automatic POST retries.

## Compatible speech HTTP mappings (TTS)

The speech HTTP implementation (OpenAiSpeechSynthesizer for the initial OpenAI configuration; OpenAICompatibleSpeech for another compatible endpoint) appends `audio/speech` to its own BaseUrl and posts JSON model=DefaultModel, input=segment text, voice=resolved alias, speed=SpeakingRate, response_format=pcm. Its initial supported provider response is raw PCM16 little endian mono 24 kHz; reframe into canonical frames while reading. Require configured support for that response format before enabling voice. If another endpoint returns only compressed media or a different rate, a separately tested adapter conversion is required; do not silently interpret compressed bytes as PCM. The initial HTTP speech adapter has StreamingAudio=true for streamed response bytes, TimingMarks=false, Cancellation=true for local stream cancellation; discovery must lower streaming capability if the endpoint buffers the whole response. Normalize HTTP failures using the LLM error taxonomy. Synthetic implementations implement the same ports without HTTP.

## Session ready projection

Application builds `SessionReadyProjection` / `ReadyOutput` ([Event Model](07-event-model.md)). It contains only data the API may map to `session.ready`: public agent descriptor, mode, pendingMode, status, streamId, audioFormat, **effective** capabilities, public history, pagination metadata (`hasOlderHistory`, `historyBeforeSequence`), and lastEntrySequence. The ready transcript window is the newest durable history page (`ReadHistoryPageAsync`, limit 50), overlaid with current runtime rows by entry identity so live streaming rows keep the published display prefix; it is not derived from the bounded `HistoryRestoreWindow` runtime snapshot used for prompt context. HTTP history and non-live rows use the ordinary received-clamped projection. During reattach, the one active Streaming assistant row may include the already-published display prefix through the runtime's last emitted `textStart + text.length`; this makes its text length contiguous with the next `agent.text.delta` without changing durable `receivedTextEndExclusive` or exposing a generated-but-never-published tail. It must not include session summary, Agent system instructions, provider configuration, credentials, unpublished generated assistant tails, mailbox/queue/timer/provider handles or other internal runtime state. Persistence `SessionSnapshot` stays on IMemoryStore and is never sent to Contracts. The rolling session summary remains server-only prompt/context data.

Environment trigger Text contains a serialized, validated data-only representation of the allowlisted payload, including orderReference/status or pending topic. AgentContext supplies Mode, PendingTopic and HelpOfferedDuringSilence explicitly; the brain never reads mutable Session Runtime fields. The runtime sets PendingTopic from an unfinished_interaction fixture via `IEnvironmentEventIngress` and clears it after a delivered intervention or an explicit fixture clear (empty topic); it does not infer a workflow or autonomous task from arbitrary user text.

## P6 durable work (observed)

`AgentRunToolCallCheckpoint` and SessionRuntime bound the complete serialized model/tool checkpoint to 256 KiB independently of the shared 8 MiB tool-output ceiling. Before dispatch it includes the next tool-message envelope in remaining checkpoint headroom and supplies adapters a conservative text budget accounting for JSON escaping. Result admission verifies the exact serialized document; oversized results become explicitly truncated, bounded prefixes. Every checkpoint is size-checked before construction. An oversized initial prompt, tool batch or exhausted result capacity returns terminal `checkpoint-capacity`, not an exception/retry loop. New checkpoints reserve space for the blocked-action hash needed by browser recovery. A legacy full checkpoint that cannot hold its recovery flag/hash fails closed without replaying the uncertain effect. Succeeded dispatch fences clear only after a tool-result checkpoint commits; capacity failure or restart cannot reexecute a completed write.

Ordinary batches/results additionally preserve one maximum valid `work.complete` and its serialized envelope, derived from the trigger's actual completion contract, plus browser recovery metadata and one bounded Core capacity notice. Valid terminal arguments use compact UTF-16 base64 storage so every permitted summary character has a fixed bound; the resumed arguments undergo normal completion/authority validation. Ordinary tool arguments and completed-effect identity remain unchanged. Before approval or external dispatch, insufficient result space returns `finish_required` and asks the model to finish from collected evidence. One bounded refusal can be checkpointed and followed by completion; further ordinary calls may fail `checkpoint-capacity`. The tested system ceiling is 256 KiB; it is not an Agent setting. Superseded read-only observations are re-compacted before result and checkpoint admission. Requested cleanup preserves 8 KiB of result/checkpoint headroom plus existing completion and recovery envelopes. Budget exhaustion with durable evidence enters tool-free finalization with `stepLimit`, `runDeadline`, `checkpointCapacity`, or `outputLimit`.

After routing, `BackgroundOccurrenceIntakeHostedService` atomically admits child Session graphs. `AgentRunHostedService` reconciles pending Experience/input intent and dispatches runnable claims through `AgentRunCoordinator`. Scheduling/routing remains separate from shared Session execution; waiting and terminal Runs hold no claim. Lifecycle counters carry bounded outcomes only.

A headless Running claim retains runtime ownership while its brain decision is pending, including a retry whose preceding response is already terminal. Cleanup consults mailbox-owned work state under the SessionHost admission gate; WaitingToRetry may release the runtime after its durable transition.


Observed execution-model pin: `ExecutionModelPolicy` runs before live-versus-durable routing. The pin (catalog key, provider alias, model id, reasoning effort, and source) is immutable on the occurrence after it is stored. Later default edits apply only to occurrences admitted afterward. DOM masking also covers canvas/SVG regions, known generated text and whole child frames. The host may opt exact HTTP(S) origins into `Browser:TrustedVisualCaptureOrigins` to retain Canvas/SVG graphics there; the default empty list keeps them masked. This accepts the confidentiality risk of opaque graphics on that origin. Known sensitive text, sensitive DOM regions and whole child frames remain masked, and navigation/interaction authority is unchanged. This is best-effort visual protection, not proof that every raster, CSS background, shadow-root or dynamically rendered secret is masked. `Browser:ScreenshotPrivacy=Disabled` is the host setting for stronger confidentiality requirements; agents cannot override it.

`browser.verify` condition `text` requires non-whitespace expected text, independently at typed dispatch and schema admission. `value` requires a target and explicit value; empty value intentionally verifies a cleared field. Click/form SDK completion and context closure remain effect evidence, not business success or logout. Truncated results retain status/error and the three independent outcome flags whenever the remaining envelope budget can represent them; otherwise `output_limit` is not success evidence.

Restricted response inspection uses one bounded streamed request for either page content or an attachment, preserving the native request method, body, cookie/authentication headers and response headers. No speculative attachment probe or attachment refetch remains. Attachment responses are bounded while reading, share the initiating operation deadline/cancellation and are fenced by the call identity before publication. Native pending downloads are bounded and canceled/deleted on cancellation or expired operations. Each request owns a fresh connection pool and disables redirects; it never probes or replays an uncertain request. Encoded ordinary responses and request bodies have a 16 MiB Infrastructure memory ceiling. Delayed page reads and child frames retain a bounded response lifetime without inheriting a completed operation’s cancellation token.

All browser contexts and routed fetches use the Infrastructure destination transport guard. It resolves DNS once, rejects forbidden answers (including mixed safe/forbidden answers), then connects to that exact IP. Chromium loopback proxy bypass and QUIC are disabled. HTTPS stays encrypted end to end. The guard applies to documents, resources, popups, redirects, downloads and WebSockets; native origin/interaction policy remains independently authoritative. Metadata, link-local, unspecified and multicast destinations are denied in both host modes, including mapped IPv6 and known vendor metadata addresses. Other private networks and loopback remain eligible under host authorization. No page or model can add an exception. Deterministic tests inject DNS answers without contacting metadata services.

Context initialization owns its driver/context/lock through each setup stage and publishes only after routes are installed. Partial failures close the unpublished context and preserve the original error. Late context/driver creation after cancellation is disposed. Session release removes binding metadata even after explicit/runtime close; context closure retains a live Session's owner binding for subsequent persistent-profile recreation. Persistent profiles survive Session release until explicit context close, reset or host shutdown.

Unattended leases distinguish host-policy inheritance (`null` origins), exact additional restriction (nonempty origins) and unavailable authority (empty origins). Additional origins intersect host policy. Both attached operations and leases acquire the same Agent Instance use gate before context setup/use; adoption is bound to the actual lease identity so expired flow state cannot adopt a replacement lease implicitly. Definition/capability and active Instance admission still precede every tool dispatch. Background work inherits these grants and the host's OpenWeb/Restricted choice without acquiring new authority.

## Adaptive visual browser assistance

The existing native provider, semantic targeting, capability projection, artifact store, provider serializers and Session/AgentRun tool loop own this enhancement. `PromptContextBuilder` adds concise browser strategy only when eligible browser tools exist. Effective host screenshot availability suppresses proactive capture/coordinate guidance when `ScreenshotPrivacy=Disabled`. Screenshots are recommended when authorized model vision can materially clarify unfamiliar layouts, weak labels, dashboards or unexpected overlays, without requiring repeated failed searches. Routine labeled forms and navigation use semantics. Do not automatically capture after actions, recapture unchanged states or alternate observations indefinitely. Capture failures and quota exhaustion direct the model back to semantic observation within existing execution limits.

Screenshot capture attempts a redacted semantic observation inside the same native gate before masking pixels. Optional semantic collection has a sub-budget of at most one second (or one quarter of the operation budget); the existing overall deadline is unchanged. Semantic timeout/provider failure yields `observationUnavailable=true`, empty semantic URL/title/content and a fresh snapshot/tab identity. Independent secret inspection and masking must still succeed; their failure returns no image. Caller cancellation and the overall deadline still abort capture. The receipt links image and observation through existing snapshot/tab IDs and actual encoded dimensions. The visual-state check spans semantic reads and pixel capture; changes during that interval mark the observation `settled=false` and withhold coordinate evidence. Image parts remain request-local; text-only models receive the artifact and semantics without image parts. Existing Chat Completions maps images into framed user continuations after textual tool receipts; Responses uses `input_image`. Checkpoints persist artifact references, never image bytes; rehydration validates Session ownership, length and hash and respects the active model's Vision flag. Provider selection, cancellation, authorization and accounting remain unchanged.

Viewport coordinate fallback requires a screenshot `snapshotId`, successful automatic settlement, independently unchanged visual state and existing vision/interaction authority. Semantic unavailability alone does not remove coordinate authority when these independent checks pass. Unchanged pixels after unsuccessful settlement provide context only. The existing settle observer also tracks visual changes, ignoring temporary Core and SDK capture masks. Native validation checks Session identity, page identity/generation, DOM changes, scroll and viewport dimensions before mouse dispatch. Active CSS animations or pending fonts withhold coordinate evidence. An interaction consumes the evidence; navigation, resize, tab changes and relevant layout changes invalidate it. A semantic refresh preserves unchanged evidence. Full-page and element captures never authorize viewport coordinates. Observation freshness is an operational guard, not proof against arbitrary hostile/dynamic rendering; independent outcome verification remains mandatory.

Masking and semantic redaction both honor explicit `data-sensitive` values, including short protected strings. Core hides carets through a removable masking stylesheet so SDK input-style changes cannot invalidate its own capture. Conservative Canvas/SVG masking remains the default; exact host-trusted origins may retain graphics while sensitive-region and iframe masking, privacy-disable policy and byte/count limits remain active. Charts masked by the effective host policy require permitted semantic alternatives; adaptive guidance cannot widen privacy policy. No new provider, JavaScript tool, combined observe tool, capture scheduler or Admin strategy selector is introduced.

## Scoped Instance services and execution cutover

Application owns `InstanceSettingsResolver`, `AgentInstanceSettingsService`, `AgentInstanceResourceService`, `AgentRunConfigurationResolver` and `InstanceAutomationPolicy`. Domain owns typed presence, local resource metadata, nullable inherited state and immutable `AgentRunConfiguration`; Infrastructure owns content/store transactions and EF mapping. Contracts expose bounded metadata, never binary bodies in catalogs or Run details.

Settings reads disclose field constraints from the same resolver rules used to validate saves: required Boolean values and numeric minimum/maximum restrictions, each with a field-specific reason. Initiative, Voice, memory permissions, unsupported attachment handling and Trigger permissions cannot be enabled beyond the selected Definition; Avoid unsupported claims cannot be disabled when the Definition requires it. Other permitted toggles remain independently editable, including disabling and re-enabling Voice within published permission. Invalid direct writes retain the owner revision and return the disclosed reason.

Each resource write validates normalized relative path, the common resource format allowlist (below), 8 MiB item size, 64 item/64 MiB local collection limit, secret rejection for text, owner/item CAS and active lifecycle. Knowledge is textual; binary references retain exact bytes. Content is immutable by hash and verified on read. Disable/delete cannot leave an enabled Definition Skill with missing required content. Inherited content is read-only; copy records its source and becomes independent.

Fresh user, initiative, occurrence, background and repair admissions resolve current Instance data. Runtime execution reads the bound Run configuration and captured model/persona, with live revocation checks. A consistent owner revision is checked again at store admission; concurrent owner changes cause fresh-generation retry, not mixed configuration. Session creation pins are retained only as provenance. HTTP human knowledge lookup resolves the current owner catalog; model retrieval uses the admitted Run manifest.

Common durable Definition fork copies resource IDs, paths and hashes. Explicit shared promotion copies only selected local content into `instance-promoted/<path>` and selected overrides into the draft. Verification accepts owner proposal evidence together with required Core structure/resource checks and Synthetic evaluation. Publication remains immutable and only the initiating Instance is explicitly adopted.

### Common Definition and Instance resource formats

Definition and Instance resource authoring supports plain text/Markdown, CSV/TSV, JSON/JSONL, YAML, TOML, XML, logs/INI, PDF/RTF, Word/Excel/PowerPoint and OpenDocument, PNG/JPEG/WebP/GIF/BMP/TIFF/AVIF, MP3/WAV/OGG/FLAC/M4A and MP4/WebM/MOV. CSV/TSV and the structured text formats are eligible for Knowledge and receive the existing secret-content checks. Office documents and other binary formats remain exact-byte Reference/Template/StaticAsset/EvalFixture resources; support does not imply text extraction or model parsing.

Known executables, installers, shell/JavaScript/VB scripts, HTML/SVG active documents, shortcuts and macro-enabled Office extensions are rejected even when a caller supplies an allowed MIME type. Instance multipart uploads check both the original filename and the target logical path; Definition raw content uploads have no filename and validate the path when binding. Unknown MIME types remain rejected. Files are stored as inert bytes, never executed; format validation is not malware scanning. Existing 8 MiB/item, 64-item/64 MiB collection, path, revision and immutable-content rules remain unchanged.
