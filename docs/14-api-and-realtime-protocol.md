# HTTP API and Realtime Protocol

## Tenant Agent decommission HTTP

Authenticated `GET /api/v2/tenants/{tenantId}/agents/{instanceId}/decommission` requires the current original human and raw `agents.read` on that exact owned Agent. It returns coherent Agent name/lifecycle, Instance/security revisions, decommissioned flag, current deletion hint/blocker and recorded operation ID. An exact retired owner is available only through this deliberate retained-fact projection; ordinary inventory/configuration routes exclude it.

`DELETE /api/v2/tenants/{tenantId}/agents/{instanceId}` accepts strictly `{expectedRevision,expectedInstanceRevision,operationId}`. Cookie/CSRF/no-store rules apply. Current original-human `agents.read` and `agents.delete`, an archived Agent, exact revisions and no incumbent references are required. The same checks repeat in the owning transaction. Success returns the operation ID, `status=decommissioned` and separate `cleanupStatus=completed|pending`. Completed means native profile absence and workspace purge were confirmed for this attempt; pending means committed retirement remains authoritative and technical cleanup will retry. Caller cancellation/logout after commit does not revoke that mandate. Same-operation readback cannot repeat logical retirement; a different actor/target/Instance witness or a new operation on an already retired target conflicts. The obsolete security witness is not reapplied to factual same-operation readback; current authority is still required.

Missing authentication is401; missing current human/resource authority403; stale revisions, active lifecycle, retained references or pending profile reset409; malformed/unknown body fields400. Direct endpoints never resolve tenant ownership or actors from body fields or old owner headers. This backend checkpoint adds no frontend decommission control. [Lifecycle contract](04-backend-interfaces.md#tenant-agent-decommission).

## System Browser privacy HTTP

Authenticated GET and PUT `/api/v2/system/browser/privacy` require the actual original live platform human and raw `system.governance.manage`. A tenant Owner, tenant agent or old owner header grants no access. The server derives the global User Principal from the cookie Account/session; no actor or tenant fields are accepted. PUT strictly accepts `{expectedRevision,mode,unmaskedOrigins,trustedGraphicsOrigins,acknowledgeExposure}`; mode is exactly Protected, Unmasked or Disabled. Unknown fields reject. All state-changing cookie/CSRF/no-store rules apply. The retired `/api/v2/admin/browser/privacy` has no alias; there is no tenant privacy override endpoint.

The response remains `{saved,effective,deployment,restartRequired,activation,durable,constrainedByDeployment}`. Each policy has mode, exact origin arrays and revision. Deployment exposes capture/unmasked availability and immutable exact-origin ceilings. Unmasked requires explicit exposure acknowledgement on every save and at least one authorized exact origin. Origin lists are canonical, distinct and bounded to 32 each; paths, credentials, wildcards, queries and fragments reject. Saves cannot exceed deployment authority. Saved/effective revisions remain separate: policy writes do not hot-switch capture, restart the host or delete existing Artifacts. InMemory edits remain explicitly ephemeral; SQLite survives host recreation.

A stale expected policy revision returns 409; invalid command/acknowledgement 400; insufficient current system access or deployment authority 403; missing/expired login 401. Original-login and raw system authority repeat inside the same policy/audit write transaction, so logout/password changes before commit prevent the save. A malformed/lost reply is not save authority: read current policy deliberately before another save; never automatically replay PUT. [Ports](04-backend-interfaces.md#system-browser-privacy-administration), [System UI](19-multi-tenant-iam-ux.md#platform-browser-privacy).

## Tenant Browser profile reset HTTP

Authenticated GET `/api/v2/tenants/{tenantId}/agents/{instanceId}/browser/profile` requires independent current `agents.read` and `browser.read` on the actual Agent plus the original live human login. It returns `{instanceId, instanceRevision, securityRevision, witness, profilePresent, liveViews, canReset, busy, lastReset, agentName, lifecycle}`. `lastReset` is null or `{operationId,status,reasonCode,requestedAt,recordedAt}`. Status is `pending`, `reset` or `unknown`; safe reasons are `browser_profile_reset_started`, `browser_profile_reset_completed`, `browser_profile_reset_unknown`. The Agent name and lifecycle share the same current Instance/security observation as the profile witnesses, so a human confirmation needs no unrelated metadata read. Presence/counts describe only the persistent profile. `witness` is opaque and empty while a gate is busy; it carries no page content or host path. GET does not bind/launch/create a profile. It may record abandoned pending facts through the existing Instance transaction, without close/deletion replay.

Authenticated POST at the same path plus `/reset` accepts strict `{operationId, expectedRevision, expectedInstanceRevision, witness}`. Use a fresh nonzero operation UUID and the exact GET security/Instance revisions and 64-character witness. Unknown members reject. Current raw nondelegatable `browser.manage`, both independent reads, active Instance and original human login are required before start and checked again before deletion. Standard cookie/CSRF/no-store rules apply. Missing login returns 401, unavailable/foreign/denied resources 403, stale/busy/changed authority witnesses 409, invalid body 400.

HTTP 200 returns the reset result above; only `status:reset` confirms deletion. `unknown` can mean the context closed while bytes remain. `pending` can survive an interrupted reply/settlement. Refresh GET to inspect saved facts. Repeating the same current operation returns facts without closing/deleting again, even if its submitted revisions are now old. A new deliberate attempt after unknown requires refreshed witnesses and a new ID. An older used ID cannot trigger a later reset. Native/provider epoch and Instance-owned private witnesses never appear in public Agent serialization. This is human management only; no model reset tool or exceptional Browser-manage grant is added. [State](15-persistence-and-configuration.md#tenant-browser-profile-reset-state), [qualification](reports/tenant-browser-profile-reset-verification-2026-10-20.md).

## Tenant Office inspection intent

An XLSX explicit range without `sheet` selects the first worksheet; sparse mode without `sheet` traverses workbook order. The saved read scope distinguishes those meanings.

```json

```

No write, publication or recipient download is implied. Existing safe package/cursor/revision/output-limit errors contain no source bytes.

## Tenant workspace read contract

Human home reads use `/api/v2/tenants/{tenantId}/agents/{instanceId}/workspace`; scratch reads use `/api/v2/tenants/{tenantId}/sessions/{sessionId}/workspace`. Both expose GET collection (`prefix`, `cursor`, `limit`, maximum 256), `/search` (`q`, `cursor`, `limit`), `/metadata?path=...`, `/content?path=...` and `/office-preview?path=...&sheet=...&range=...`. Unknown/repeated query fields are rejected. Paths are exact absolute `/home` or `/working` paths for the bound owner; traversal aliases and the other root are rejected. Search cursors are lexical observations and may end in a directory slash.

Pages and metadata reuse the existing workspace wire records: logical path, type, bytes, modified time, directory/kind/link/mode observations and bounded paging/usage. Physical roots and hidden sibling namespaces are never projected. Missing uninitialized roots list/search empty without creating files. Content downloads are attachments with sanitized filenames and `nosniff`; reads use private/no-store caching. Office processing uses the shared limits/processor and post-processing authorization fence. Mutable metadata is not an immutable version or CAS token; changed source facts during content projection return conflict and current access loss withholds the result.

IAM `resourceType=workspace` uses `resourceId=home:{instanceId:D}` or `working:{sessionId:D}`. Actual tenant ownership is checked before reads and scope assignment. Human `workspaces.read` is independent from parent `agents.read` or `sessions.read`. Working grants retire with canonical Session deletion; home grants do not transfer to a Session or another Instance. Model tools remain a separate path; the human mutation contract follows below.

### Human workspace access hints

`GET /access` on either canonical workspace group requires current original-human and independent actual parent read. It reads no filesystem bytes or paths and returns the bound workspace, current security revision, Instance name/revision only for home under Agent read (both null for working), Session title under Session read, independent `canRead`, `canWrite`, `canDelete` and lifecycle `readOnly`. It does not require workspace body-read permission, grant authority or initialize directories. A changed owner/security/lifecycle witness withholds the projection; hints never replace operation authorization.

### Human file mutations

Both canonical home and working workspace groups accept `PUT /content?path=...&expectedRevision=...` with bounded original bytes, and `DELETE /content?path=...&expectedRevision=...` for one file/link/empty directory. Paths stay within the route-bound workspace, roots cannot be replaced/deleted, and deletes are nonrecursive. Account authentication, tenant membership and CSRF remain mandatory; invalid CSRF returns `400 invalid_csrf`. The current tenant security revision is an authorization/configuration witness, not a file version. Writes are bounded to the existing per-file/root limits, and authorization is checked before body intake and immediately before publication.

A known completed mutation returns 204 with no stored filename, body or metadata. Reads remain independently authorized. Missing access/current lifecycle or a stale witness stops the protected commit. Unexpected filesystem failure returns `workspace_effect_unknown` with `mutationsMayHaveOccurred: true`; clients reload current state and do not replay automatically. This does not add Agent tool/grant execution or filesystem CAS semantics.

Human authentication uses a same-origin HttpOnly `agentcore.session` cookie, SameSite Strict, Secure under HTTPS, twelve-hour maximum age and no sliding renewal. The encrypted ticket contains Account/session references, not role/permission snapshots. Current server session revocation, Account status and security stamp are validated on every request. Account-session data protection uses the configured credential-key root under the separate `account-sessions` purpose/directory.

`GET /api/v2/auth/csrf` returns `token` and `headerName` (`X-AgentCore-CSRF`) and sets the HttpOnly antiforgery cookie. Identity responses use `Cache-Control: no-store`; authentication middleware may add `no-cache`. Login/invitation inspection/registration have a fixed-window per-caller limit. No durable browser JWT or owner header authenticates these namespaces.

## Hub and encoding

Endpoint `/hubs/session`; MessagePack Hub Protocol v1 is the canonical application encoding (distinct from SignalR's own protocol version). `protocolVersion` stays 1. One connection attaches one session and a session has one owning connection. The hub validates, associates the connection lease, and forwards to application services. Runtime logic stays outside hub methods. Audio DTOs use `byte[]`/Uint8Array encoded as MessagePack binary. MessagePack is the default. `VITE_AGENTCORE_REALTIME_PROTOCOL=json` is a diagnostic transport on the same hub, handlers, and lifecycle; JSON byte arrays arrive as base64 and are decoded at the client boundary. Unset or any other value stays MessagePack. Vite reads the variable when the SPA is started or built from `web/` env or the Vite shell; repo-root `.env` does not apply to native Vite. Restart Vite after changing the variable; a browser refresh alone is insufficient. Changing an ASP.NET or container environment variable after that build does not switch the transport. There is no `/hubs/session-json` hub and no second lifecycle. Local JSON inspection:

```bash
cd web
VITE_AGENTCORE_REALTIME_PROTOCOL=json pnpm dev
```

The same value may be placed in gitignored `web/.env.local` (see `web/.env.example`). A JSON diagnostic image passes the variable as a Docker build arg (`docker compose build --build-arg VITE_AGENTCORE_REALTIME_PROTOCOL=json` then `docker compose up`); the default image build leaves it unset. The browser cannot set `diagnosticId`, `correlationId`, or `causationId`; the server rejects client-supplied correlation and causation.

```csharp
// AgentCore.Contracts representative boundary signatures, not runtime ports.
public sealed record ClientEnvelope(int ProtocolVersion, string SessionId,
    string EventId, long Sequence, string? Timestamp, string? ResponseId,
    string? AttachmentId, string Type);
public sealed record InputAudioDto(int ProtocolVersion, string SessionId,
    string AttachmentId, string StreamId, long FrameSequence,
    long SampleOffset, byte[] Data);
public sealed record OutputAudioDto(int ProtocolVersion, string SessionId,
    string AttachmentId, string ResponseId, long FrameSequence,
    long SampleOffset, bool IsFinal, byte[] Data);
```

Envelope record describes common metadata; each command has a statically typed payload DTO following the table, not an arbitrary dictionary. Implement SignalR hub `Attach(AttachCommand)`, `SendText(UserTextCommand)`, `CancelResponse(CancelResponseCommand)`, `SetMode(SetModeCommand)`, `SpeechStarted(SpeechStartedCommand)`, `SpeechEnded(SpeechEndedCommand)`, `SpeechEvidence(SpeechEvidenceCommand)`, `SendAudio(InputAudioDto)`, `PlaybackStarted(PlaybackCommand)`, `PlaybackProgress(PlaybackCommand)`, `PlaybackCompleted(PlaybackCommand)`, `PlaybackStopped(PlaybackCommand)`, `ResponseReceived(ResponseReceiptCommand)`, `SetMuted(MuteCommand)`, `EndSession(EndCommand)`. All return `Task<CommandAck>` except SendAudio returns Task after local ingress admission. Browser uses ordered `connection.send("SendAudio", dto)` calls, not a round-trip `invoke` for every frame; audio rejection is reported through SessionEvent error. CommandAck is `{eventId,accepted,error}` with error nullable; a non-null error uses the category/code/message/fatal/retryAfterMs payload from the error table. Accepted user text means its user entry and pending-input intent are durable. Core batches accepted entries into one Activation/AgentRun when the turn becomes effective; acknowledgement does not mean the response is complete.

The client registers `SessionEvent` for typed server envelope maps and `AudioOutput` for OutputAudioDto. Hub sends one event argument, not positional payload fields. Include serialization fixtures to verify exact keys/casing/binary bytes. Use WebSocket transport and MaximumParallelInvocationsPerClient=4 so an audio method cannot monopolize control handling. Audio ingress uses immediate bounded TryWrite and reports overflow; it never waits for STT/network work. Control sequencing still comes from the browser connection service and mailbox admission. Configure maximum receive message size 32 KiB and reject text >8,000 UTF-16 code units or frame >1,920 bytes at application validation.

## Envelope requirements and ordering

| Field | Client control | Server control |
| --- | --- | --- |
| protocolVersion | Required integer 1, including attach | Required 1 |
| sessionId | Required UUID | Required UUID |
| eventId | Required unique client UUID, reused for exact retry | Required new server UUID |
| sequence | Attach=0; subsequent controls start at 1 per attachment | Starts at 1 for ready, increases per attachment at actual send |
| timestamp | Optional UTC ISO string; advisory only | Required server TimeProvider UTC ISO string |
| correlationId | **Omitted.** If present, ProtocolError; never copied into EventContext | Required; server-stamped. Root may use the accepted client eventId as a correlation seed |
| causationId | **Omitted.** If present, ProtocolError; never copied into EventContext | Nullable; immediate producing event |
| responseId | Required for playback/receipt and `agent.response.cancel`; null otherwise | Required for all agent.*, playback.*, null for session/transcript/error unless response-scoped |
| attachmentId | Null on attach; required subsequently | Required after attach; protocol rejection may be null |
| type / payload | Required discriminant and typed payload | Required discriminant and typed payload |

`responseId` is the generation identity; there is no competing generationId. Transcript payloads require utteranceId. Audio deliberately omits eventId/correlation/timestamp/global sequence to keep high-frequency frames separate; required fields are exactly the audio DTO fields above. Correlate audio via responseId on output or streamId on input. Frame sequences/sample offsets provide audio ordering. Audio output identity is verified against the response lifecycle control stream, never inferred from arrival time.

Control sequences increase in send order, not when work was produced. Each live attachment assigns the next control sequence and finishes that `SessionEvent` send before assigning another, including when tool progress and model output publish together. Priority stop can bypass queued audio/text without producing descending counters. Sender drops stale response data before assigning its control sequence. Only `playback.stop`/`playback.gain`/error/lifecycle controls may bypass queued deltas; `agent.text.completed` and successful `agent.response.completed` are ordering fences and wait for all preceding text/audio sends for that response. Client ignores duplicate server control sequences; a gap forces resynchronization (stop output, close the connection, then reconnect and reattach). Audio has independent counters. Buffer unknown-response audio at most 60 ms until `agent.response.started` arrives, otherwise reject; never play unknown identity. Control sender must send `agent.response.started` before submitting that response's first audio.

Client serializes control calls in its connection service; API accepts increasing sequence values, tolerates gaps caused by a rejected command, rejects backwards values except exact known eventId retry. Store dedupe outcomes for the attachment (maximum 1,024 controls; reject older unknown retries as StaleCommand). Repeated eventId with different payload is ProtocolError, including a changed `user.text.behavior`. A new attachment resets command sequencing. Text eventId is also stored as ConversationEntry sourceEventId; a retry after reconnect is deduplicated by that ID with fresh attachment/sequence metadata. Keep at most one unacknowledged text submission in the browser; audio and speech boundaries are never replayed. Non-text commands are not retried across attachment changes. `agent.response.cancel` is accepted when the expected `responseId` is still active or already terminal for this session (idempotent); it is rejected as StaleCommand when a newer response is live, and as ValidationError when the id is missing, malformed, or unknown. Accepted user.text is persisted before success ACK. A valid `agent.approval.respond` ACK means the decision was accepted and the approval waiter was signalled. It does not wait for durable execution resume or downstream tool/model completion; those continue inside the owning Runtime/mailbox. Stale/unknown decisions retain their existing rejection semantics. `behavior=queue` while a response is live does not supersede it. The shipped first-party web client uses a local pending-send FIFO instead of `behavior=queue` during live responses; row Steer uses `behavior=interrupt`, `agent.response.completed` dequeues the FIFO head with the default non-interrupt path, and explicit Stop (`userStop`) does not dequeue queued drafts.

Playback textEndExclusive is the speech-coordinate offset of synthesized speech (display text when `reply.speech` is absent). Display receipts stay on `reply.text` and must not be copied onto heard. Send `response.received` when either the rendered display offset or the delivered `blockIds` set advances; a block that becomes visible without more display text still needs a receipt so reconnect can keep `DisplayDelivered`. Receipt/progress values must be <= emitted display/speech/samples and monotonic. Ignore playback.started/progress/completed/stopped and text receipts after response supersession or disconnect for state/history/context. A stopped acknowledgement may record diagnostic stop latency only. Completed successful responses may still accept a final text receipt to acknowledge already delivered text; this cannot authorize more output. When output transport is `clientSpeech`, every playback acknowledgement uses `consumedSamples=0`; `textEndExclusive` is the only heard coordinate (`started` must be 0, `progress` is clamped to already emitted speech-text, `completed` equals the final length only after `speech.output.completed`, `stopped` is the last trusted boundary). Assistant completion waits for that completed ACK. Explicit Stop leaves unaccepted first-party drafts in the browser queue, but already server-accepted `behavior=queue` turns keep durable ownership and dispatch after the interrupted response terminalizes. When muting, client sends ended boundary before mute; unmute produces session.ready-like stream data via session.state.changed with a fresh streamId before accepting PCM. Stream IDs are server-issued on ready/unmute/recovery and after a max-utterance restart. `client.speech.evidence` is admitted only for an attached unmuted Voice session whose input transport is `clientTranscript`; Voice listening on that path does not open an `ISpeechRecognizer` session, and PCM frames are ignored. Map kinds onto the existing speech evidence path: one durable final per utterance, ephemeral partials, final-before-ended, and `failed` as RecognitionFailed without a user turn. Protocol v1 remains additive: `audio.input` and server-audio PCM output DTOs are unchanged.

Speech boundaries include sampleOffset in the same stream coordinate as audio. Audio ingress defers a boundary until preceding samples are admitted; application receives speech observation promptly but recognizer flush waits for the ordered marker. This avoids separate hub invocation ordering corrupting STT buffering. One browser audio producer sends ordered frames; duplicates are ignored, gaps fail the stream.

## Server events

Conflicting late terminal events cannot replace a settled entry status or timestamp, including after reattach. `createdAt` continues to mean entry creation/generation start. Completion time is metadata, never an entry/control ordering key.

## Connection lifecycle

Session IDs act as local/demo bearer capabilities: use cryptographically random UUIDv4 session IDs (122 random bits), never sequential IDs. Production event/response IDs use UUIDv7. `IIdGenerator.NewSessionId()` and `NewId()` are specified in the C# port so deterministic tests cover both. Do not log session URLs publicly. This is not a full authentication system. **Planned until verified:** post-MVP trusted-local owner capability replaces SessionId-as-credential for catalog, attach, upload, bind, artifacts, and content ([R1](10-technology-decisions.md#decision-trusted-local-owner-capability-r1)); historical MVP still uses session IDs as demo bearers until that phase is verified.

Attach atomically acquires a fresh attachmentId lease, activating an in-memory runtime. When the durable catalog row is semantically `paused` (`pauseReason` other than `disconnected|recovered`), reject with recoverable `SessionPaused` until `POST /api/v2/sessions/{id}/reopen` clears pause and bumps `runtimeEpoch`. Transport `paused` rows (`disconnected|recovered`) attach without reopen and do not refresh `lastUserActivityAt`. If `MaxActiveSessions` would be exceeded, reject with recoverable `SessionCapacityExceeded` and `retryAfterMs` defaulting to 5000; the durable session remains and may be retried. An exact repeated Attach eventId on the same connection returns the original acknowledgement/ready snapshot and lease; it never creates a second owner. A new Attach on an already attached connection is rejected until it disconnects. A still-attached session rejects a second connection with SessionInUse; no silent takeover. Disconnect invalidates the old lease, supersedes output, closes STT, clears `pendingMode` (do not carry `PendingMode=Voice` into reconnect), and pauses initiative. If the server hasn't detected disconnect yet, reconnect retries SessionInUse with bounded backoff rather than stealing the session. Configure SignalR keepalive 10 seconds/client timeout 30 seconds. Grace retention is 60 seconds after disconnect is observed.

Attach loads/reconciles the durable snapshot if necessary and returns ready with current history/status/**mode**/pendingMode; it does not replay event/audio buffers. lastServerSequence helps diagnose a gap only. Before attach the browser discards all playback buffers and marks old active responses interrupted. Once ready arrives it replaces its history projection by entryId and may fetch older pages. A recently modified interrupted entry must be refreshed even if its entry sequence predates the cursor. User unsent text remains in the composer; retry uncertain accepted text only with original eventId. An ended session cannot be resumed or attached; create a new one explicitly. The browser may still GET the session view and `/messages` to render a read-only history. `session.mode.set` follows [controller mode rules](05-interaction-controller.md#mode-transitions). Re-entering voice after reconnect requires a new Voice click (preflight + `session.mode.set`); ready `pendingMode` is null after disconnect/crash recovery even if a voice request was queued.

ProtocolVersion !=1 yields ProtocolVersionMismatch before attachment or audio acceptance, reports supportedVersions=[1] in the safe error extension, then closes the connection. No automatic version downgrade. Clean End/DELETE first disables input and supersedes output, then persists status Ended, sends state changed, releases lease. If persistence fails, remain Ending with retryable SessionPersistenceUnavailable; do not falsely report successful durable end.

```mermaid
    participant H as Hub / SessionManager
    participant S as Session Runtime

    B--xH: Connection lost

    H->>S: Detach old lease

```

## Error policy

Categories: Provider, Session, Protocol, Audio, Validation, Connection, Transport. User-safe code/message/fatal are required. Authentication, RateLimited, Timeout, Cancelled, InvalidRequest, InvalidResponse, Unavailable, UnsupportedCapability and Unknown are provider codes normalized by the adapter. Session codes include SessionBusy, SessionInUse, SessionPaused, SessionPersistenceUnavailable, SessionCapacityExceeded, VoiceUnavailable and StaleCommand. `session.attach` on a durably paused session returns recoverable `SessionPaused` until `POST .../reopen` succeeds. Transport codes include recoverable `AudioDiscontinuity` (sequence/offset/gap; recognition restarts on a new streamId) and recoverable `MaxUtterance` (forced end after `Voice.MaxUtteranceSeconds`, default 120; recognition restarts on a new streamId). An unexpected execution failure may include optional `diagnosticId` on the `error` event and on a command ack `error`. Expected validation, not-found, conflict, protocol rejection, cancellation, and shutdown omit it. `diagnosticId` is not an extension. Expected user cancellation emits interruption, not an alarming error toast. A midstream provider failure keeps the partial entry marked failed, stops TTS/playback, and permits a new user turn; never auto-replay the request. STT/TTS failure disables voice input/output for that session until explicit reconnect or a mode reset to text; the same session's text mode remains usable. Session storage corruption/ownership failure is fatal; temporary provider/connection errors are recoverable. No automatic Real→Synthetic fallback that would mislead the user.

## Shared Event webhook envelope

`eventId` in this ingress body is a producer delivery identifier (printable ASCII, 1–64 characters), distinct from the stable Event resource UUID used by Automation triggers. The JSON body is at most 8192 UTF-8 bytes and depth 8. `data` is a required object with arbitrary bounded fields; normalized evidence is at most 4096 UTF-8 bytes. Unknown envelope fields, duplicate properties at any depth and malformed data fail closed. `occurredAt` is optional UTC; omitted/null uses admission time. Optional `rootAgentRunId` and `triggerDepth` must appear together, with a UUID and integer depth 1–4. Producers propagate correlation when execution emits another signal. Data remains quoted untrusted evidence and never grants capabilities, execution destinations or approval authority.

For Event key `invoice.paid`, send `Authorization: Bearer <secret>` to `/api/v1/hooks/invoice.paid`:

```json
{
  "eventId": "invoice-1001-paid",
  "occurredAt": "2026-10-08T16:00:00Z",
  "data": { "invoiceId": "1001", "amount": 125, "currency": "USD" }
}
```

One Event can snapshot multiple active Automation subscriptions from different Instances. Each delivery uses the same existing Occurrence → Activation → Session/AgentRun path, destination, completion reporting and policy checks. Duplicate receipt admission resumes only its original pending delivery snapshot; later subscribers never receive old signals. There is no Event Type selector or payload schema registry. `/api/v2/admin/events` remains the separate safe Admin audit feed.

The complete per-subscriber occurrence evidence, including Automation instructions and the normalized payload, retains its 8192-byte UTF-8 limit. A subscriber exceeding that budget is recorded as Skipped without truncation; other subscribers continue. Replay retains that terminal delivery status and does not create duplicate work.

### Office attachment read windows

`attachments.read` retains Session/AttachmentId authorization and ReadOnly behavior. Optional `sheet`, `cursor` (string, max 2,048 characters) and concrete A1 `range` select XLSX content; optional `offset` (zero-based) and `limit` (1–100) select DOCX elements. Omitted XLSX range selects `mode: "sparse"`: up to 500 meaningful cells, one worksheet per response, in workbook/row/column order. With no sheet selection, cursors visit all sheets, including empty ones; with an exact sheet selection they visit only that sheet. Preserve the same optional sheet selection during continuation. A non-null cursor cannot be combined with a range. Explicit range selects `mode: "range"` and preserves the existing 200-row × 64-column rectangular semantics. Rectangular XLSX `inspection` includes `mode: "range"`, `sha256`, `sheets`, `sheet`, `sheetExtents`, requested `range`, `usedRange`, `returnedRange`, `truncated`, `nextRange`, `warnings` and complete `rows`. `truncated` means this window does not cover the entire selected sheet (or output fitting reduced it); it does not indicate a file-wide access restriction. `nextRange` continues below the returned rows in the current column band, then right from the first used row; agents can instead choose any valid sheet/range using the extents. An unexpected generation-preparation fault uses the existing safe `preparation-failed` or typed `authority-unavailable` Run failure and Failed conversation row. A current started response emits the ordinary `agent.response.completed` failed outcome after durable history/Run settlement, then becomes idle. Existing recipient and response-identity gates still apply; no new route, Hub message, public debug injection or retry instruction is added. A completed consent receipt remains completed even when preparation of the later answer fails.


### Canonical human Attachment materialization

`POST /api/v2/tenants/{tenantId}/sessions/{sessionId}/attachments/{attachmentId}/materialize` accepts closed JSON `{expectedRevision}`. The authenticated original human needs independent current Session read, exact Attachment read, working Workspace write and Session-scoped Artifact creation. Lifecycle must allow file mutations. It creates an exclusive sanitized `/working` filename (bounded deterministic `name-2` collisions), verifies raw original bytes and publishes an immutable Artifact with human/source/working provenance. Success is 201 with `{artifactId,workspaceLogicalPath}` only; metadata/download remain independently authorized. This explicit action has no idempotency key and clients must not automatically retry it.

Before either effect, unavailable/revoked authority fails closed (403), stale witnesses/read-only state fail 409 and quota fails 413. After a known completed working copy, an unsuccessful publication returns 409 `attachment_materialization_incomplete`; uncertain file/publication I/O returns 409 `attachment_materialization_unknown`. Both require reloading working files and Artifacts before deciding on another explicit action; neither response claims that both copies completed. Original source bytes never change. Canonical human materialization is the narrow exception to the earlier human-Artifact-create-pending statement; generic human Artifact creation/deletion remains pending. The [shared frontend action](13-frontend-implementation-spec.md#tenant-original-attachment-copy-and-session-file-collections) uses this explicit materialization contract.


`GET` on the canonical human Attachment `/{attachmentId}/materialize` subresource supplies current original-human exact-source hints `{displayName,securityRevision,canMaterialize,readOnly}`. Independent current Session/Attachment reads are mandatory even when copy authority is absent. Working write and Session-scoped Artifact creation determine `canMaterialize`; active mutation lifecycle determines `readOnly`. Original identity/source/security/Instance fences repeat after reads. Hints confer no command or destination read authority; POST revalidates independently.
