# Clean baseline cutover

This release keeps .NET 10, the existing tenant IAM/approval owners, captured Run context, SQLite migrations, canonical files and immutable Definition history. It changes host configuration and requires a coordinated binary/configuration deployment. It does not reset installed data or reconnect Google accounts automatically.

## Prepare and audit

1. Freeze the actual release SHA and stop writers for the backup. Preserve the matching previous binary/configuration, SQLite database including a coherent WAL checkpoint/backup, workspace/Attachment/Artifact/resource roots, credential/Data Protection keys and Sandbox metadata. Restrict access to the backup; do not paste dotenv lines, tokens or protected payloads into reports.
2. Use [the host reference](host-configuration-reference.md) and [static consumer inventory](reports/clean-baseline-configuration-inventory-2026-10-26.json) to map inputs. .NET uses PascalCase `__` segments. Launch/Compose inputs, platform names, `VITE_*` public values and documented SDK conventions keep their uppercase spellings. The runtime accepts only canonical Google, speech, Drive and delimited-preview sections. Retired names fail even when blank. Remove retired assignments rather than keeping empty placeholders.
3. Audit Google grants **on the coherent restricted backup**, using its matching existing key directory and the intended canonical client ID:

   ```sh
   dotnet run --project src/AgentCore.Api --no-launch-profile -- audit-google-grants /absolute/backup/core.db /absolute/backup/credential-protection-keys CANONICAL_CLIENT_ID
   ```

   The client ID is not a secret; client secrets and tokens are never command arguments. This offline command opens SQLite read-only, disables key generation, never starts the host/workers, emits aggregate classifications only and never changes rows. `canonical`, `otherClient`, `unstamped`, `invalid`, `unreadable`, `synthetic`, `noGrant`, `connected`, `activeConnected`, `retiredAccounts`, affected tenant/binding counts distinguish recorded facts. Other-client grants cannot be assigned to a particular old integration client without provenance; the audit does not guess. Missing/mismatched keys are an audit failure or `unreadable`, never proof of no grants.
4. Register exactly `/api/v2/integrations/tenant-google/oauth/callback` on the canonical HTTPS origin (loopback HTTP is allowed for local development). Set all three GoogleOAuth fields or leave the integration unconfigured. Reconnect each unproven account deliberately through its tenant Credentials UI with its original owner, independent current IAM and new consent. Both Gmail and Drive use that client but keep their independent scopes/identities/bindings. A current check or runtime read of an unproven grant returns `oauth_reconnect_required` before HTTP and retains the encrypted grant, profile and epochs. Explicit disconnect/reconnect uses the existing audited transitions. Live Google consent, renewal and revocation UAT remain operator acceptance; offline transport fixtures are not a Google service certification.

## Apply and verify

5. Translate orchestration inputs once. Native development uses `scripts/dev-real.sh`, which parses the selected dotenv as data. Pure native hosts set `GoogleOAuth__*` and `GoogleDrive__Enabled` directly. Application Compose deployments use `python3 scripts/compose.py` with the same arguments as Docker Compose. The wrapper validates dotenv/inherited keys before interpolation and forwards only the explicit service configuration. Setting both a nonblank canonical and orchestration spelling is an error. Defaults → inherited environment → selected dotenv → launcher-owned derivations is native precedence; Compose inherited inputs override its dotenv.
6. Use disposable Synthetic SQLite and new roots first. Existing tracked EF migrations run normally. Bootstrap explicitly with the five `AGENTCORE_BOOTSTRAP_*` inputs, start and authenticate, provision an Agent and its Space/Environment context, then exercise an authorized read/execution/publication/download and restart readback. InMemory's active `Security__EphemeralBootstrap__*` startup path remains separate because it has no durable bootstrap; it is not an obsolete alias.
7. Stop/reconcile prior Sandbox workloads using their matching owner/version before changing the trusted server adapter. Deploy/restart the mounted filesystem **and retirement** adapters together, both using filesystem contract 5; never just edit a database marker or verification receipt. Retain Sandbox metadata. Reverify tenant profiles and effective Instance setup; host reachability grants no profile or execution authority. Current retirement no longer accepts contract-4 provisioning. Host readiness reads private server/mount readiness and does not require a retired global profile catalog; the selected tenant profile, Instance and Run source checks still determine execution eligibility.
8. General Assistant v34 is a new immutable built-in template. New provisioning may select it; existing v33 pins stay v33 until an authorized adoption. Core names captured Space `/home`, Instance `/private` and Session `/working`; these descriptions do not grant filesystem rights.
9. MarkItDown is deferred and absent from runtime packages, Workbench requirements and tools. The [disposable feasibility evidence](reports/clean-baseline-markitdown-feasibility-2026-10-26.json) does not authorize a host subprocess, dynamic installation or an Attachment bypass. Use existing specialized Office/windowed readers; report unsupported PDF/PPTX/scanned content honestly. A later extraction proposal must pass source authorization and isolation gates before advertising conversion.
10. Qualify the selected Real/Compose/HTTPS deployment with its actual configuration and matching roots. `python3 scripts/qualification/configuration-compose.py` checks placeholder resolution only. Focused local Synthetic evidence and live external acceptance remain separate; optional CI runs only if requested.

A clean data reset remains an explicit operator choice under [Space cutover](space-environment-cutover.md). Select a new empty database and new roots after coherent backup. Never overwrite nonempty incompatible storage or bypass guards.

## Rollback

Restore a coherent recovery point: previous binary + matching configuration + database + workspace/Attachment/Artifact/resource roots + credential/Data Protection keys + Sandbox metadata. Do not run the old binary against incompatible state or perform destructive migration rollback. Preserve audit and immutable Run/publication evidence. Account revocation, delivered external messages and other irreversible outside effects need separate reconciliation; do not replay uncertain effects.
