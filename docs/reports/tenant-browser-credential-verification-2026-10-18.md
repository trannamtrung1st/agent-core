# Tenant Browser protected Credential verification — 2026-10-18

The full proposal remains active. This successor implements the raw-authority Review lane for General Password filling through the existing Browser effect owner and adds scoped alias discovery. It does not qualify rich Browser resources, privacy/reset/decommission, autonomous injection or the wider tenant cutover.

## Implemented boundary

`browser.fill_credential` is now available only inside the existing model `approvals.request_authorization` Browser command branch. Ordinary direct tenant mutation stays closed. Core derives an exact optional witness over the actual tenant Credential, admitted/current binding, Credential/secret revisions, canonical alias, safe name and target-frame origin. Primary `credentials.use` targets that Credential; independent `credentials.read`, Browser read/use and Session read remain mandatory for executor and qualified reviewer. This interim lane requires raw compound authority and creates no ExceptionalGrant. The catalog still marks Credential use delegatable; exact one-time exceptional Credential-use consumption for a protected fill remains required and open, rather than being prohibited by a new product policy. The old Credential tenant FK, actual Session/Instance/executor ownership and existing receipt/Run transaction are reused without a schema migration. Null witnesses omit serialization, preserving ordinary Browser hashes.

The protected target owner verifies actual persisted same-Chat human UserTurn ancestry through the existing approval continuation links, source inputs, owner, response and root. Missing/mismatched parents cannot supply authority. Exact durable human consent may survive a disconnected client; no attached cookie is fabricated. Autonomous, background, cross-Session or unresolved origins cannot inject values.

The native typed tenant request requires nonserialized Core resolver and authority callbacks. Its physical witness includes the current target-frame origin from cached permitted frame handles, with no DOM read or context creation during preparation. The shared incumbent sink validates the unique live existing-password field, current intervention state and frame before resolving. Core rechecks live claim/consent/source/scopes/binding before unprotecting. Native redaction registration, field/frame revalidation and a final real Core authority callback precede SDK fill. The callback/value never enters model input, checkpoint, consent, receipt or audit. SDK acknowledgement establishes a protected field action, not form submission or verified sign-in.

`credentials.list` now uses `TenantCredentialRuntimeReadService`, current Session/Account/requester ownership, admitted/current eligible bindings, raw Credential read and current read policy. Use permission is independent. Existing alias cursor/limit and whole-record output fitting remain; post-I/O fences discard races. Private returned binding/Credential provenance is revalidated before later model generations, including approval continuations. New Review policy blocks discovery with `credential_read_review_required`; a typed metadata-read Review adapter remains open. Metadata is operator-authored non-secret data under its existing contract, not a universal free-text secret filter. Purpose-specific Email/Drive execution stays independently gated.

Both stores apply compound Browser visibility before approval counts/pagination even though protected fills have a Credential primary resource. Rotation or binding/origin drift invalidates exact consent while retaining independently authorized cancellation. The existing shared inspector shows the safe Credential and exact frame origin in escaped Browser parameter text; its execution guidance now truthfully describes one current-authority attempt.

## Observed workflows

Four actual hosted Synthetic cases cover both InMemory and disposable SQLite with native headless Chromium and a local reflecting login fixture. The model first discovers the scoped alias, proposes an exact fill, releases Runtime resources and waits for authenticated HTTP consent. The field remains empty before approval. After approval, one canonical successor uses the existing effect fence, resolves exactly once, fills the password once and delivers one bounded redacted checkpoint result to the model. Protected values are absent from approval JSON, every model request, retained admission/checkpoint/side effect and audit. Receipt and flags distinguish command completion from unverified application outcome and prohibit replay. No grant is created. Navigation is separately identified trusted fixture setup.

Two of those cases use a controlled resolver wrapper to remove actual IAM Credential-use permission after the real protected resolution but before returning to the native sink. The native final Core callback observes the change, leaves the password empty, stores Denied/`permission_denied`, and lets the model receive only unavailable/no-effect facts. Credential read remains independently granted, so earlier safe alias metadata does not itself block this outcome explanation. The wrapper does not replace native targeting, fill logic, authority checks, protector or stores.

Four native boundary cases cover missing callbacks, foreign owner/wrong command, target reuse, redaction, permission loss after resolution and live field reclassification. Two independent loopback origins demonstrate that an iframe may have a different password origin from its parent page; navigating that iframe changes the physical witness and prevents the old secret resolver from being called. No browser fill occurs on the new origin.

Both-store boundary fixtures cover exact protected consent/current secret resolution, immutable receipt reuse without another provider invocation, missing Credential scope before native target observation, secret rotation disabling consent while preserving cancellation, and server-side scoped approval counts. Actual stored parent Runs prove same-Chat human lineage; missing or substituted parents are rejected.

Metadata fixtures grant only read, prove the alias is returned without use permission, and persist the actual result in an existing tool checkpoint. Revoked read or newly required Review withholds that retained data before later model generation; the existing execution authority returns unavailable. Foreign Session frames are refused, unreadable bindings disappear from results and a 64-byte budget returns a complete output-limit error without a partial alias record.
