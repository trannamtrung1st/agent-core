## Implemented behavior

`TenantOperationPolicyService` now separates current tenant `tenant.governance.read` inspection from human-only `tenant.governance.manage` writes. The canonical collection returns the closed non-system permission catalog, bounded sorted search/count/paging, immutable approval class/human-only/delegatability, Core minimum, current effective policy, current editability and coherent security witnesses. Exact reads and the collection recheck the original live human login, current read authority and security revision after projection. Read-only inspection neither changes policy nor writes audit. Manage permission alone does not implicitly confer inspection permission. The existing witnessed policy/security/audit transaction remains the sole write owner; no new table, migration, grant, approval authority or policy interpreter is introduced.

The [UX-first contract](../19-multi-tenant-iam-ux.md#organization-governance-policy-interaction) precedes the page implementation. `/t/{tenantId}/admin/governance` reuses the current tenant Admin shell, collection toolbar/Table, large Drawer, responsive Descriptions, native form fields, shared confirmation, command and unsaved-draft guards. No new CSS, kit, token, font or asset is added. Navigation requires organization-wide read; the fresh server editability and context require manage for editing. Core minimum and current organization policy stay separate. People-only and nondelegatable actions remain explicit; review grants no missing permission.

Tightening saves directly. Relaxing mode or independence requires a named organization/permission and before/after confirmation. Use Core minimum changes the draft only; saving still uses current security/policy witnesses and confirmation when relaxing. Failed/stale saves retain choices. Stale/denied and acknowledged-but-unreadable responses block another save until deliberate reload. Reload confirms discard when dirty; close/navigation use the incumbent draft guard. The server CAS remains decisive against competing changes. A successful acknowledgement must match the exact permission, requested policy, Core minimum and next revisions before success/close.
