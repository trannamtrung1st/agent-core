## Removed authority

`IStateIsolationConfigurationStore` had no bound production caller and no test caller. DI still registered two adapters. The SQLite adapter's public `ApplyAsync` selected the physical Instance directly and could update settings, Experience/maintenance metadata and global Admin history without the canonical tenant transaction. The InMemory adapter instead resolved through a raw `FindAsync` that hides owned Instances. This was a source-confirmed internal mutation path/parity gap, not a demonstrated reachable HTTP exploit.

The unused contract, `IsolationMetadataUpdate`, both adapters and DI registration are removed together. There is no replacement unscoped writer. The shared `IsolationOwnerRevisions` value moves to `TenantAgents.cs` in the same namespace and keeps its public data shape. Canonical `TenantAgentConfigurationService.ApplyIsolationAsync` still requires the original current human, scoped update authority, exact preview fingerprint, security and three owner revisions, immutable Definition ceilings and the existing owning transaction. No schema, migration, permission/default, wire field, UI, provider or installed data changes.
