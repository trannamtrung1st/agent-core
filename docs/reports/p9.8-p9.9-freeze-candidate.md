## Delivered behavior

Experience is a separate opt-in Agent Instance store. Core admits a deterministic source checkpoint from completed observable Session history or substantive terminal WorkItems, runs a strict native structured retrospective through the normal provider abstraction and durable work machinery, and supplies eligible historical observations under a 6000-character context budget. Source outcomes, learned memory, persona and harness authority remain independently owned. Pause/end hooks acknowledge source persistence before secondary admission. Retrospection and quiet NoAction work do not recursively generate more work.

Owner-configured thoughts reuse TriggerRegistration → TriggerOccurrence → WorkItem. Both periodic admission and Run now freeze prompt/configuration/model evidence, use server-owned ThoughtActivation origin, avoid overlap including approval/retry waits, and run the existing bounded no-chat tool loop. Normal policy and exact-action approvals govern P9.7 authoring; execution refreshes current policy/freeze before applying an approved action. Tool selection/configuration and thought-registration self-mutation remain denied for this origin. NoAction and ordinary ActionCompleted are quiet. AttentionRequested uses the existing idempotent trusted-owner attention record, without granting arbitrary recipients or messaging rights.

The Admin Experience and Initiative panels reuse Ant Design v6, instance layouts, model/effort controls, confirmations, safe diagnostics and Background Work. Controls cover revisions, enable/disable, explicit retrospective checkpoints, provenance, suppression/deletion/reset, thought editing/deletion, Run now, status/outcome/model and durable approval decisions. SQLite migration, legacy schema adoption, tombstones and interrupted-admission recovery are implemented; InMemory preserves the same ownership and mutation semantics.

## Second review and corrections

A second requirement-by-requirement review found and corrected five gaps within the same proposal scope:

- Offline Session lifecycle commits after SQLite reopen now admit the same deterministic Experience checkpoint as live runtime pause/end. The source commit remains authoritative; secondary admission errors cannot change it.
- NoAction validation parses the tool-result envelope. A nested error key, null/empty error value or plain successful text no longer disguises a performed effectful action as a rejected action.
- Work source projection checks the entire tool result for sensitive values before clipping. A credential crossing the 1200-character boundary is omitted entirely.
- Owners can disable an existing thought even after its saved model disappears from the catalog. Re-enabling and Run now remain blocked until a valid model is chosen.
- Experience and Initiative reads carry response ordering. Older reads/polls cannot overwrite newer owner mutations, and polling waits during mutations and initial loads.

New backend regressions exercise offline pause/end after reopen, a substantive terminal WorkItem with a secret across the clipping boundary and five action-result classifications. An additional SQLite-backed regression removes the saved thought model from the catalog, successfully disables the registration and proves enabling/Run now remain blocked. New UI regressions complete delayed reads after newer writes in both panels. The existing failed-end integration test now awaits the SignalR error-event publication before comparing its DiagnosticId with the command acknowledgement; it keeps the same behavior assertions.

The focused review run passes 17 checks: 16 continuity journeys/boundaries plus the failed-end publication regression. Playwright MCP on the isolated Synthetic fixture delayed an actual Experience read, toggled the owner configuration, delivered the older response and retained the new value. At 390px it repeated this with Initiative enable/disable, retained the new registration state, kept Run now disabled after restoring the fixture and observed no horizontal overflow. Feature reads/writes returned 200 and no page errors occurred during these flows. After the disposable servers were shut down, two polling requests logged connection-refused errors; those are shutdown events, not flow failures. The browser was then navigated to a blank page. The initial contended frontend attempt timed out in older draft-editor/Admin tests and was interrupted. Without the broad browser/backend load, those suites passed unchanged (9 and 36 tests) and the full frontend suite passed all 600 tests. The final backend run owns acceptance after correcting the new test timestamp and the existing error-publication barrier.

## Boundaries and verification limits

Experience and thought activation default off. Thought cadence is 3600..604800 seconds, prompt and completion summary are bounded to 2000 characters, and eight nondeleted registrations per instance are admitted under the store's existing transaction/lock. Retrospection input is at most 100 entries/18000 characters; fields/items are at most 600 characters, arrays six items and serialized content 6000 characters. Explicit deeper reads stay same-owner and use the same context budget. Deleting/resetting content retains checkpoint tombstones; a genuinely new source cursor remains eligible.

No automatic promotion to learned memory, authoritative knowledge or instructions occurs. Structured interpretations can be wrong; Synthetic fixture content proves contracts and composition, not hosted-model judgement. Real-provider and live nopCommerce smoke remain explicit opt-ins and were not invoked. Six existing Docker sandbox probes were skipped because their Docker readiness probe was unavailable; the CLI is present, but a direct `docker info --format '{{.ServerVersion}}'` probe exited 1.
