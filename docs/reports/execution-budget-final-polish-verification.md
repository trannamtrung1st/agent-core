## Confirmed findings and corrections

1. Generic successful `browser.verify` during cleanup plus closure could falsely imply completed logout. Core now keeps logout requested, closure requested, closure confirmed and current operational blockers independent. Generic predicate verification, successful clicks and model claims cannot establish application authentication. With no sign-out-specific trusted proof in the current contract, logout remains unverified; the model's observed evidence remains in the result. Close-only tasks can complete from authoritative closure receipts; logout-and-close with confirmed closure is partial.
2. The earlier projection accumulated certain failures permanently. The new receipt-order projection clears a recovered operation after its success; an SDK-confirmed alternate interaction can resolve non-close operational blockers. Read-only verification cannot resolve close uncertainty, which requires a successful close receipt. A supported close-only obligation is fulfilled by closure. Earlier failures remain in durable evidence, without dominating a recovered final result.
3. The admission regex reserved capacity for negated wording and conflated logout/closure. Bounded deterministic non-backtracking recognition now pins independent intent flags. Positive log out/logout/sign out/sign off, personal and hyphenated variants, and browser-window closure are recognized. Obvious negatives, keep-signed-in/leave-open requests, conditional/advisory/conflicting instructions and oversized inputs use ordinary bounded capacity. Mixed instructions reserve only the positive obligation. This never grants authority or automatically performs cleanup.
4. Admin used duplicated host ceilings. Its protected endpoint is now the source for displayed maxima, numeric validation and explicit-budget Save admission. A shared Admin context avoids separate policy definitions across form/save consumers. Loading, failed and malformed limits reads cannot authorize explicit values; Retry preserves drafts. Definitions can reset each explicit class to null/System default, preserving other classes, publication revisions, Instance overrides and immutable Run pins.

## Limits

Recognition deliberately covers common bounded wording rather than all natural language; ambiguity keeps normal resource behavior and never becomes effect authority. Generic Core verification has no application-specific authentication proof, so it does not certify logout even when the model reports observed sign-in evidence. Finite budgets, recovery and compaction do not guarantee arbitrary real-site/model completion. All execution here is Synthetic/native Chromium with isolated stores; no paid model or external AHI replay was authorized or performed. P10/P11 and historical milestone freezes remain unchanged.
