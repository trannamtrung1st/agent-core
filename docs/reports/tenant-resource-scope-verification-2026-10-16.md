## Implemented boundary

`IamResourceScopes` resolves member User IDs, Role IDs and registered Agent Instance IDs from the current tenant security aggregate. Incoming references normalize to GUID D form. A route/body ID alone cannot establish ownership. `IamAuthorizer` validates existence, tenant ownership and permission/resource-family applicability before evaluating resource grants, including tenant-inherited grants. Unsupported resource families deny rather than accepting fabricated targets.

Access inspection/assignment and exact-action approval qualification apply at the protected resource itself. Ordinary operation permissions apply only to their catalog family. This metadata does not implement approval requests, policy evaluation or exceptional grants; those remain separate pending work.

`TenantAccessService` resource reads enforce `iam.roles.read` at the target and return direct plus inherited assignments and the tenant security revision. The read projection uses stable paging with a 1–100 page-size bound and total; page counts remain scoped to the authorized resource. The canonical assignment endpoint accepts an optional paired resource type/ID; omitted pairs choose Tenant scope in the same access model. The check endpoint accepts validated owned resources. Aggregate validation also rejects foreign/nonexistent resource assignments when a caller bypasses the service.

Registered agent identity ownership is globally unique across tenants. InMemory checks under its security write lock; SQLite performs a transactional ownership check and has a unique `SystemIdentities.AgentInstanceId` index. The new `20261016120507_UniqueAgentTenantOwnership` migration replaces the former tenant-local uniqueness index and retains a tenant lookup index. Prior migrations are untouched. The generated model snapshot also records the already-configured Account security-stamp concurrency token; this adds no column. No existing user database or application host was migrated, reset or restarted.
