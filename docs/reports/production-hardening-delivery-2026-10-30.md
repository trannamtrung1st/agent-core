### Data and restore contract

Core and both Elsa schemas share the selected SQLite database. Preserve WAL-consistent database bytes, workspace Space homes/Session private and working files, Attachments, Artifacts, Definition resources and the entire credential protection directory (including account-session and OAuth-proof subkeys). Source templates are immutable release inputs. For this profile every durable root must be an explicitly inventoried disjoint child of one private aggregate directory; no external roots, symlinks, hard links or native workloads are supported by the first backup tool. Browser profiles and OpenSandbox metadata must be declared if later enabled, with every native writer stopped; otherwise backup refuses that unsupported profile.

Backup uses a private sibling staging directory, read-only SQLite integrity/schema and protected credential/Secret/OAuth proof decryptability checks with automatic key generation disabled, a complete relative directory/file inventory with byte lengths and SHA-256, schema/source/profile and required root mappings, and atomic completion rename. Restore independently verifies everything before creating a staging tree, verifies the copied tree again, then publishes into an absent target by rename. The artifact and manifest are private, not suitable for public evidence. SHA-256 detects corruption; it does not authenticate an archive supplied by an adversary. Operator custody and matching release identity remain mandatory. No reset, migration or replay is implicit.

Signals: `/health` scheduler snapshot for TriggerScheduler readiness only (not Run/Workflow/email readiness) (HTTP 200 alone is insufficient); `AgentCore.Runtime` traces/metrics and safe diagnostic IDs for failures; existing event-storage snapshot for bounded recovery backlog; offline filesystem free space/WAL and backup verification for storage. Alerts notify an operator, never replay effects or clear receipts. Thresholds require measured healthy/overload evidence.

Cutover: stop all writers, preserve matching source/image and complete roots, verify backup, apply only explicit supported offline migrations, start qualified source with same keys/roots, authenticate/read retained state and perform safe work. Incompatible rollback restores matching old source plus the complete snapshot into a fresh target. Never down-migrate, truncate receipts or substitute fresh keys.
