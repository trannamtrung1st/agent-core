## Shipped authoring behavior

Contract docs now match the implementation. They do not call the phase complete.

- `POST /api/v2/admin/definition-drafts/new` accepts `{ definitionId }` only. The server stores `AgentDefinitionStarter` with `SourceKind.New`.
- Form and Advanced JSON edit one unsaved candidate. Invalid JSON does not save or publish.
- `PUT .../resources/batch` binds an already-stored manifest in one revision and returns the full logical-path-ordered draft resource list. A rejected manifest does not bump `Revision`.
- Optional knowledge `resourcePath` is omitted when null. Resolution uses that path when it is non-blank, otherwise `knowledge/{identity}`.
- `POST /api/v2/admin/agent-instances` accepts an optional persona. Omit or null stores the definition identity as Default. A present persona is Custom on the insert and on the single `ManagedInstanceCreated` summary.
- Playwright project `p76-admin` runs only `e2e/p76-admin-journey.spec.ts` on `data/playwright/p76-admin.db`. The `synthetic` project ignores that file.

## Closure repair

Publishing an existing definition reloaded the inventory. While that inventory was loading, the single unpublished draft auto-opened again and hid Durable publications. Auto-open now waits until the definition inventory is ready and the definition has no inventory row. A new definition with one starter draft still opens. `AdminApp.test.tsx` covers that starter open.

Older Playwright helpers targeted `getByLabel("Resource file")`, which also matched the import control names, and they read System instructions while the Capabilities tab was selected. Those locators now use the Add resource file input and return to the Definition tab first. Definition, Capabilities, and Resources still unmount while hidden.
