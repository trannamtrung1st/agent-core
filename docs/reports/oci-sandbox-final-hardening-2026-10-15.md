## Changes

- Canonical `docker.io` image, policy and credential identity remains unchanged. Manifest transport uses `https://registry-1.docker.io`; its built-in token exception requires exactly `https://auth.docker.io/token` and service `registry.docker.io`. The initial manifest probe is anonymous, Basic auth goes only to the approved token endpoint, and bearer auth goes to the requested manifest. The requested repository supplies pull-only scope. Other registries inherit no exception; redirects/cookies remain disabled and safe failures withhold provider bodies and secrets. This matches Docker's [Registry API](https://docs.docker.com/reference/api/registry/latest/) and [authentication contract](https://docs.docker.com/reference/api/registry/auth/).
- The existing Credentials dialog now creates, preserves, renews and clears optional expiry. Local date/time input converts to UTC; details show the stored offset-bearing date and Expired/Not expired/No expiry. Existing revision guards and credential-epoch invalidation remain authoritative. Protected-value rotation remains separate and preserves expiry.
- Advanced Profile storage uses MiB presentation with exact integer-byte form/API state, dirty tracking, Save/Discard and existing CAS/history. The allowed byte range remains 1 through 262,144,000. The retained Instance layout also presents its sparse storage override in MiB.
- Lifetime must be at least idle expiry. Initialization validates Unicode/null characters and the actual 16,384 UTF-8 byte budget. Submission opens invalid collapsed Advanced fields and retains the draft with field-specific guidance. The shared guarded editor continues to work in the concurrent Add prebuilt image modal.
