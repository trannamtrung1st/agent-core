## Current authority and persistence

`TenantTaskExecutionContract` recognizes only the converted scheduled/manual Automation task shapes and their exact approval successors. The incumbent operation authorizer resolves each schedule/manual root back to the immutable accepted occurrence, exact executor/Session, authored instructions and Automation revision. Current source-kind policy constrains execution. The same mailbox, capability re-projection, operation preparation, atomic transaction, grant and receipt owners perform the work. Saved task intent accompanies capability re-projection. Activity follows independent roots without treating them as reportable chat children.

`WhenRequesterLacksPermission` permits an explicitly admitted independent schedule under its own current authority; it never invents a permission-denied human. `Always`, independent review, current source reads and primary-only grant boundaries remain enforced. Current reviewer identity comes from a live human session. A null requester is not a shared human quota bucket. This does not add a generic executor, queue, grant store, approval engine or ambient tenant.

`20261020190000_TenantIndependentAccountConsent` changes the incumbent account read/action shape constraint and adds two strict no-human source guards. A null-requester account request must join to the same owned Run/Session and an actual accepted Schedule root, retaining the exact frozen task through successors. All 41 incumbent guards are frozen/restored around the approval-table rebuild; the resulting 43 guards preserve prior receipt/source ownership. Downgrade refuses retained no-human account requests before any lossy change. Legacy-only down/up retains source data and existing security guards. Old migrations are unchanged.
