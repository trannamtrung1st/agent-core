# Tenant Browser reviewed model continuation verification — 2026-10-18

The full proposal remains active. This successor connects converted reviewed Browser commands to the existing model authorization, external-effect and Run checkpoint path. It does not qualify direct Allowed Browser reads, protected resources, autonomous admission or complete Browser product acceptance.

## Implemented boundary

- The existing `approvals.request_authorization` tool adds `run_browser_command` with `command.tool` and native-schema `command.arguments`. Only converted Definition-authorized tools appear. Core derives actual tenant, Session, Instance, Run, permission and witnesses. Extra ownership/revision/grant fields, duplicate arguments and unconverted Credential/capture/upload/coordinate/geolocation/Artifact-drop inputs fail closed.
- Current source/raw permission checks precede cold owner registration. `EnsureTenantIsolationAsync` changes metadata only: zero initial contexts/pages/profile work, idempotent same-mode selection and no implicit transition/closure of a live view. Current saved cold targets can reconstruct trusted metadata; warm physical drift retains the incumbent rejection boundary.
- The shared-capacity host performs approved Browser I/O outside the mailbox through `TenantBrowserEffectService`. Exact pending authorization call matching precedes dispatch. Review retains no grant; current native-gate authority, consent/claim/time budgets, one-time physical target and no-replay receipt semantics remain.
- Factual settlement can atomically append one completed authorization result to the original live Run checkpoint with the immutable receipt/security/audit. Observation carries its expected Run revision; both stores repeat current source and compound executor/requester/reviewer scope before retaining data. Cancelled, terminal, new-generation or changed frames cannot receive it. No table, column, index, queue, observation store or migration is added.
- Normalized Browser observation JSON is bounded to 32 KiB before checkpoint framing, explicitly marked untrusted and excludes Bytes/Downloads. The actual serialized checkpoint/output limits still govern. Insufficient headroom drops observation with `result_budget_exhausted` while preserving exact outcome; factual settlement survives even when a minimal tool result cannot fit.
- Results distinguish `commandCompleted`, `applicationOutcomeVerified=false`, `applied=null` and `replayAllowed=false`. Missing/unknown observations have explicit reasons. Stored checkpoint data is consumed without a second provider call or tool-result append. Native time is charged once; a human wait does not become execution time.
- Current source/executor/requester/reviewer authority and live uncancelled claim fence every retained Browser observation before Resume and later model generations, including earlier approval hops. Each retained result carries exact request/operation provenance. Revocation preserves the receipt while withholding delivery. Historical tool data grants no future command permission.
