It builds on the [independent Session-policy correction](tenant-credential-session-read-policy-verification-2026-10-18.md) and [protected-fill grants](tenant-browser-credential-grant-verification-2026-10-18.md). ## Implemented boundary

The existing authorization tool offers `inspect_credential_metadata` with only normal discovery cursor/limit arguments. Core binds the actual Session and exact currently eligible admitted/raw-readable binding/Credential revisions, aliases and safe display witnesses. It saves at most limit+1 records so an additional saved alias can establish pagination. Metadata values, protected payloads and use permission are absent from consent. Empty pages use the actual Session-read primary resource; nonempty pages use the first saved Credential's existing tenant FK. All saved scopes remain mandatory and cannot expand during delivery.

Raw Credential read and independent Session read are separate from secret use and Settings management. Review qualification requires underlying read/approve scope for the complete saved page and applicable compound independence. No grant or RoleAssignment is issued. The inventory filters resources rather than granting undiscoverable reads; this does not redefine catalog delegatability or implement exceptional authority for other read operations. Scoped visibility filters every saved resource before totals/paging, including the lookahead. Same-root Session/normalized-query correlation ignores mutable scope/revision changes and preserves refusal/cancellation semantics.

Both stores repeat current owner, source, admitted/current capabilities, raw permissions and reviewer qualification in the ordinary consent/receipt transaction. The receipt records read authorization with Run/security/audit; it does not establish that data was delivered. The existing continuation resolves only those unchanged saved records under current authority and post-I/O fences, then checkpoints one bounded result separately. A lost pending checkpoint may rebuild only the same exact revision-bound page; it cannot rediscover new bindings or use a protected value. Whole records and private provenance remain bounded. Source/access/capacity loss can preserve an authorized receipt while withholding metadata.

Retained approved data requires the actual saved approved request, immutable human decision and matching Completed receipt plus current compound scope, source and reviewer qualification before later model generations, including approval descendants. Prior direct-read output still uses its independent current-policy check: fresh consent cannot retroactively authorize an older direct result. Results explicitly separate `readAuthorized`, `credentialMetadata`, unavailable reason, `applied=false` and `replayAllowed=false`.
