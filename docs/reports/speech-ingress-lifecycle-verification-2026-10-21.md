# Speech ingress lifecycle qualification — 2026-10-21

## Scope and ownership

The existing Session Runtime speech-input path now uses one `SpeechRecognitionIngress` resource per opened recognizer. That resource owns raw transport bytes, input continuity, bounded audio/control/deferred markers and supervised provider workers; Session Runtime remains the sole mutable conversation/controller owner. Normalized speech evidence and stream/epoch-tagged safe faults enter its mailbox. No new public endpoint, tenant authority, alternate conversation owner, mutable Run frame, persistence field, provider selector or frontend surface was introduced. This is a reusable prerequisite for canonical tenant voice, which is still unavailable and unqualified.

The former 25-message queue allowed 25 permitted 40 ms frames (a full second) while promising 500 ms. It now bounds both queued messages (25) and canonical audio (12,000 samples / 500 ms); removing a PCM message releases precisely its sample budget, while boundary markers release none. Deferred markers are bounded to 32 and at most 12,000 samples ahead of accepted audio. Equal-offset markers retain arrival order. Malformed/nonfinite evidence and old stream IDs are rejected. Admitted PCM is copied to transport-owned memory; caller buffer reuse cannot alter provider input. Sequence/offset overflow, gaps and saturated queues latch recoverable `AudioDiscontinuity` for that stream. PCM remains outside the normal domain mailbox, event history, logs and durable storage.

Mute retires the opened recognizer and its callbacks, retaining independent output playback and browser permission/capture ownership. Unmute opens a fresh recognizer with a fresh stream ID/epoch before admitting input. Late non-cooperative provider evidence cannot enter the new turn. Input/event worker exceptions are observed and normalized without provider bodies. An active provider-worker failure falls back to usable text with existing `VoiceUnavailable`, without an open/fail/reopen loop. If speech output is active, its existing mode-change supersession path stops playback, retires the response and saves the conservative heard boundary before text fallback. Late playback cannot resurrect or credit the old response. Disposal is idempotent and completes both provider input/cleanup attempts even if either fails. It retires callbacks before awaiting provider cleanup; it cannot force a vendor's permanently blocked native method to finish.

Normalized faults additionally carry their originating server stream and speech epoch, and Runtime checks both and mute before recovery. The origin fence preserves the same retirement rule at the mailbox boundary as the resource callback fence. An attempted extra gated ordering test assumed Mute and faults use one FIFO; actual faults use the urgent queue and Mute uses the normal mailbox. That fixture timed out (84 other cases passed), so its impossible ordering and test-only observer were removed. No direct reproduction of a queued-fault/mute race is claimed; late non-cooperative provider retirement and active provider-failure recovery are separately exercised.

## Limits and next work

No frontend code changed; backend Runtime integration and actual wire scenarios are the required runtime evidence for this module. No browser visual/Impeccable acceptance, real microphone/acoustic quality, hosted speech/provider, live OAuth, production data, multi-instance deployment, CI dispatch or full milestone acceptance is claimed. All providers are Synthetic or controlled in-process fixtures; no hosted keys are needed or used. Non-cooperative provider callbacks are fenced; unbounded vendor-native cleanup duration is not solved by a Core cancellation token.

Canonical tenant mode/control, current original-human microphone admission, idle-versus-live recognized turn admission, recipient-aware audio/playback receipts and frontend Voice wiring still need their complete vertical conversion. Per-Run runtime/store adapters remain pinned to actual immutable tenant claim generations; this extraction does not relax them. Remaining platform guardrails, obsolete authority/schema removal and exhaustive original-proposal security/route/design qualification are also open. The original full goal remains active.
