## Reproduced failure and change

`TenantUserProfileService.ReadAsync` required the original human before each owning-store read, then compared two captured Profile/security witnesses. If logout, relogin, password rotation or IAM change occurred after the last store read, both witnesses could still match and the private response returned 200. The same read serves a PATCH's committed result. All **16 baseline HTTP cases failed with actual 200 instead of the required 403/409**: both stores × GET/PATCH result × four retirement/change boundaries.

The service now revalidates the original login after complete comparison I/O and compares that final tenant security revision with the captured Profile witness. The owning store still enforces actual membership and exact write CAS. A PATCH committed before its acknowledgement is withheld remains saved; a fresh authorized GET recovers revision 2 and the exact applied-once value. No automatic write replay is introduced. User Profile fields, API shape, approval policy, schema and durable autonomous execution are unchanged.

The new regression uses actual stored private sentinels, wraps the real Profile store and performs the competing logout/relogin/password/role HTTP action after the final comparison read. It asserts the exact 403 `initiator_unavailable` or 409 `profile_changed`, no private Profile/sentinel in the refusal, then fresh authorized recovery of the same unchanged GET value or once-committed PATCH.
