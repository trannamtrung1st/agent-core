## Implementation evidence

- FortuneSheet React/core 1.0.4 is pinned, with formula-parser 0.2.13 fixed in the lockfile. Published React/ReactDOM peers are >=18.2. The tested frontend is React 19.3.0 / Vite 7.3.6. The exact installed license closure and full notices ship in [fortune-sheet.txt](../../web/public/notices/fortune-sheet.txt). MIT applies except bessel's Apache-2.0 terms; jStat's installed LICENSE establishes MIT despite its legacy manifest omitting the field.
- The adapter supplies supported sparse `celldata`, inert string values and bounded normalized styles. No active `f`, hyperlinks, images, calculation chains or provider editing/persistence callbacks reach FortuneSheet. ClosedXML reads cached values only. Explicit recalculation flags produce stale-cache metadata; unavailable caches remain distinct. Theme tint uses [OOXML HLS luminance semantics](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.foregroundcolor?view=openxml-3.0.1), with deterministic light/dark/indexed-color tests.
- Real browser checks exposed and corrected library behaviors that prop inspection alone missed: matrix-only input did not populate its canvas; imperative selection mutated a frozen argument under React Strict Mode; a document paste handler parsed clipboard HTML before checking read-only state; editing inputs/resize/fill/freeze handles and editing shortcut instructions needed scoped suppression. Selection initialization, copy readback, capture guards and cleaned-up observers/listeners enforce the requested read-only behavior. Zoom retains the selected range and cell jumps scroll to the selected local coordinate.
- FortuneSheet CSS is lazy and scoped during the Vite CSS transform, including the library's otherwise-global selectors. Ordinary Chat/text/image paths do not import its runtime. Vite prebundling and separate test cache directories prevent first-use optimizer reloads and collisions with an existing frontend.
- Policy requests deduplicate/cache for one application load; failures remain retryable and never fall back to frontend policy constants. Metadata precedes preview reads, actual bytes are independently bounded, and hash/version/size checks remain in place. Drive Office preview passes its effective ceiling into a separate provider download overload, using `ResponseHeadersRead` and checking both Content-Length and streamed bytes; its original download overload retains its separate transfer budget.
- Complete merges map to local coordinates. Boundary-crossing merges are disclosed and shown unmerged rather than inventing an anchor. Source-coordinate headers, worksheet/range navigation, selected-cell details, bounded row/column windows and explicit partial/shortened-value notices remain visible.
- Source/content/range errors use local recovery and preserve Download. A failed lazy module/CSS load offers Reload application: browsers can cache a failed module, so a same-document Retry is insufficient. This recovery was exercised against an intentional production-chunk HTTP 503; Download remained enabled and reopening after reload rendered the sheet.
