## Changes

- Canonical resource APIs accept uploaded bytes or an existing resource bound to the same owned draft. A guessed/staged hash never proves ownership. Core generates new IDs; parent Definition read plus update authorizes editing. Downloads resolve owned bindings, verify exact immutable bytes and recheck read authority after I/O.
- Batches preserve existing path/media/secret policies, 8 MiB item and 64-item / 64 MiB draft limits, with 16 MiB incoming-byte batches and a 24 MiB encoded HTTP limit. Invalid paths and manifest conflicts return classified client failures. SQLite path swaps vacate changing paths inside the transaction, so observers never see a partial manifest. Binding/removal, draft revision, security CAS and audit commit together.
- Scenario create/edit/remove and offline run use the same parent scope and revision boundary. Scenarios are bounded to 100. The existing Synthetic offline evaluator runs outside persistence locks and invokes no real tool or hosted provider. Changed draft/scenario/fingerprint/authority, Account suspension or cancellation prevents saving its completion.
- The store assigns evaluation `CommitRevision` from its committed tenant security revision. This controls latest evidence before timestamp ordering; callers cannot supply precedence. A later failed result blocks publication even at the earlier pass's timestamp. Snapshot queries return latest results for current saved scenarios; historical rows remain retained.
- Publication recovery distinguishes `evaluation_required`, `evaluation_stale`, `evaluation_failed` and `definition_resources_invalid`. Canonical domain validation/conflict exceptions now retain safe 400/409 classification and field/reason metadata instead of reaching unexpected-failure handling.
- Review closed mutation-only response disclosure: saved Definition update/publication/deprecation data requires read alongside mutation permission; Instance lifecycle responses also require `agents.read`. Actual mutation bits remain separate IAM decisions and do not silently grant read access.
- Concurrent immutable file puts use independent temporary files and verify a winning identical put. Only the current writer's temporary file is removed. A losing binding CAS can leave a private unbound blob; canonical APIs expose no raw-hash read/bind path. Blob retention and logical-definition cleanup remain part of the final lifecycle cutover.
