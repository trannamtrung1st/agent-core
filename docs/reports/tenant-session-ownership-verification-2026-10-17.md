## Delivered boundary

`TenantSessionService` resolves the authenticated Account/session and actual tenant User, requires independent tenant `sessions.create/read` and exact owned Instance `agents.chat`, and derives the executor from that Instance's real SystemIdentity/Principal. Active Instance and active executor are separate gates. It pins the owned published or shipped source version, effective settings, persona revision and model into the existing Session snapshot. The creator is immutable attribution, never a substitute for a future Run's requester, and no human permissions are transferred to the executor. No global ProfileId or local-user profile is created.

`ITenantSessionStore` commits backing Session/snapshot, immutable ownership, tenant security CAS and audit together. It rechecks original human/session/stamp, actual Instance generation and executor before commit. The public `/api/v2/tenants/{tenantId}/sessions` create/read/inventory endpoints return safe metadata only. Exact Session read grants filter before totals/paging; foreign, fabricated and unowned targets cannot be adopted or granted. Store reads freeze the retained Definition projection. Creating metadata does not attach a runtime or authorize a tool.

The Application service itself returns `TenantSessionMetadata`; private Definition/snapshot content stays behind the trusted persistence port. A member with Session create/read but no chat is denied; adding exact agent chat permits creation without granting `agents.read` or exposing its configuration. Final Session/service and HTTP reruns verify this projection boundary.

Intermediate migration `20261016233720_TenantSessionOwnership` binds the owning root to the actual `(SessionId, AgentInstanceId)`, exact tenant Instance/executor pair and creating tenant User with restrictive composite foreign keys. Source and ownership IDs remain unchanged; timestamps use UTC milliseconds. Global Account Principals keep nullable TenantId. InMemory shares the actual registered Session/Instance backing and retains equivalent ownership markers. The final clean-schema consolidation remains pending.

Unscoped Session metadata/history/inventory and crash recovery omit owned rows. Legacy writes and Run admission reject an owned Session or fabricated new unscoped Session for an owned Instance. Session-to-Instance identity is immutable in both stores and in the SQLite backing key. No legacy owner capability can authenticate canonical Session routes or read the new Session through old host/v1 routes. The ownership marker is not an alternate authorization path.
