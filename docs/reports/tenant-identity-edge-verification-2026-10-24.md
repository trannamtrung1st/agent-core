# Tenant identity, paging and approval-expiry qualification — 2026-10-24

This follows `c7049ecb` on the original IAM goal. It qualifies the remaining named Account/invitation and approval-expiry UI states, with real paged access data. The original goal remains active; this is not full proposal or milestone acceptance.

## Changes and exercised behavior

The existing Ant Design Approval detail now explicitly says **Request expired** and asks for a fresh action after the saved request becomes terminal. It retains the existing disabled/absent decision controls. Reopening an original invitation URL now handles same-document purpose-fragment navigation by reloading the page for a fresh read. That clears the old form/error, consumes the supplied proof through normal inspection and strips the fragment again. There is no automatic mutation replay. No permission, default, wire shape, store, schema, migration, visual token, font or CSS rule changes.

A dedicated focused runner bootstraps a fresh private Synthetic SQLite host, pins MessagePack, prevents server reuse and keeps all files/keys/captures in a marked temporary root. It builds the API serially, performs the existing bootstrap command, then starts the existing host. Expiry preparation is test-only: the helper requires its temporary prefix/real path/marker, rejects linked database files, binds exact tenant/request IDs and changes only invitation/request expiry timestamps (and the matching request JSON field) in one transaction. It adds no public debug endpoint or production expiry setting. Native tests separately use the actual application clock and normal HTTP services in both stores.

Three complete browser journeys exercise:

1. Create a real Account through a valid invitation, remove that initial membership, sign in and inspect the no-organization state. Join two different organizations as that existing Account through visible invitation forms; sign out/in, retain both memberships and verify distinct tenant principals without creation/invite controls. Invalid, revoked and actually expired links withhold the join form, preserve recovery and keep purpose credentials out of request URLs. No uninvited signup feature is introduced.
2. Create twelve matching organizations, 120 custom roles and 21 invited registered members through real public APIs. Search/paging totals and page reset are checked in the actual organization, role and member screens; the member total is 22 including Owner. Inspect the deep role result, close by Escape and verify focus returns to its opener. Search from later pages, verify exact late member and empty result recovery. This is representative pagination evidence, not an unbounded-load benchmark.
3. Prepare an actual model `settings.patch` Review in Chat, shorten only its fixture expiry, and let normal Core processing expire it. A different qualified reviewer sees disabled decisions, terminal recovery and no decision POST. A direct old decision returns 409; the Instance stays at revision 1. A new human message creates a different root/request; visible approval then applies the exact instructions once and advances the Instance to revision 2.

Each relevant state is captured/asserted at 320, 390, 768, 1024 and 1440px. Browser errors must remain empty. The expiry flow verifies the actual saved result separately from its human decision.
