## Implemented behavior

`SystemAdministrationService` and `ISystemAdministrationStore` provide metadata-only Account/organization catalogues, original-human organization creation, Account status and organization Active/Suspended status. System permissions are independent of tenant membership and governance. Catalogues filter before count/page, order CreatedAt/ID, bound page size to100 and repeat the original live login/permission after I/O. Public Account rows omit password hashes, login stamps and sessions; organization rows omit member/role/private resource graphs. Literal trimmed search is explicitly case-sensitive.

The existing creation/status routes now use the new original-human service, with strict command bodies. Status commands capture an opaque purpose-bound SHA256 Account version or tenant revision. Both actual adapters repeat original Account/session/stamp/global Principal and raw exact System permission inside their atomic commit. Account status preserves password/login/profile fields, rotates the security stamp and retains independent last-tenant-Owner protection. A final active Account backing the built-in Platform Operator role cannot be suspended/removed, including after all tenant ownership transfers. Refusal changes no stamp/status/audit. Tenant status preserves ownership/resources and advances only status/revision with body-free audit; it does not delete tenants. Creation gives only the original Account the new Owner graph.

Membership middleware previously interpreted any `tenantId` route parameter as a tenant request. The new System status integration exposed that suspension prevented System reactivation. Restricting membership resolution to `/api/v2/tenants` preserves independent System metadata/status authority without granting private tenant access.

The native operator UI adds independently gated Platform Organizations/Accounts routes and uses the shared Admin shell, bounded filters, native Table/Drawer/Descriptions, existing CreateOrganization, centered confirmation and draft guard. Inspect exact identity/current status; review before/after and consequence before one captured write. Stale/unknown outcomes require explicit readback, retain the chosen status and never replay. Matching current facts disable unnecessary resubmission. Read denial removes private metadata/actions. The final operator refusal has explicit factual copy. No CSS, token, font, asset, new kit or replacement design world is added in this module.
