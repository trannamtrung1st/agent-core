## Ownership and fixes

Existing Activation evidence freezes `inputBehavior`, `interruptedRunId` and `interruptedRunRevision`; no schema migration/table is added. Both stores atomically preserve the captured interrupted prefix, cancel the exact source, settle its completion accounting, revoke an available source grant, bind selected originals, create the new user entry/Activation/Run and append admission/cancellation audits with one security revision. The actual transaction clock is used for cancellation: the rounded prepared user-entry time could otherwise precede a precise Run timestamp. The atomic result carries its exact cancelled source, avoiding a postcommit authority reload.

The mailbox holds current normalized model/brain callbacks while the exact interruption write is pending. Existing producer acknowledgements supply bounded backpressure. Persistence completion remains processable; refusal drains held output and success discards it after supersession. Shutdown releases held acknowledgements. Once enqueued, input completion and old-generation retirement are supervised independently of the caller's HTTP/Hub cancellation. This closes the precommit-prefix race and the disconnected-caller retirement gap without another writer or queue.

The browser captures the current Run before preparing witnesses and cannot retarget an uncertain delivery. Core rechecks independent Run read/cancel authority; an action-specific refusal does not revoke Chat. Selected files and queued text remain local until accepted. A pre-dispatch preparation failure now restores a cleared draft. Shared narrow row CSS supplies 44px minimum Steer/Remove hits with the existing 8px gap.
