## Implemented boundary

The existing native provider has one immutable tenant/Instance/executor/Session binding, a matching internal command witness, tenant/Instance profile directories and guarded technical release. Binding and unscoped command reservation share a lock. A prior unscoped namespace cannot be promoted; an established tenant namespace rejects unscoped bind/command, state, reset, protected fill, unattended use and release. Existing context, page, proxy, profile, target and isolation owners are reused. Release retains trusted binding/isolation while closing its owned view. Existing exclusive profile locks and native close behavior remain in place. Linked tenant profile path components are refused.

`TenantBrowserStateService` derives the actual owner from the canonical Session store. Original-login membership, exact Session read and agent Browser read are independent from administrative agent read/Chat/use/manage. Post-I/O original-human/Account/security and Session checks discard captured detail after change. The new private/no-store GET returns existing handle counts, availability/sharing and safe timestamps/codes only. It never binds, launches, reads profile bytes or inspects page content. A ready unbound provider reports zero handles and unknown sharing; unavailable/unsupported sources use null counts. There is no unscoped state fallback, public command DTO or POST action.
