## Ownership and persistence

`ITenantAutomationStore` is a facet of the incumbent IAM and trigger backing stores. Human read/write and original-session checks, registration/Instance/security CAS, current executor permissions and exact graph validation precede the existing atomic occurrence/Session/Run transaction. The hosted scheduler adds a bounded canonical phase and retains existing phase isolation. Its stable ID cursor prevents a blocked prefix from permanently hiding later due registrations. Non-executing expiry/completion advances only exact registration state. Configuration adoption reads bounded future owned registrations; decommission counts retained canonical references.

`20261020180000_TenantAutonomousAutomation` tags the existing tables, replaces the Session creator FK with Principal identity, and adds five strict owner/source guards. Tenant ownership uses the actual same-tenant SystemIdentity; legacy rows retain their profile variant. Existing approval/receipt and attachment guards are frozen and restored around SQLite table rebuilds. Accepted occurrence facts are immutable. Downgrade rejects canonical data before changing the schema; legacy-only down/up remains supported. Old migrations are unchanged.

Runtime preparation permits attachment-free owned schedule/manual context. It grants no attachment tool access. Protected/native tool contracts for autonomous roots remain unconverted. The actual tenant worker and Session mailbox produce the outcome; no new scheduler, executor, queue, grant owner or fake human is added. Synthetic adapters require no credentials and make no provider network calls.
