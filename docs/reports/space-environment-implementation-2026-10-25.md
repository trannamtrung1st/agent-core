## Workspace cutover implementation notes

The existing `IAgentInstanceWorkspaceStore` has no active product consumers beyond DI and decommission cleanup; its unqualified file methods are executable legacy ownership paths and must be removed. Reuse its canonical filesystem primitives through the tenant read/mutation/source facets and the existing cleanup facet. Do not retain a second Instance-home adapter for test convenience. The class/type name may change with this cutover; Instance Resource storage remains separate and is not renamed to Space.

Use one closed tenant-qualified owner union for `SpaceHome(tenant, space, Home/Private alias)` and `SessionWorking(tenant, session)`, with no nullable ID combinations or caller-supplied physical roots. Put the reusable owner value in Domain so filesystem metadata can report its actual Space/Session owner without mislabeling a Shared Space as an `AgentInstanceId`. `/private` resolves only through the current Run's validated own-Private-Space capture. Aliases share the same physical Space root, IAM home scope and quota accounting. Home roots become tenant/Space directories; working roots retain server-resolved Instance/Session ownership. Human home services resolve Space directly and do not require an arbitrary member agent for Shared Space access. Private ownership/retirement and working Session lifecycle still constrain writes.

Cut over route, scope ownership checks, source/read witnesses, approvals/effects, composer references, Office/artifact/download consumers and sandbox mount authority together. Mounts must intersect actual workspace IAM and HomeAccess, carry active/private owner identity, and retire before a switched Run can execute. Update descriptive access DTOs/UI to Space revision/name rather than retaining a false Instance owner. The old `/agents/{id}/workspace` route must return 404. Existing filesystem link/root protections remain the common primitive.
