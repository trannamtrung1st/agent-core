This pass implements usable foundation screens against the real canonical APIs and applies the existing Ant Design v6 dark presentation. ## Delivered surfaces and ownership

`/sign-in`, invitation acceptance, `/account/organizations`, `/account/profile`, and `/t/{tenantId}/admin/{access,members,roles,audit}` are implemented. Members includes invitation status/revocation; role authoring separates catalog permissions from assignment. Platform-authorized users can create an organization. Reader controls are read-only. Password change reauthenticates and signs out previous sessions. Organization switching opens the shared searchable/paged organization list and replaces the document, closing previous browser connections and transient UI state.

`AdminShell` now accepts a focused context for the same header, breadcrumbs, page heading, sidebar and responsive navigation drawer; current Chat/Admin consumers retain their existing defaults. The existing collection toolbar, native AntD controls, `confirmAction`, form validation feedback, 8/12/16 spacing, root token bridge and dark palette are reused. The shared toolbar can omit horizontal-table guidance for collections that do not scroll. No second UI kit or replacement theme was introduced.

The identity service keeps CSRF only in memory and authentication in same-origin HttpOnly cookies. Scoped query hooks abort stale requests and discard previous-key data synchronously. Current effective permissions are fetched for each tenant destination. The API adds safe current-permission projections, authorized server-side organization/member search and a bounded invitation listing without tokens/hashes. A global Principal reference alone never enables platform controls. Existing unscoped Chat/resources/Hub and durable approvals remain separate pending work and are not linked as completed tenant features.

The Impeccable context and incumbent Admin brief were read; the polish and craft-floor playbooks were applied. One initial desktop/mobile audit was batched with real interactions, followed by grouped corrections and final confirmation. Functional failures found by required verification were fixed and rechecked; no new visual direction or cosmetic redesign was introduced.

- Before: a 736px drawer clipped its left side on 320/390px screens. After: the shared access drawer wrapper caps at `100vw`, keeps its own scrolling and reachable footer. Native resize transitions are awaited by observable bounds rather than wall-clock sleeps.
- Before: organization rows inherited an irrelevant table-scroll hint. After: the shared toolbar has an explicit no-hint mode for these non-scrolling collections.
- Before: singular counts, generic repeated permission labels and last-Owner Reload advice were misleading. After: correct singular/plural copy, contextual accessible permission names and denial-specific recovery.
- Before: nested Escape could create competing dirty-form confirmations, and conditional role-drawer unmount could lose focus. After: one pending confirmation owns Escape until its native close completes; role editors restore their surviving trigger or page heading. Keep editing preserves the complete draft.
- Outer mobile text/password/search controls are 40px; inner inputs in affix wrappers retain native sizing so their height is not added twice. Role Save/Cancel remain reachable inside the drawer footer.
