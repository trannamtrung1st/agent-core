# Tenant Browser direct read verification — 2026-10-18

The full proposal remains active. Converted Browser reads now use current Allowed policy through the tenant tool boundary; policy-required reads retain exact durable Review. Browser host-recreation qualification, protected resources and the wider proposal remain open.

## Implemented boundary

- `TenantBrowserInspectionContract` supplies one closed typed read classifier shared by preparation and native dispatch. Eligible direct reads are observation/find/wait, bounded console/network/rule inspection, verification/locator/configuration, Tabs list and Dialog inspect. Tenant schemas restrict Tabs/Dialog to their read operations. Navigation, closure, storage operations requiring Browser use and unconverted resources remain outside this lane. Extra identity/mutation arguments fail before provider access.
- `TenantBrowserReadService` derives actual Run/Session/Instance/executor, checks current original-requester authority, raw independent `sessions.read` and exact agent `browser.read`, admitted/current capabilities and both current read policies before binding/target work. Browser use, ExceptionalGrant and an effect receipt are unnecessary. Missing scope does not become an exceptional read grant.
- Current source, claim, permissions and policy repeat under incumbent native gates and after I/O. Nonserialized `TenantReadOnly` independently rejects a mutation before consuming its physical witness. Safe cold binding is metadata-only; existing handles are read without provisioning, navigation, closure or isolation transition. Claim, admitted per-tool and remaining overall deadlines bound the call. Caller/Run cancellation and late noncooperative results produce no observation delivery.
- Results preserve native semantic/configuration shape, bounded untrusted content and false effect/business-success flags, with exact typed read provenance. The existing mailbox checkpoint owns delivery; a read does not start or clear a durable external-effect fence. Snapshot/discovery compaction preserves provenance on bounded historical excerpts. All retained direct read data is checked against current scope and Allowed policy before later model generation without native I/O. Tiny output budgets retain valid JSON and omit protected partial data.
- `browser_read_review_required` refuses direct dispatch before any binding/target observation and directs the same exact command to the existing `approvals.request_authorization` tool. Review grants one observation; subsequent direct reads still require fresh policy. The shared zero-argument normalizer applies to direct inspection and stored provenance, accepting blank payloads only for the existing zero-property schemas and preserving explicit invalid values. The code’s tool name was already correct; three documentation references incorrectly said `iam.request_authorization` and are now corrected.

## Observed flows

Ten hosted cases used actual Synthetic model execution, both stores and disposable headless Chromium. Cold `browser.get_config` ran under only agent Browser read plus independent Session read and created no context. Two warm `browser.snapshot` reads used a trusted disposable fixture view, retained native-shaped data in the resumed model request and left the Run with no effect fence or approval. The first observation compacted into a bounded excerpt with its read marker/hash intact. Trusted native navigation only prepared the warm fixture; it was not model mutation authority or a reviewed effect.

With Browser-read policy Always, the actual model’s direct read was refused with the named Review reason and no native command consumption. The same model proposed exact `run_browser_command`, durably suspended, received an authenticated HTTP approval, resumed in the existing successor Run and received one saved observation. The cold configuration path still allocated no context and created no grant. Current-policy direct reads and reviewed output therefore use their separate existing owners.

Both-store boundary fixtures demonstrated independent Session scope, foreign tenant/Session and stale generation refusal before provider access. Either Browser or Session read policy could require Review before even binding/target observation. Canonical preparation then produced a read-only Browser Review without native work/grants. Revocation at the native gate prevented the read; revocation after I/O withheld output and recorded a denial. Caller cancellation discarded a late noncooperative observation. Run cancellation during I/O likewise withheld data and preserved the cancellation with no effect fence.

Actual Core read results were persisted and compacted before later-generation checks. Revoked read scope or newly required Review blocked their retained content without another provider call. Mutation/identity/unconverted inputs were rejected with zero binding/provider calls. A 64-byte output budget returned valid `output_limit` JSON without a partial page excerpt. Actual Tabs list returned its native semantic tab records. Pending Dialog inspect retained redacted Confirm metadata without resolving the modal; trusted fixture code triggered and later dismissed it separately. Both positive read-only forms worked without a registration change. Actual native guard assertions rejected Browser close through `TenantReadOnly` without executing its callback, closing the context or consuming the original physical target. Existing reviewed command, target, credential continuation and legacy snapshot/compaction behavior remained covered.
