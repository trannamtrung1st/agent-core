## Corrections

- Upload metadata sends the parsed base media type. Receipt verification compares MIME media types without case or transport parameters, while preserving the original immutable effect hash/snapshot and requiring exact ID/name/size/MD5/destination checks. Invalid or Google-native media types reject before dispatch; no native conversion is introduced.
- A completed resumable transfer clears its protected session with CAS. Metadata reconciliation remains required; clearing continuation authority never releases an uncertain pending-effect claim by itself. Successful receipts also clear session authority.
- A known upload target verified in Trash becomes terminal Failed with current same-ID safe metadata and `verified_target_trashed` proof. Both stores require that evidence and cleared session authority. Its pending claim is released; its old operation ID cannot run again. The message correctly explains that no active uploaded target remains, rather than claiming the original request never executed. Only an explicit new upload may create a fresh ID; there is no automatic restore or replacement.
- Genuine verification failures retain uncertainty and report operation/file IDs, causeCode, bounded verificationFailures and recoveryAction through both conversational tools and HTTP inspection. A completed checksum-bearing mismatch does not offer content continuation. Missing files, expired sessions, unavailable authorization and unknown transport completion still do not authorize another create.
- Cleanup of an active mismatched target uses the existing inspected exact Trash approval. No automatic deletion, permanent deletion, broad scan, cleanup endpoint or rollback is added. A cleanup request without approval is denied; an approved exact cleanup can be verified, close the original unavailable-target receipt and permit a fresh explicitly requested upload.
