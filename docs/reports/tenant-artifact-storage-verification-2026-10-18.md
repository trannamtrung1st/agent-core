# Tenant Artifact storage and human delivery — 2026-10-18

This prerequisite advances the full [IAM proposal delivery](multitenant-iam-delivery-2026-10-16.md). It adds actual tenant Session/Run-owned immutable Artifact storage and independently authorized human reads over the existing Artifact adapters. It does not complete the Artifact family or full proposal.

## Implemented boundary

`ITenantArtifactStore` is the owned port on the existing InMemory/SQLite Artifact stores. Trusted publication requires the actual owned Session, producing Run and current uncancelled claim/generation/lease. The input is copied before hashing/publication; default limits remain 50 MiB/item and 250 MiB/Session. A stable Artifact ID returns the original immutable record for identical source/metadata/bytes, while changed publication facts conflict. Invalid content types are rejected before storage. This port supplies storage ownership only; it cannot grant IAM permission, approve an operation or establish an external-effect receipt. No model publisher or HTTP creation endpoint is enabled.

Owned rows use the existing Artifact metadata and blobs. SQLite migration `20261018140554_TenantArtifactOwnership` adds the tenant marker, actual composite Session FK, paging index, owned shape constraint and conditional actual-Run/immutability triggers. The migration explicitly rebuilds before creating triggers: the initial generated constraint rebuild was observed dropping early-created triggers and was corrected. Downgrade refuses to remove ownership while owned rows exist. Historical unowned rows are neither adopted nor relocated. Actual ownership queries join the retained Session/Run source; legacy store read/create/delete methods exclude owned Sessions, including retained deletion ownership.

`TenantArtifactService` requires the original live human login and current membership, independent Session and Artifact read scopes, and separate Run-read authority when filtering by Run. Artifact-specific assignments filter before cursor validation and limit+1 paging; hidden rows expose neither lookahead nor valid cursors. Download reads bound and verify the complete buffer, re-read the immutable source and recheck original identity/security/Session witnesses before return. SQLite paths derive exclusively from IDs beneath the configured private root and reject symlink components, size/hash drift and unavailable bytes.

The canonical [HTTP contract](../14-api-and-realtime-protocol.md#tenant-artifact-http-reads) provides collection, safe metadata and attachment content GETs under the actual tenant Session. Metadata excludes physical paths and unconverted provenance; downloads force sanitized attachment filenames, nosniff and canonical no-store. There is no owner-token fallback.

## Observed workflows

The first representative InMemory case claimed an actual tenant Run, published a private Artifact, read its metadata/list/exact bytes as the owner, denied forged generation and legacy access, granted an exact Artifact role to a Session reader, then revoked it and denied delivery. The equivalent disposable SQLite workflow passed after migration.

Both-store authenticated HTTP workflows created an Agent and Session, admitted a message through the canonical HTTP route, claimed its actual Run and published bytes through trusted fixture setup. The production tenant executor was deliberately held so fixture claim ownership was deterministic; no model-generated publication is claimed. Owner GETs returned one safe metadata item and exact HTML bytes as a download, with sanitized attachment filename, checksum, nosniff and no-store. Invalid bounds, wrong Session/tenant, anonymous/owner-header access and missing Artifact read were rejected. A member with only Session read received an empty collection and denied content; an exact Artifact assignment enabled download; revocation denied it again. Both fixtures recorded zero outbound provider HTTP. The SQLite fixture explicitly pairs its late-replaced database services with the SQLite Artifact adapter; the initial mixed-store fixture failed closed and was corrected.

Store/service cases exercise exact scope filtering before cursor validation, lookahead, independent Run filtering, missing Session read, invalid MIME, changed retry bytes, caller byte-array mutation and cancellation of the producing Run. Read hooks remove original login (then create a new login), revoke the current assignment, cancel the request or logically delete the source after bytes are read. Every case withholds the buffer. The deletion scenario first commits Run cancellation through the existing runtime, because deleting a Session with a live Run is correctly rejected as `session_in_use`.

SQLite-specific cases reopen the existing store and recover exact metadata/bytes, reject all owned-row mutation including marker stripping and forged Run insertion, reject ownership-removing downgrade, same-size content tampering and a symlink even when its target contains matching bytes. A disposable prior-schema row with historical arbitrary Run provenance survives upgrade with null tenant and identical bytes, without adoption. Model snapshots report no pending changes. Quota checks cover same-ID retry, item/Session limits, canceled publication leaving no extra row and two competing publications within the Session limit.
