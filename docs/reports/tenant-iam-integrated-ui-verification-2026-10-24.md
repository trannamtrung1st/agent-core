# Tenant IAM integrated UI and realtime verification — 2026-10-24

This checkpoint qualifies a large integrated Account/tenant/Chat/management/approval slice against disposable Synthetic SQLite. The original proposal remains active. This is not full proposal or milestone acceptance.

## Changes

- Restored rich Composer references remain tenant-owned and permission-checked; current frontend wording no longer incorrectly treats them as retired. Contenteditable assertions use rendered text.
- Attachment-only input omits empty optional structured parts, preserving the existing file-only wire contract. A browser case sends a real uploaded file without text, reloads, opens the retained original and checks its original text.
- A retiring response terminal event no longer releases the admission hold for an accepted replacement before its response-start event. The deterministic regression failed before the fix.
- Explicit socket recovery and its intentional-stop close callback share one recovery owner. A deterministic regression previously observed two stops; the corrected path retains definitively refused queued input and sends no automatic replay. The browser Steer journey recognizes only the two explicit stale-revision/interruption refusal messages, verifies retained input, then makes at most one deliberate fresh attempt.
- Recipient authorization rebuilds the complete current human/IAM/Session witness up to three times for `stale_revision`. Real permission removal and logout deny immediately; sustained churn remains bounded and fails closed. Eight deterministic variants cover both stores, including permission change, revocation, logout and continuous churn. No operation or output is retried by that authorization read.
- A rendered receipt can arrive after the durable Run terminal commit while its Runtime is publishing the terminal event. The host now lets that same owned Completed attempt drain naturally before quiescent receipts or next admission. Failed, Cancelled and stale/replaced attempts retain existing cancellation. A gated native MessagePack regression reproduced failure on both stores before the fix; it checks final publication, durable receipt credit and the next response on the same attachment.
- Four new UI cases use genuinely different requesting/reviewing humans, Review/ExceptionalGrant and approve/reject after requester logout. They inspect the saved literal action, decision attribution, exact applied/withheld configuration, unchanged executor IAM and terminal reload state. Login fixture retries are bounded to explicit 429 responses; protected commands are never retried.

## Verification environment and evidence boundaries

The owned API/Web ports are 5093/5183. Synthetic uses no provider credentials, Browser or Sandbox service. A private SQLite database and all file/key roots live under the disposable fixture directory. Existing user data and the Real-profile host were preserved. No CI, live OAuth/provider call, deployment, push or PR was requested or performed.

The manually started predecessor Vite inherited the local JSON transport setting. Those browser results are explicitly JSON evidence. The final affected Chat and independent-approval checks select MessagePack explicitly, and the committed tenant runner now pins MessagePack. Native API tests independently use the real SignalR MessagePack client.

Node 26 exposes native Web Storage incompatible with the current jsdom fixture. The focused frontend suite uses `NODE_OPTIONS=--no-experimental-webstorage`; no package or product setting was changed. Existing React act notices and Vite chunk-size warnings remain.
