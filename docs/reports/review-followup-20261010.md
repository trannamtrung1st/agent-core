## Changes

- Compose creates canonical child `triggers` with explicit stable ID, enablement and revision. Reopen compares every durable child field; current eligibility is separately asserted because it is a read projection absent from creation responses.
- Admin lifecycle SQLite seeds parent `TriggerMode` and a separate Schedule child, atomically, without restoring retired columns or API fallback.
- Schedule saving is independent of Event catalog errors. Structurally valid disabled Event drafts retain known source identities despite catalog or collection failures. Activation requires a successful current authorization read and validation of the source catalog branches actually used; blocked activation can save disabled.
- Privacy reads distinguish a pending revision from deployment-constrained mode/origin sets. Equal revisions can be constrained. Admin labels the condition and explains that restarting alone cannot remove deployment restrictions. Startup still pins one immutable effective policy.
- New SQLite/API regression switches a persisted Schedule to two Events, reopens, switches back, and reopens again. It checks stable parent identity, retained timing, replacement child identities and no orphan rows.
- The P7.6 acceptance fixture now checks editable Browser privacy and retains read-only assertions for every other Effective configuration section. Its old blanket assertion was incompatible with the privacy feature.
