## Implemented boundary

`ITenantRunProfileStore` is a trusted-Run facet of the incumbent IAM/Profile owners, implemented by both stores. It reads the actual retained UserMessage root and current tenant User/Principal/Account. It never impersonates a human login, selects a global Profile ID, treats Session creator as every requester or adopts an independent Automation creator's Profile. Human-root background descendants retain the same source. Independent manual and scheduled Automation do not acquire one, even with raw executor read grants.

Projection requires the current live Run/generation, active identities/executor, current executor reads of the source/current Sessions, original requester Session-read/Agent-chat authority, raw executor `memory.read` and current operation policy. Passive recall withholds unavailable or Review-required values without creating or consuming consent. Admitted and live ProfileEvidence policy intersect; later broadening cannot restore an admitted exclusion. Explicit human “friend” remains valid preference data. Profile evidence changes neither SpeechLocale nor model selection.

Canonical Runtime previously discarded the current Definition after using it as a Boolean authority check, then invoked a legacy restriction path without canonical configuration owners. Projection now uses the actual current Definition and admitted restrictions. Before each model dispatch it refreshes continuity restrictions and replaces the optional Profile Evidence section from the trusted source. Mandatory requester/authority facts remain separate. One current trusted Runtime fact section replaces its predecessor; historical tool Evidence remains in the interaction. Runtime observation repeats a metadata-conflicted authorized read once, then withholds unavailable observations.

The existing Run checkpoint receives a bounded `TenantProfileSource` witness before provider dispatch: actual tenant/User/Account, Profile revision and UTC millisecond time. The witness contains no preference values, login or copied grants. Both stores refuse dropping/substituting an already used source and revalidate current identity/read authority and exact source version at the owning checkpoint, new response persistence and final-outcome gates. Application provider/effect authority, factual report source inspection/Review/settlement and text/audio/resync transport repeat relevant checks. A changed source during generation refuses newly protected output. No new execution owner, HTTP route, wire DTO, schema migration or global Profile adapter is introduced.

Disabling Profile evidence removes new Profile projection without rewriting stored preferences. An already used witness remains subject to current raw read/policy and exact-version checks; projection exclusion itself does not erase historical model/tool data. Conversation readers retain the proposal's Session-authorized free-text history semantics and residual disclosure risk. This implementation does not introduce a universal free-text filter. Raw Profile self-service remains private to its actual User.
