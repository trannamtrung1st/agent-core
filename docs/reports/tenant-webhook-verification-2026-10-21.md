## Implemented boundary

Human management uses the authenticated original Account/session/tenant User, current independent scoped read/manage, exact source/security revisions and one management audit in the owning transaction. Source commands derive the current tenant revision themselves and cannot rewrite a caller-supplied IAM child graph. Identity, creator, event key and creation time remain immutable. Event keys are unique per tenant. The existing scoped assignment owner validates actual source ownership.

Create/rotation returns a new token once; GET/list/receipt/audit do not return token or hash. Only SHA-256 hashes persist. Rotation invalidates the old token; revocation clears its hash and retains receipts. Explicitly issuing a new token for a revoked source reactivates it. The UI names that consequence before confirmation. Tokens are source credentials, not Users, SystemIdentities, signatures over payloads or delegations.

Anonymous-capable `/api/v2/hooks/{tenantId}/{sourceId}` stays separate from human cookie/CSRF routes. HTTPS or the explicit trusted-loopback development exception is required. Authenticate before bounded body parsing, then repeat active tenant/source/revision/token atomically with exact dedupe. Duplicate normalized evidence returns the original fact; changed evidence conflicts. Nested external data is literal, bounded untrusted evidence; top-level identity/root/target injection is refused. The store stamps actual admission time and records authenticated source revision without inventing a human/Agent actor.

Both stores use the incumbent backing data. Old unscoped APIs hide tenant rows and reject tenant admission/fanout. SQLite migration `20261021020000_TenantWebhookOwnership` installs eight source/receipt/delivery guards after both table rebuilds, retains the previous 46 security guards, preserves legacy-only row values through a disposable roundtrip and refuses downgrade with retained tenant data. This guarded interim state does not satisfy the final clean cutover mandate.
