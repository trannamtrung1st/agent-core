# Built-in General Assistant design brief

Source audit: clean `main` at `25db1f9755b56ebd745efcc7090ea1d4db6435ac`. The accepted local proposal supplies the feature contract. This brief precedes implementation; execution evidence belongs to the delivery ledger.

- **Job and direction (Operate):** owners and authorized members start an ordinary conversation without creating an Instance. Reuse Chat's existing picker and composer, the Access Agent table, detail sections, guarded commands and native confirmations. Ant Design v6 and `.agents/context/DESIGN.md` remain the visual authority.
- **Chat:** recommend the visible, authorized managed General Assistant first. Mark it `System-managed`; retain deliberate selection of other eligible agents. Filter visibility and authorization before search/count/paging. Hiding affects new selection only. Distinguish lack of Chat access, no visible agents, pending setup and unavailable models without exposing hidden names. Existing conversations retain their normal transport and history.
- **Management:** show `System-managed` on the row and heading, `Visible in Chat` in settings with “Only controls new-chat selection; does not stop this agent or existing conversations.” Hidden agents remain manageable. Reset uses `Reset to System Defaults` and a native keyboard-accessible confirmation identifying the current organization and agent. Explain retained conversations, memory, files, credentials and local Skills/resources. Lifecycle and Versions explain system ownership instead of suggesting missing IAM.
- **Interaction:** reuse shared section/header spacing (8/12/16 tokens), AccessFeedback and tenant command/readback handling. Preserve denied/revoked, stale, unknown, busy and draft states. Confirm and restore focus. Verify 320/390/768/1024/1440 widths, labels, wrapping, keyboard controls and useful empty/recovery states.
- **Ownership:** add the managed marker to SystemIdentity with a filtered tenant-unique index; add universal Instance visibility and group-level persona provenance. A dedicated trusted store entry point creates only this built-in, its ordinary executor/private Space and minimal scoped starter grants in the incumbent transaction. No human impersonation. Automatic adoption and configuration reset reuse the same Instance CAS transaction, compatibility and Automation planning. Incompatible release configuration blocks new admission; admitted Runs keep their pins. Reset preserves visibility, IAM and user data and has durable operation readback.

Starter permissions are explicit: model/public research and Session/file/artifact operations needed for ordinary work; private Instance/Space access stays exact-scoped. No management role, credential/Secret, sensitive Browser/Sandbox or cooperation grant is installed implicitly. Tenant owners can add explicit grants through existing Access controls.
