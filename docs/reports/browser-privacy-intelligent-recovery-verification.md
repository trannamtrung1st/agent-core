## Policy and lifecycle decisions

SQLite saves global privacy policy and sanitized Admin audit in one transaction with revision CAS. Protected is the default. Unmasked requires owner acknowledgement on every save, a nonempty exact-origin subset, and explicit deployment allowance. It exposes main-document form and graphics pixels only at approved origins. Other origins use Protected. **Child frames remain wholly masked**, including same-origin, permitted cross-origin and denied frames. If their embedding element is inside a closed shadow root, the SDK locator mask cannot reach it: capture fails closed with `target_denied` and no bytes. Legacy `frame` elements join `iframe` masks. Semantic observations remain independently redacted.

Disabled prohibits capture and removes screenshot/mouse discovery and proactive visual guidance while preserving semantic tools. Deployment Disabled overrides Admin; otherwise Admin exceptions stay beneath `AllowUnmaskedCaptures`, `UnmaskedCaptureOrigins` and `TrustedVisualCaptureOrigins` ceilings. Legacy `DomMasking` is a Protected alias. No navigation, interaction, credential, approval, owner or artifact permission is expanded.

Activation deliberately follows **full host restart**, matching immutable native host configuration. Saving Disabled does not immediately revoke the running effective revision. Admin shows saved/effective revisions and restart requirements. Native capture and artifact publication share host-retirement cancellation; coherent in-flight captures cannot mix revisions. Uncommitted artifact writes are canceled; already committed Session artifacts remain under their existing lifecycle, and restored images confer no native coordinate authority. InMemory persistence is explicitly disclosed as ephemeral and cannot preserve a save across full host restart; SQLite is required for durable activation.

Recovery stays advisory. Two semantic misses produce a short strategy-change hint conditional on model vision, real eligible/projected tools, host privacy and remaining capture allowance. An eligible unloaded screenshot capability uses existing `capabilities.load`; unavailable tools are not invented. No auto-capture, action replay, forced logout or forced close is introduced. Explicit logout and close remain independent; failed logout should not suppress an independently requested permitted close, while conditional closure, negation, preservation, cancellation and expiry remain authoritative. Native closure is not authentication proof.
