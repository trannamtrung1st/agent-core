# Frontend Implementation Specification

## Admin capability access and projection

Editable Ant Design draft Capabilities use canonical Selected capabilities and All current capabilities. On entering Form with a trusted catalog, legacy tool allowlists become Selected exact grants with their existing discoverable projection; immutable published versions retain their previous semantics. Selected uses grouped exact-name choices. All displays an informational count and explains that publication pins the current catalog without granting future registrations. Always available uses the same trusted catalog category ordering, search and availability labels as Authorized capabilities. It contains only authorized discoverable choices, disables newly unavailable choices, retains previously configured unavailable selections, and automatically removes projection selections when authority is removed. Core context-only capabilities stay independent. Capability status distinguishes unavailable configuration from authority. Derived on-demand/context information is read-only; there is no loadable permission editor.

Counts are informational and have no 32-option disable/save behavior. Catalog failure retains the existing retry notice and blocks Form saving. Advanced JSON and Form round-trip both new policy fields; diff review includes authorization mode, exact grants and always projection. Existing form-section spacing, responsive tags and Ant Design defaults own layout; no extra UI kit or page-specific styling is introduced.


## Workspace refinement authoring and inspection

Capability access, grouped catalog and always projection use the current authoring contract above. The historical workspace refinement used a 32-grant selector; the capability enhancement replaces that bound with informational counts.

Chat identities represent Agent Instances only (`managed:<instanceId>`); Chat boot does not fetch the Definition catalog. Empty inventory disables identity selection and Send, and directs the owner to create an Agent Instance in Admin. The owner Workspace tab uses `Agent Workspace`, `/home` and `Durable across sessions`, lists folders, permits file downloads and disables directory downloads. Existing responsive Ant Design components own the layout.


## Baseline and modules

React SPA, Vite, pnpm, strict TypeScript, Zustand, @microsoft/signalr, @microsoft/signalr-protocol-msgpack, browser fetch, Ant Design v6 (product components import AntD directly), and minimal app-specific CSS. Vitest and React Testing Library test behavior; Playwright tests synthetic end-to-end flows. No SSR, Next.js, heavy data cache, Ant Design Pro/ProComponents/X, or a second component/CSS framework.

Shipped web modules include `app` (routing/composition, `AppShell`, session path helpers, lightweight `/admin` routing via `AppRouter`/`appRoute`), `features/chat`, `features/admin` (owner-protected inventory, effective-configuration inspection, draft editing, Test & Publish, managed instance identity, memory and automation, deprecation, and version rollback), services (`api`, `realtime`, `attachments`, `catalog`, `audio`, `adminApi`), `speech` (client recognizer and synthesizer ports, Browser/fake adapters, client-transcript utterance accumulator and voice lifecycle, client-speech player with queue/ACK/cancel, voiceControlEnabled, and one speech-transport orchestration service), and `state/sessionStore`. Wire types are hand-maintained against [Protocol](14-api-and-realtime-protocol.md) with serialization fixtures; no generated types are created during this docs task. Browser services own long-lived connections/audio; React components subscribe, issue commands and render state. Native `SpeechRecognition` / `speechSynthesis` objects stay in speech adapters, never Zustand. Browser TTS voice fallback is voiceURI, then name, then language, then the browser default; do not write the transient voice list into agent definitions.

Future modules may add `features/voice` composition splits and `contracts` packaging without changing the routing model below.

Shared table presentation uses direct Ant Design small tables, `admin-collection-table` and feature-owned column/scroll widths. Prefer single-line summaries with explicit ellipsis and native full-text titles. Ordinary long values and links wrap inside their cells rather than overlap adjacent columns. Skills, Definition versions, Events, Credentials and Workspace use `admin-table-actions`: a non-wrapping, center-aligned Flex group with `paddingXS` gap and non-shrinking buttons/tags. Reserve enough action-column width and scroll locally on narrow screens. Form, drawer and expanded-detail action groups retain responsive wrapping; this policy does not impose a fixed row height. Compact Chat list/row menus omit unnecessary separators while retaining danger styling and confirmations.

Zustand contains session descriptor, attachmentId, connection state, input/output state, mode, pendingMode, `sttTransport` / `ttsTransport` from `session.ready`, entry map/order, liveResponseId, response terminal statuses, transcripts, mute and safe errors. PCM buffers, AudioContext, stream readers and HubConnection objects live in services, never reactive store state. Reducer guards attachmentId, responseId, event sequence and text offsets before appending output. A duplicate or overlapping delta may append only its matching suffix; a forward `textStart` gap triggers reattach for a fresh authoritative active prefix instead of silently freezing the row. Reattach also resumes display receipts for the active response. Discard superseded response chunks even when they arrive after R2 started. Keep tombstones for all responses in the attached session; bounded by the session entry limit, reset only after authoritative snapshot replacement.

## Primary screens

The UI derives one status label with [controller precedence](05-interaction-controller.md#state-representation) plus first-class progress: connection/error (Connecting, Ready, Reconnecting…, Connection failed…), pending Voice (Starting voice…), then first-class `activeProgress` from `agent.progress` (trusted `message` when present, otherwise Preparing response… / Reading attachments… / Running tools… / Waiting… / Finalizing response…), then user-speaking / agent-speaking, then coarse `session.state.changed.outputState` fallback (Thinking…, Generating response…, Reading attachments…, Running tools…, Interrupted), then Listening… when Voice is live. First-class `activeProgress` outranks user-speaking, agent-speaking, and coarse `outputState` when connection, error, and pending Voice are absent. Do not invent User speaking without `inputState=userSpeaking`. When `inputState=userSpeaking` but there is no live partial transcript and no live agent output, prefer **Listening…** so echo-only VAD after a typed turn or completed reply does not show a false **User speaking** row in the thread. Conversation activity is shown in the thread, not as a HUD of Tags. Connection failure uses an `Alert` with Retry; reconnecting is a quiet inline status. Ant Design owns the verified MVP generic UI system ([Technology Decisions](10-technology-decisions.md#decision-ant-design-v6-as-mvp-generic-ui-system)). ChatGPT is a layout/hierarchy reference only. [.agents/context/DESIGN.md](../.agents/context/DESIGN.md) provides only lightweight project UI guidance. If UI/design guidance conflicts with behavioral specifications in `/docs`, `/docs` wins. This document owns screens and behavior. `AppShell` wraps a session rail plus conversation. The rail lists durable sessions with catalog commands; it is not an inbox of bubbles. On viewports 768px and wider the rail is a persistent sider (240px between 768px and 1199px, 280px at 1200px and above). Below 768px the list opens from a Drawer. Product components import Ant Design primitives directly; `web/src/app.css` is limited to shell sizing, overflow, product layout, preview sizing, and accessibility.

Text chat: compact agent header, scrollable conversation (user messages as right-aligned bubbles; assistant messages as open sanitized Markdown), composer/send, voice-mode button (hidden or disabled when `voiceControlEnabled` is false: server `voiceAvailable` AND, when `stt.transport=clientTranscript`, local SpeechRecognition or a test fake AND, when `tts.transport=clientSpeech`, local speechSynthesis or a test fake), connection/error indicator. Historical MVP opened one conversation from identity pick with no list. The shipped post-MVP catalog rail lists durable sessions. New chat shows agent Identity and Speech locale in the empty conversation. Codex-like Model is one composer control that opens a Dropdown overlay (catalog with a Default mark on the system default). The overlay footer holds the effort slider. Visual inset (8px compact shell plus 8px control inner padding, matching session rows) follows [.agents/context/DESIGN.md](../.agents/context/DESIGN.md). The chip sits next to Attach/Voice and is the only Model control; paused and ended sessions never render a header Model (paused shows Resume in place of the composer, ended shows only the quiet ended note); the first send, attach, or Voice click creates the v2 session and pins the chosen agent version. Partial assistant text appears incrementally as Markdown; when a public persisted `speechText` meaningfully differs from display text, a compact secondary **Spoken** section appears first in that same assistant message (the TTS projection), then on-screen Markdown (not a second turn). Interrupted/failed entries retain a subtle status label; completed responses stopped for the configured output cap show **Output limit reached** when `finishReason=lengthLimit`. Drafts survive reconnect; submitting is disabled until ready. First-party Send submits immediately when no agent response is live. While a response is live, Send becomes **Queue**: the draft and ready attachments move into a client-side FIFO **pending-send queue** shown above the composer (not into chat history) until dispatched. **Steer** and **Remove** on each queued row (while a response is live) send that row's item with `user.text` `behavior=interrupt` without reordering the remaining queue. **Stop** sends `agent.response.cancel` for the rendered `responseId` only (`userStop` on the server), does not dequeue queued drafts, and must remain idempotent under races. When **`agent.response.completed`** arrives with status `completed`, the client dispatches exactly one FIFO head item using the normal non-interrupting send path. Failed completions (`status=failed`) do not auto-dequeue. Other `agent.response.interrupted` reasons do not auto-dequeue the client queue; explicit Stop (`userStop`) never dequeues. With queued work and no live response, Send dispatches the queue head even when the composer is empty. Queued drafts are not durable across refresh, new chat, or session switch; a transient WebSocket reconnect of the same session preserves the in-memory queue until attach fails. Wire `user.text` `behavior=queue|interrupt` remains for compatibility with external clients; the first-party web app does not use backend `queue` as its Codex-style mechanism. Enter sends/queues; Shift+Enter inserts a newline. Send, Steer, Stop, and Resume are keyboard-operable; focus returns to Message after Stop or a successful Resume. Speech finals from `client.speech.evidence` are user turns, not queued composer text. Empty conversation copy must not describe Browser STT as offline.

Voice call: agent name, single human-readable status (same precedence: connection/error, pending Voice, first-class `activeProgress`, then Listening… / User speaking / Thinking… / Speaking… / Interrupted / Reconnecting…), conversation history, Mute and End. Microphone remains active while the agent speaks when input is `serverAudio`. When input is `clientTranscript`, locally suspend Browser STT for agent output (see voice-preflight flow) and disable the composer **microphone** control until listening resumes; the Voice **mode** control stays available so leaving voice is not the same action as muting. No PCM is sent to backend STT during that hold. That does not mean the browser vendor keeps recognition on-device; Web Speech may use a cloud service. Browser TTS privacy is platform-dependent. Choose another configured STT/TTS adapter for backend-controlled or local speech. Keep the labeled composer available while voice is live. Keep the call layout simple, accessible buttons with labels, keyboard support and visible focus. Error text explains the next action. An optional developer-only panel shows event timeline, latencies, IDs, transcript evidence and controller decisions without dominating the call UI.

The voice-call control is a **mode transition on the same session**, not a new conversation. Follow [voice preflight](#voice-preflight). When a session already exists, preflight uses the Voice gesture immediately. When Voice is the first action on a new chat, create/attach first so `session.ready` can advertise transports; Browser/Browser then skips getUserMedia. The composer keeps Voice visible while mode is voice (`aria-pressed`); pressing it (or Cancel while Starting voice…) sends `session.mode.set(text)`, disposes prepared tracks/AudioContext/worklets, and returns to the same conversation's text composer. History, drafts and identity remain. Mute/Unmute is a separate microphone control and only affects input. After Voice is accepted, that attachment keeps Voice across mute, a typed send, a later `session.ready`, and a reconnect or sequence recovery; those do not send `session.mode.set(text)`. A genuine transport loss disarms microphone capture without changing Session mode. The microphone control then offers Resume microphone, which reauthorizes capture without `SetMode` when the server is already Voice. Ending the session or pressing Voice sends `session.mode.set(text)`. If voice is unavailable, show `VoiceUnavailable` and stay in text. Follow [mode-transition safety](05-interaction-controller.md#mode-transitions): the server may queue voice until a live text response ends; leaving voice while the agent is speaking supersedes that voice response.

## Voice preflight

User activation may expire before a queued `pendingMode=voice` wait finishes. When a session already exists, the Voice click prepares audio locally first. When Voice is the first action, create/attach first so preflight can use `session.ready` transports and skip getUserMedia for Browser/Browser; then ask the server to change mode, and only then send PCM.

```text
User clicks Voice
    ↓
if no session exists: create and attach a text session, then wait for session.ready transports
    ↓
local audio preflight using advertised transports
    ├── if stt.transport is clientTranscript: do not call getUserMedia for STT PCM
    ├── if tts.transport is serverAudio (including mixed clientTranscript+serverAudio): create/resume AudioContext and initialize playback worklets
    ├── if tts.transport is clientSpeech and stt.transport is serverAudio: request microphone and input worklets; do not load PCM playback worklets
    ├── if both transports are client-side: skip capture worklets; start the client recognizer/synthesizer adapters
    ├── if stt.transport is serverAudio: request microphone permission and input worklets
    └── DO NOT send PCM yet
    ↓
send session.mode.set(voice)
    ↓
if pending:
    show Starting voice…
    retain prepared audio resources
    offer Cancel (session.mode.set(text))
    ↓
server Mode becomes voice (streamId issued)
    ↓
if serverAudio STT: start sending microphone PCM
if clientTranscript: start ClientSpeechRecognizer and emit client.speech.evidence (partials ephemeral; one application final per utterance). Native `SpeechRecognition` `isFinal` chunks are application-stable pieces, not utterance boundaries; `onspeechstart` (or first result) opens the turn, `onspeechend` is pending until a trailing native final or a 300 ms grace heuristic closes it, and native `onend` flushes only when `speechend` is already pending. The BrowserSpeechRecognizer also closes an application utterance after about 1.8 s without a new transcript update (pause in recognized language) by emitting `ended` with `utteranceOpen` cleared so a later Chrome result can start a new utterance id, and discards noise-only turns after about 4 s with no recognized text through nonfatal `failed` evidence; `speechend` remains the fast path when Chrome provides it. Render `transcript.partial` as an ephemeral live user bubble; `transcript.final` (with entryId and entrySequence) becomes the durable user entry after SQLite save. `transcript.discarded` clears the live bubble without adding history. While Browser TTS is playing, locally suspend Browser STT from `agent.response.started` through response terminal and client playback completion without changing server mute or leaving voice mode, so speaker audio is not re-transcribed; resume with a fresh transcript epoch afterward. Mid-utterance native `onend` without `speechend` keeps the Agent Core utterance open and relies on accumulator `unexpectedRestart()` to freeze the spoken prefix and stitch overlap-aware continuation text across the native restart. Native `onend` is also recognition-session termination: restart immediately while no application utterance is open; during an open utterance use bounded restart/backoff plus a cap on consecutive service ends without speech progress (`SpeechRecognitionRestartLimit`); do not treat session `onend` alone as `ended`. Permission/device/service errors mark recognition inactive and surface the structured speech error.
    ↓
if serverAudio TTS: play AudioWorklet PCM
if clientSpeech: queue speech.output.segment (including language and speakingRate), await each utterance `onend` before the next segment, ACK playback.* with consumedSamples=0, and call speechSynthesis.cancel only on explicit Stop/Steer/barge-in/playback.stop/disconnect
```

If preflight fails (permission denied, missing AudioWorklet, suspended context that cannot resume), do not send `session.mode.set`. If the mode request fails, is cancelled, the connection drops, or `PendingVoiceTimeoutMs` elapses, release prepared resources, clear the user-initiated voice latch, and return to the text composer. After reconnect, `pendingMode` is null; the user must press Voice again so a new gesture can preflight. A cancelled in-flight Voice click must not look user-initiated on the next attach, or the client skips the passive durable-voice → text downgrade.

## Audio services

[Realtime Voice](06-realtime-voice.md) specifies DSP, queues, formats and tracking. The UI presents a continuous call over the composed text-first pipeline, not voice notes or native speech-to-speech reasoning. Do not claim Listening until Mode is voice and either capture is sending (`serverAudio`) or the client recognizer is started (`clientTranscript`). If the device rate is 44.1/48 kHz, resample continuously with preserved filter state; never assume 24 kHz device support.

The output worklet validates its active response epoch and stops at the next render quantum on flush, with a short fade where practical. It reports consumed samples independently of UI rendering. The connection service emits playback acknowledgements every 100 ms. Text and voice both emit `response.received` every 100 ms and at final render for the rendered **display** prefix and delivered blocks; de-duplicate those receipts on the pair (display offset, delivered block-ID set), not the text offset alone. Those display receipts must not be copied onto heard. These receipts are advisory delivery evidence, validated on the server. Queue underflow outputs silence without advancing consumed samples. Queue overflow triggers a recoverable AudioBackpressure error and stops that response.

Local VAD ducking is an optional, independently disableable UX optimization; restore gain after controller Continue/Ignore or timeout. Only authoritative supersession/stop/end/disconnect tombstones a response. Never mute microphone automatically to solve speaker echo.
